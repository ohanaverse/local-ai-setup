## Commands
Flags, exit codes and behavior live in the guide named on each line.
- `./benchmarks/qwen3.8-benchmark [max_tokens]` — single-pass benchmark (3 local backends — ollama/omlx/mtplx — + OpenRouter); `./benchmarks/qwen3.8-benchmark-multi N [max_tokens] [cooldown]` for stable medians
- `./benchmarks/ornith-1.5-benchmark [max_tokens]` — 3 Ornith-1.5-35B local variants (ollama, omlx 4-bit, omlx 6-bit; no OpenRouter); `./benchmarks/ornith-1.5-benchmark-multi N` multi-pass
- `uv run --directory llmbench llmbench agent run --suite <path>` — agentic coding benchmark (`docs/guides/09-agent-benchmarks.md`). `--directory` makes `llmbench/` the working directory, so a relative `<path>` (also in `eval run`, `--root`, `--results-dir`) resolves from there: `../benchmarks/suites/smoke.toml`
- `uv run --directory llmbench llmbench eval run --suite <path>` — cross-category capability benchmark (`docs/guides/11-capability-eval-benchmark.md`)
- `uv run --directory llmbench llmbench probe thinking` — same prompts to several already-running OpenAI-compatible servers, compares reasoning length/answer shape; manages no provider, reads no registry, writes only `--out` (`llmbench/CLAUDE.md`)
- `uv run --directory llmbench llmbench provider isolate <ollama|omlx|omlx-6bit|mtplx>` — stop others, start+warmup one (`docs/guides/05-benchmarks.md`; llama.cpp retired 2026-09-07, see `docs/reference/provider-artifacts.md`)
- `... provider isolate mlx_lm_server <target> --draft <draft>` — target+draft speculative decoding on port 8001; no default pairing, always pass both (or `LLM_ISOLATE_MLXLM_MODEL`/`LLM_ISOLATE_MLXLM_DRAFT_MODEL`)
- `... provider restore [--unload]` — after a benchmark: start ollama, omlx and LiteLLM when not answering, stop mtplx and mlx_lm_server; `--unload` first unloads every ollama/omlx model (benchmarks always restore that way; plain `restore` leaves models agent sessions use alone)
- `... provider stop <provider>` — stop one provider (mtplx is ~28GB resident); `wt smoke --json` (or non-TTY stdin) skips its exit stop prompt, leaving the server running
- `uv run --directory modeltiers modeltiers run [--dry-run] [--offline] [--inventory FILE]` — advisory capability tier per model from `wt model list --json` + public sources, writes `~/.config/local-ai/tiers.toml`. Exit 0 written, 1 not written, 2 written with a stale-snapshot source, 3 sentinel moved (re-calibrate `contracts.toml`). Nothing routes on a tier. `docs/guides/12-model-tiers.md`
- `modeltiers show [--candidates] [--sort COLUMN] [--wide] [--html FILE]` / `explain <provider_id/model_name | canonical key>` / `ladder <signal> [--low SCORE] [--high SCORE]` — read-only views (same `uv run --directory modeltiers` prefix); `show`/`explain` read `tiers.toml` only, `ladder` reads snapshots only (guide 12, step 5)
- `wt cloud-sync [--only openrouter,ollama] [--dry-run] [--yes --approve-removals DIGEST[,DIGEST]] [--force] [--html FILE]` — refresh OpenRouter prices and mirror ollama.com/pricing into `registry.toml`, ollama and LiteLLM routes. Start with `--dry-run`; exit codes 2–5 say which flow changed nothing and why; removals (ollama entries off the pricing page, OpenRouter models gone from its list) need approval, and a model added with `wt model add` is `source = "manual"` and kept until its source lists it (`wt model edit <id> --source manual` for older entries); see the `cloud-sync` skill and `wt/docs/wt-cloud-sync.md`
- `bin/mlx-quantize <convert|dynamic-quant|dwq> --model <repo-or-path> [--mlx-path <out-dir>]` — omlx-bundled mlx_lm quantization (`docs/guides/10-mlx-lm-quantization.md`)
- `make lint-shell` (`bash -n` + `shellcheck --severity=error` over the Makefile's `SHELL_SCRIPTS`), `make lint` (`lint-shell` + `check-links`), `make test-all` (mirrors CI: lint + llmbench + modeltiers + wt checks/tests)
- `make install` — all components (wt binary + shims, llmbench and modeltiers venvs); needs Go 1.26.7 on PATH (`mise use -g go@1.26.7`, matches wt-ci)
- `bin/update-tools [--only a,b] [--dry-run] [--check] [--yes]` — update every tool the wt stack runs (`bin/update/<tool>`: wt, litellm, ollama, omlx, mlx-lm-server, mtplx, postgresql, redis). Start with `--check` or `--dry-run` (omlx's `--check` runs `brew update` first). Each script prints `[update:<tool>] <status> — <detail>`; exit 0 ok, 1 failed (the only code that fails a run), 3 needs a manual step. Brew services restart only when something upgraded (`--restart` forces). `docs/guides/08-maintenance-and-troubleshooting.md` §4
- `bin/check-links` (or `make check-links`) — validates repo-relative links in every git-tracked `*.md` (excludes `docs/superpowers/`, `.venv`); stdlib-only Python

## Architecture
- `benchmarks/` — bash benchmark scripts, docs, and `results/` (per-run markdown)
- `bin/` — monorepo-wide utilities owned by no package: `check-links`, `mlx-quantize` (+ `lib/mlx-lm-resolve.sh`), `check-config-dirs-untouched` (CI step after llmbench/modeltiers/wt tests; fails if a test created `agent-wt`, `local-ai` or `litellm` under the real config home), `update-tools` + `update/<tool>` (share `lib/update-common.sh`'s trailer/exit-code contract). Provider isolation was ported from bash to Python (issue #79) and lives in `llmbench/src/llmbench/providers/lifecycle/` (`orchestrate.py` + `backends/`), exposed as `llmbench provider isolate/stop/stop-all/restore/list`; benchmarks call it in-process, the `benchmarks/` scripts via the CLI.
- `litellm-session-logs/` — standalone pipeline (psql + sh + stdlib Python, own CLAUDE.md) that rebuilds chat transcripts for one session, from LiteLLM's Postgres `LiteLLM_SpendLogs` or from Claude Code's local record under `~/.claude/projects/` (`build_cc_transcript.py`, which adds the harness context and subagent threads the proxy DB cannot see); run manually, not wired into wt
- `llmbench/` — Python/uv benchmarks plus provider isolation (`src/llmbench`, own `CLAUDE.md` and `Makefile`): throughput (`llmbench run`), agentic coding (`llmbench agent`), capability (`llmbench eval`), and `llmbench provider ...`. Reads `registry.toml` read-only; keeps latest-run pointers in `~/.config/local-ai/benchmarks/latest.toml`.
- `modeltiers/` — advisory tiers for the models wt lists (Python/uv; own `CLAUDE.md` and `Makefile`; one runtime dependency, `tomli-w`). Reads inventory only through `wt model list --json`; never writes `registry.toml`, `config.yaml` or wt state. Its one own write is `~/.config/local-ai/tiers.toml` (atomic; format `docs/contracts/tiers.sample.toml`); source downloads are snapshots under `~/.cache/local-ai/modeltiers/` with fallback to the newest good one. Identity answers live in `modeltiers/src/modeltiers/data/aliases.toml` (each with evidence; a row with none stays listed) and the tier rule in `data/contracts.toml` (calibrated 2026-10-12; two sentinels re-pinned 2026-10-21) — editing them is the only way to change what a run decides. A reader treats a model absent from the file, or an unparseable file, as `unrated`; wt's picker is the one outside reader and only displays it. Design: `docs/superpowers/specs/2026-10-12-model-tiers-design.md`
- `wt/` — worktree agent launcher (Go module; own `CLAUDE.md` and `Makefile`). Writes `registry.toml` only through `config.UpdateRegistry` (`wt model init|add|edit|rm`, the `wt config` Models tab, `wt cloud-sync`); on-disk and running state come from live probes, never a stored flag, and the stale-pricing notice dates from `registry.toml`'s `pricing_updated_at`. Owns `~/.config/agent-wt/config.toml` (incl. `[litellm]` routing state), rotation/usage state (`rotation.state`, `usage.jsonl`, `last-picked.state`), and **all LiteLLM management** (`wt litellm sync|list|providers|status|on|off|set|restart`; `wt start`/`stop`/`smoke` keep local routes current). Reads, never writes, the hand-written `~/.config/agent-wt/slot-profiles.toml` (`wt/docs/wt-agents/slot-profiles.md`) and modeltiers' `tiers.toml` (picker TIER column, `internal/tiers`).
- `Makefile` — shell lint (root + wt), `check-links`, `test-all`
- `docs/` — guides/ (playbooks), reference/, contracts/ (cross-language fixtures read by tests: wt's Go contract tests, llmbench's `registry.sample.toml`/`registry.written.sample.toml`, modeltiers' `tiers.sample.toml` (parsed by wt's `internal/tiers/contract_test.go`) and `model-list.sample.json` (the only thing modeltiers reads from wt, held by `cmd/wt/model_list_contract_test.go`) — a key added to or renamed in `modelListJSON`/`modelListRow` or a tiers format change must reach the fixture in the same change), archive/ (dated docs), superpowers/ (plans+specs)
- `.github/workflows/` — shell-ci (root lint), wt-ci (Go + wt lint), llmbench-ci, modeltiers-ci (Python)
- LiteLLM config `~/.config/litellm/config.yaml` — written only by wt (`WT_LITELLM_CONFIG` overrides the path, `WT_LITELLM_RESTART_CMD` the restart; `MODELMAN_LITELLM_*` are legacy aliases). The path follows none of `WT_REGISTRY`, `MODELMAN_REGISTRY` and `XDG_CONFIG_HOME`, so wt refuses route writes and dry runs (`litellm.ErrRegistryRedirected`) when the registry is redirected and nothing names config.yaml — **any ad-hoc `wt` run against a scratch registry must set `WT_LITELLM_CONFIG` too**
- Tiers file `~/.config/local-ai/tiers.toml` — written only by `modeltiers run` (`MODELTIERS_OUT` overrides), read by `modeltiers show|explain` and wt's picker by the same path rule (`MODELTIERS_OUT`, else `$XDG_CONFIG_HOME/local-ai/tiers.toml`, else `~/.config/...`). The path does not follow `WT_REGISTRY`, so `modeltiers run` refuses (exit 1) an inventory from a redirected registry while `MODELTIERS_OUT` is unset (`--dry-run` warns and goes on) — **any ad-hoc `modeltiers run` against a scratch registry, or one that must not touch the real file or `~/.cache/local-ai/modeltiers/`, must set `MODELTIERS_OUT` and `MODELTIERS_CACHE`**
- LaunchAgent plist: `~/Library/LaunchAgents/local.litellm.proxy.plist` (LiteLLM), referenced by the isolation helpers. (llama.cpp's plist was retired 2026-09-07; see `docs/reference/provider-artifacts.md`.)
- `mlx_lm_server` provider — one target+draft pairing served by `mlx_lm.server --draft-model` as a plain backgrounded subprocess (pidfile `/tmp/local-ai-setup-mlx-lm-server.pid`, via `providers/lifecycle/pidproc.py` + `backends/mlx_lm_server.py`), never a LaunchAgent (one model per process; sweeping pairings means restarting it). `local_path` artifacts (from `bin/mlx-quantize` or the `omlx`/`mlx_lm_server` local-path fields) are user-produced and wt never deletes them (`wt model rm` prints the path); cleanup of a failed experiment is a manual `rm -rf`. See `docs/reference/provider-artifacts.md`, `docs/guides/10-mlx-lm-quantization.md`.

## Key Gotchas
- **Benchmark isolation is mandatory**: `llmbench` and the legacy scripts enforce one local model loaded at a time — local MLX/GGUF models share Apple Silicon GPU/RAM and distort each other otherwise. Normal `wt start` usage allows several local models at once (omlx pools several; mtplx and mlx_lm_server serve one per process; see `wt/CLAUDE.md` "Lifecycle") — advisory only.
- **Stop mechanisms per backend**: Ollama `ollama stop <model>` (daemon stays up); oMLX `wt stop <model>` unloads one model, `omlx stop` / `wt stop omlx` / `wt stop --all` halts the service; MTPLX `mtplx stop --port 8003 --grace-seconds 10` (plain pidfile-tracked subprocess, never a LaunchAgent).
- **oMLX serves both 4-bit and 6-bit variants** — warmup must name the exact variant (`omlx` vs `omlx-6bit`).
- **Shebang split**: benchmark scripts use `#!/opt/homebrew/bin/bash`; `bin/` helpers use `#!/bin/bash`. Exception: `bin/check-links` uses `#!/usr/bin/env python3`.
- **Results go to `/tmp/<benchmark>-<timestamp>.md`**; archive into `benchmarks/results/`.
- **OpenRouter rows are N/A without an API key**: `qwen3.8-benchmark` (the only script with them) reads `OPENROUTER_API_KEY` from `~/Library/LaunchAgents/local.litellm.proxy.plist`.
- **Guides never embed live model state**: no counts, routing snapshots, or "today that's X, Y" inventories in `docs/guides/`. Show the command that reveals the state (`wt litellm list`, `wt model list`); label captured output as an illustrative or dated example.
- **Routing is derived, not stored**: no file marks a model as routed. `wt` builds `config.yaml`'s `model_list` from `registry.toml` plus live probes — a cloud model always, a local model while it runs (an ollama model while pulled). Whether a model is routed is `wt litellm list`.

## Quick test commands

For focused test runs without live provider interference:
```bash
# llmbench (Python) — conftest.py runs the suite under a scratch HOME with provider binaries stubbed
cd llmbench && uv run pytest tests/providers/lifecycle/test_orchestrate.py -q

# wt (Go) — no special isolation needed
cd wt && go test ./cmd/wt -run TestStats
```
See `llmbench/CLAUDE.md` and `wt/CLAUDE.md` for package-specific test patterns.
