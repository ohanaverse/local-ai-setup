# Benchmark Tools That Run Natively on Apple Silicon for Coding-Agent & LLM Evaluation (Local + Cloud Models)

## TL;DR
- **Best fit: EvalPlus (HumanEval+/MBPP+), lm-evaluation-harness, and Inspect AI (+ its `inspect_evals` library) are the three tools that run natively on Apple Silicon, ship both prompts and graders, and can point at Ollama, MLX servers, or a LiteLLM proxy over OpenAI-compatible endpoints — none require Docker for the harness itself.** For pure code-generation scoring, EvalPlus is the fastest path; for a unified local+cloud harness with the widest built-in benchmark catalog (coding, agentic and general), Inspect AI (or its friendlier wrapper `openbench`) is strongest.
- **The Docker requirement is about code-execution sandboxing, not the harness.** Terminal-Bench/Harbor and SWE-bench require Docker/Linux containers for *every task*; by contrast EvalPlus, lm-eval-harness, DeepEval, LiveBench and EvalScope run the harness natively and only *optionally* sandbox the code-execution step (which can run in-process on macOS, with the caveat that you are then executing model-generated code on your host).
- **Avoid for native-macOS use: SWE-bench (Docker-mandatory, ARM64 only experimental), BigCodeBench (Docker strongly recommended), and METR RE-Bench/Vivaria (Docker-mandatory and being wound down in favor of Inspect AI).** All of your local runners (Ollama, oMLX, mlx-lm/mlx-omni-server) expose OpenAI-compatible endpoints, so any harness that accepts a `base_url` will talk to them directly or through your LiteLLM proxy.

## Key Findings

**1. The distinction that matters for you.** "Runs on Apple Silicon" has two separate layers: (a) does the *harness/runner process* run natively on macOS ARM64, and (b) does the *code-execution/scoring step* need a Linux container. Terminal-Bench/Harbor and SWE-bench fail layer (a) — they spin up a Docker (or Daytona/Modal/E2B) sandbox for every single task. Most Python code-eval harnesses (EvalPlus, lm-eval-harness, DeepEval, LiveBench, EvalScope, Inspect AI) pass layer (a) trivially because they are pip-installable pure-Python packages, and only touch layer (b) when they execute the model's generated code. On those tools, sandboxing is optional or configurable, and code runs in a subprocess on your Mac if you accept the risk.

**2. Your local model access is already solved by OpenAI-compatibility.** Ollama serves an OpenAI-compatible API at `http://localhost:11434/v1`. The MLX serving tools you named all do the same: **mlx-lm** ships `python -m mlx_lm server` (OpenAI-compatible, no Docker); **mlx-omni-server** (current release 0.5.3) is a drop-in replacement that "works with existing OpenAI and Anthropic SDKs," exposing OpenAI endpoints at `http://localhost:10240/v1` and Anthropic at `http://localhost:10240/anthropic`; **mlx-openai-server** (cubist38) and **oMLX** serve `/v1` on Apple Silicon. Your "mtplx" is almost certainly **mlx-lm** (the core Apple MLX LM package with a built-in server) or **mlx-omni-server**; either works. A LiteLLM proxy in front of all of them gives you one OpenAI-compatible endpoint that unifies local + cloud — per the BerriAI/litellm project, LiteLLM is "a unified interface to call 100+ LLM providers — OpenAI, Anthropic, Gemini, Bedrock, Azure, and more — using the OpenAI format" (current v1.83.8, MIT license) — and every tool below can point at that single `base_url`.

**3. EvalPlus is the cleanest "complete suite" for coding capability.** Per the EvalPlus README, it bundles "HumanEval+: 80x more tests than the original HumanEval!" (expanding from 164 test cases to over 13,000) and "MBPP+: 35x more tests than the original MBPP!" (to over 14,000 test cases) *with* the graders. It installs via `pip install evalplus` and evaluates any OpenAI-compatible endpoint with `--backend openai --base-url http://localhost:8080/v1`. Real users have run it on Apple Silicon and via LM Studio/llama.cpp. Docker is only *recommended* for the sandboxed code-execution step; `evalplus.evaluate` runs locally without it (the docs literally offer "…Or if you want to try it locally regardless of the risks").

**4. Inspect AI is the most capable unified option — with one Docker caveat.** Inspect AI, "developed by the UK AI Security Institute and Meridian Labs," is pip-installable, actively maintained, and per its docs "includes a collection of over 200 pre-built evaluations ready to run on any model" via `inspect_evals` (HumanEval, MBPP, APPS, BigCodeBench, SWE-bench, HumanEvalPack, etc.). It has native `ollama/` and OpenAI-compatible providers, unifying local + cloud. Critical nuance from primary sources: Inspect's core sandboxing has a built-in `docker` sandbox *and* a built-in `local` sandbox ("Local file system (no sandbox)"), but the **built-in `inspect_evals/humaneval` task defaults to `sandbox='docker'`** (documented default). The `sandbox` is an overridable task parameter, so code execution can be redirected to `local` on macOS, but out-of-the-box HumanEval expects a Docker daemon, and its SWE-bench and agentic/tool-use tasks (bash/python/web_browser tools) genuinely need Docker.

**5. `openbench` (groq/openbench) is a fast on-ramp to Inspect.** Built on inspect-ai, its README advertises "95+ Benchmarks: MMLU, GPQA, HumanEval, SimpleQA, competition math (AIME, HMMT), SciCode, GraphWalks, and more" and "supports 30+ model providers through Inspect AI," including local models via Ollama, behind a simple `bench eval` CLI. It is provider-agnostic and runs natively. It's still an alpha release but very convenient for a laptop.

**6. lm-evaluation-harness is the general-purpose standard.** EleutherAI's harness runs natively and per its README ships "over 60 standard academic benchmarks for LLMs, with hundreds of subtasks and variants implemented" (MMLU, GSM8K, HellaSwag, IFEval, HumanEval, etc.). It talks to any OpenAI-compatible server via `--model local-completions`/`local-chat-completions` with `base_url=`. Caveat: chat-completions endpoints (Ollama/most MLX servers) don't expose prompt logprobs, so multiple-choice/loglikelihood tasks won't work over those APIs — stick to generative tasks (GSM8K, IFEval, HumanEval).

## Details by Tool

**SWE-bench / SWE-bench Lite / Verified** — *Coding-agent (repo-level).* Harness is **Docker-mandatory**: it builds a stack of base/environment/instance images and runs each task in its own container. Apple Silicon support is officially "experimental"; default prebuilt images are x86_64 and pulling them on M-series causes platform-mismatch/manifest errors, so you must build locally (`--namespace ''`) or use community ARM64 images (greynewell's `swe-bench-fast` reports a 6.3× speedup with native ARM64 containers). Needs ~120 GB disk, 16 GB RAM. **Ships prompts + graders.** Model access is via a predictions file / mini-SWE-agent. **Verdict: does not meet your "no Docker for the harness" bar.**

**EvalPlus (HumanEval+, MBPP+)** — *Coding capability.* Native macOS via pip. **Ships prompts + augmented test graders.** Backends: `hf`, `vllm`, and `openai` (with `--base-url` → Ollama/MLX/LiteLLM). Code execution: Docker recommended but optional; runs in-process locally otherwise. Actively maintained (MBPP+ v0.2.0; leaderboard current). **Verdict: top pick for quick, rigorous code-gen scoring.**

**HumanEval / MBPP (originals)** — datasets, not full harnesses; use EvalPlus, lm-eval-harness, DeepEval, EvalScope, or bigcode-eval-harness to run them with graders included.

**Aider polyglot benchmark** — *Coding-agent (edit format across 6 languages, 225 Exercism exercises).* **Ships prompts + unit-test graders** (clone `Aider-AI/polyglot-benchmark`). The official instructions run the benchmark inside Docker "to ensure the safety of executing potentially harmful code," but it **can be invoked natively** — documented third-party runs execute `benchmark/benchmark.py` natively against a local OpenAI-compatible endpoint (e.g., a MacBook Pro M-series serving Qwen locally). Connects to local models via `OPENAI_API_BASE`/Ollama/LiteLLM. Actively maintained. **Verdict: excellent coding-agent suite; native run is possible but you own the code-execution risk.**

**lm-evaluation-harness (EleutherAI)** — *General LLM (incl. some coding).* Native macOS. **Ships 60+ task suites + scorers.** Local/cloud via `local-completions`/`local-chat-completions`/`openai-chat-completions` with `base_url`. Caveat: no logprobs over chat APIs → generative tasks only for Ollama/MLX. Actively maintained; the Open LLM Leaderboard standard. **Verdict: best general-capability harness.**

**Inspect AI + inspect_evals (UK AISI/Meridian Labs)** — *Both general and coding/agentic.* Native macOS (pip; latest 0.3.260, Aug 2026, MIT). Native `ollama/` provider and OpenAI-compatible/`base_url` support; unifies local + cloud. **Ships 200+ pre-built evals with scorers.** Caveat: `inspect_evals/humaneval` defaults to `sandbox='docker'` (overridable to `local`); SWE-bench and tool-use/agent tasks require Docker. Model-graded scorers, rich viewer. **Verdict: most powerful unified option; expect Docker for agentic tasks.**

**openbench (groq/openbench)** — *General + coding.* Built on inspect-ai; native; `bench eval` CLI; 95+ benchmarks incl. HumanEval/SciCode; Ollama + 30+ providers. Alpha. **Verdict: easiest Inspect-based on-ramp.**

**EvalScope (ModelScope)** — *General + coding + agentic.* Native pip; **built-in benchmarks incl. HumanEval, MMLU, GSM8K, plus SWE-bench-agentic in a Docker AgentLoop.** OpenAI-compatible/Ollama/vLLM. HumanEval executes code locally by default with an optional sandbox flag. Actively maintained (2026 updates, incl. a GAIA agent benchmark). **Verdict: strong, flexible, native; sandbox is opt-in.**

**promptfoo** — *BYO-tasks eval + red-teaming.* Native (Node). First-class Ollama, LiteLLM (400+ models), and OpenAI-compatible providers; 60+ providers. **Caveat: not a built-in coding benchmark suite** — you supply prompts/test cases (though it has assertion types and can execute code). **Verdict: great for custom evals and security testing, not a turn-key coding benchmark.**

**DeepEval** — *General + some coding, plus RAG/agent metrics.* Native pip. **Ships built-in benchmark classes incl. HumanEval, MMLU, GSM8K, BIG-Bench-Hard, TruthfulQA** with fixed scorers. Local/cloud via `LiteLLMModel` (Ollama, OpenAI, Anthropic, Bedrock, etc.) or custom model classes. HumanEval executes generated code in the local environment. Actively maintained. **Verdict: good if you also want unit-test-style/pytest workflows and RAG metrics.**

**LiveCodeBench / LiveBench** — *Coding (contamination-free) / general.* Native Python; `run_livebench.py` handles generation + scoring; point at OpenAI-compatible servers with `--api-base`. **Ships prompts + scorers.** Caveats: local (non-API) inference is "unmaintained" — serve via an OpenAI-compatible endpoint instead; the **agentic coding questions require Docker**. **Verdict: usable natively for standard code tasks via your local endpoints; skip the agentic subset unless you have Docker.**

**BigCodeBench / bigcode-evaluation-harness** — *Coding capability.* Harness is Python, but Docker is **strongly recommended/effectively required** for safe execution of its diverse-dependency tasks; prebuilt generate/execute images are provided; bigcode-eval-harness leans on `accelerate`/GPU and Docker for MultiPL-E. **Ships prompts + graders.** **Verdict: workable but Docker-centric for execution — weaker native fit than EvalPlus.**

**OpenAI Evals (openai/evals)** — *General; registry of benchmarks.* Native pip; **ships a registry of ready-made evals + templates** (JSON data + YAML, many need no code). Designed around `OPENAI_API_KEY`, but you can configure custom Chat-Completions-compatible endpoints (point `base_url` at LiteLLM/Ollama/MLX). ~17.6k stars, still maintained but less actively coding-agent-focused. **Verdict: fine for prompt/model-graded evals; not primarily a coding-agent suite.**

**METR RE-Bench / Task Standard / Vivaria** — *Coding/ML-research agents.* **Docker-mandatory** (Vivaria expects a Docker socket; on macOS some `viv ssh` flows don't work out of the box). METR is **ramping down Vivaria development and pointing users to Inspect AI.** **Verdict: not a native-macOS fit; use Inspect instead.**

**CanItEdit / RepoBench / CRUXEval** — research **datasets/benchmarks** (code editing, repo-level completion, code reasoning/execution). They provide tasks and reference evaluation scripts (Python), generally runnable natively for generation+scoring against OpenAI-compatible endpoints, but they are thinner, less-maintained harnesses than the mainstream tools above and CRUXEval's execution step benefits from sandboxing. **Verdict: niche; reach for them only if you specifically need code-editing (CanItEdit), repo-level (RepoBench), or input/output-prediction (CRUXEval) signals.**

## Recommendations

**Stage 1 — Get a signal today (no Docker).** Stand up your models behind one OpenAI-compatible surface (LiteLLM proxy in front of Ollama + mlx-lm/mlx-omni-server), then run **EvalPlus** for code generation (`evalplus.evaluate --dataset humaneval --backend openai --base-url http://localhost:4000/v1 --model <name>`) and **lm-evaluation-harness** for general capability (generative tasks like GSM8K/IFEval/HumanEval via `local-chat-completions`). Both install with pip and run entirely on your Mac. Accept in-process code execution only for trusted, local benchmark code, or gate it (see Stage 3). *Benchmark to advance:* if you need multi-language coding-agent signal beyond single-function tasks, go to Stage 2.

**Stage 2 — Coding-agent depth.** Run the **Aider polyglot benchmark** natively (clone `polyglot-benchmark`, invoke `benchmark/benchmark.py` against your LiteLLM/Ollama endpoint) for a realistic 6-language edit-and-test signal, and/or adopt **Inspect AI via `openbench`** for a unified, reproducible harness with logging/viewer across both local and cloud models. *Threshold that changes the plan:* if you require true repo-level issue resolution (SWE-bench) or agentic tool-use/computer-use tasks, you will need Docker — accept it selectively for those suites only.

**Stage 3 — Safety and rigor.** For any suite that executes model-generated code, isolate it. Cheapest native option: run the execution step in a throwaway macOS user/VM or use Inspect/EvalScope's optional sandbox. If you decide repo-level or agentic evals are worth it, install Docker Desktop (or Colima) on your M-series Mac and run **only those tasks** in containers (allocate ≥120 GB disk for SWE-bench; expect longer local ARM64 image builds). Keep the day-to-day loop (EvalPlus + lm-eval-harness + Inspect non-agentic evals) Docker-free.

**Model routing:** Put **LiteLLM proxy** at the center. It exposes one OpenAI-compatible endpoint, load-balances/fails-over across your Mac fleet, and lets every tool above target a single `base_url` while you swap local vs. Anthropic/OpenAI models by name. This is the lowest-friction way to satisfy the "both local and cloud" requirement across all harnesses.

## Caveats
- **Executing model-generated code on your host is the real risk**, not architecture. When you skip Docker on EvalPlus/lm-eval-harness/DeepEval/LiveBench, you are running untrusted code in-process on macOS. Use trusted benchmark code, a dedicated user account, or a lightweight VM if that matters.
- **Chat-only endpoints lack logprobs.** Ollama and most MLX servers expose chat-completions without prompt logprobs, so multiple-choice/loglikelihood tasks in lm-eval-harness won't run over them — use generative tasks or serve via vLLM if you need logprob-based scoring (vLLM's native macOS support is limited).
- **Inspect AI's HumanEval defaults to a Docker sandbox.** This is an overridable parameter, but "native, no-Docker" is not the out-of-the-box default for its code-executing evals; plan to pass `sandbox='local'` or use EvalScope/EvalPlus if you want zero Docker.
- **SWE-bench ARM64 remains experimental**; official native ARM64 support was deferred to the newer `swe-bench-dockerfiles` repo, so expect friction (community `swe-bench-fast` mitigates it).
- **MLX tooling identification:** "omlx" = **oMLX** (menu-bar Apple Silicon inference app, OpenAI-compatible on `:8000/v1`); "mtplx" is most likely **mlx-lm** (`mlx_lm.server`) or **mlx-omni-server** (0.5.3) — both are actively maintained OpenAI-compatible MLX servers. Any of them plugs into the harnesses above identically.
- **Some vendor/marketing pages** (leaderboards, model-runner blogs) were used only for corroboration; benchmark scores cited in passing (e.g., specific Aider Polyglot percentages) come from third-party runs and should be treated as illustrative, not authoritative.
- **Version-numbering note:** Inspect AI's release cadence is rapid — a Sept 2025 paper cited v0.3.130 while the Aug 2026 line is ~0.3.260 — so pin a version for reproducibility.
