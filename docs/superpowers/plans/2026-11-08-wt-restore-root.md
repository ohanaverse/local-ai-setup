# wt restore-root Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `wt restore-root` moves the repository root's non-default branch, with its commits, upstream and uncommitted work, into a new linked worktree and leaves the root clean on the default branch, fast-forwarded to `origin/<default>` only when that is a strict fast-forward.

**Architecture:** `internal/rescue` gains a root mode (primary source allowed, detached destination, `ExecuteInto` an externally created worktree, accessors for the verified fingerprint and carried untracked paths). `internal/cleanup` exports one read-only check ("the root's index and working tree equal this record"), `internal/removal` gains the only destructive function, `ReleaseRoot`, which refuses unless the verified copy, the record and an unchanged fingerprint all hold, and the new `internal/rootmove` composes preflight, execute, release, switch and fast-forward and owns the recovery table. `cmd/wt/restore_root.go` is the command; `restore-root-result.*` is its contract.

**Tech Stack:** Go (module `wt/`), the rescue/cleanup/removal fixtures with real scratch repos and a bare `origin`, JSON-schema contract tests.

**Spec:** `docs/superpowers/specs/2026-11-08-wt-restore-root-design.md` (issue #522; the five Decisions the user confirmed are binding). Builds on `wt rescue` (#529, #542, #547, #550). Paths are relative to `wt/` unless they start with `wt/` or `docs/`.

**PR boundaries:** two PRs, each independently shippable and testable.
- **PR A (Tasks 1-5), engine seams:** detached worktree creator, rescue root mode, cleanup root-covered check, `removal.ReleaseRoot` and its guards. No command, no behavior change for `wt rescue`, `cleanup`, `remove` (including the `primary` refusal text, which PR B rewords). PR A also carries its own guard docs (Task 5 Step 5).
- **PR B (Tasks 6-12), the command:** `internal/rootmove` (Tasks 6, 7a, 7b), JSON contract, `wt restore-root`, hint line, docs, acceptance. Needs PR A merged.

## Global Constraints

- Fail closed. Any git or IO error, unexpected state or limit hit refuses before anything exists, or stops at the step it occurs in and prints that step's row of the recovery table. No rollback; every state keeps the work reachable.
- Limits are rescue's: 20000 files, 512 MiB (`rescue.MaxUntrackedFiles`/`MaxUntrackedBytes`). The root is never touched before step 4 of Execute (release).
- Deletion words: scanned by quoted literal and flag shape only (comments, prose, the `internal/cleanup` import and `cleanup.` calls are never matches; "root is clean" in a message is fine). `internal/rescue` and `internal/cleanup` keep their existing scans unchanged (`rescueBanned`/`riskyRescueSource` in `cmd/wt/rescue_test.go`, `TestCleanupCmdContainsNoDeletion`, rescue's exactly-one create-only `"update-ref"`). `internal/rootmove` and `cmd/wt/restore_root*.go` are scanned with `rootmoveBanned = append(rescueBanned, `"--hard"`, `"reset"`, `"clean"`)` (so also `"push"`, `--delete`, `worktree remove`, `os.Remove(`, `os.RemoveAll`, `os.Rename(`, and no `update-ref` at all); there is no bare `clean` and no `"switch"` ban (rootmove runs `git switch` only in the destination; `"clean"` as an argv element also catches `clean -x`). Reset, file removal and the root switch live only in `internal/removal`'s `ReleaseRoot`.
- Hooks are off (`core.hooksPath=/dev/null`) for the detached `worktree add`, the root switch, the destination switch and the fast-forward; a `post-checkout` hook gets rescue's existing warning.
- Exit codes follow `wt rescue`: 0 moved (or `--dry-run` would move, or `already_default`), 1 could not start, 2 refused or failed, 3 approval missing (no `--yes` and no terminal, or declined).
- Refusal and failure codes: rescue's strings unchanged, plus `detached_root`, `already_default`, `default_in_worktree`, `root_held`, `no_commit`, `release_refused` (spec) and `ignored_collision` (an ignored file the default branch tracks would be overwritten; ruling 12),  `no_default_branch`, `record_not_written` (rulings, Self-review). Statuses `moved|would_move|refused|failed`.
- A real run fetches once through `cleanup.Gather` with `Fetch=true`, which fetches every remote read-only exactly as `wt cleanup` does (ruling 13 amends the spec's "origin");  `--dry-run` and `--no-fetch` never fetch; later re-checks set `in.Fetch=false`. `--dry-run` adds `dryRunFetchNote` to the warnings.
- The record is required: no record, no release. With nothing uncommitted there is no copy and no record; release then needs only an unchanged fingerprint and a clean status.
- Ignored files are never overwritten or removed: Preflight refuses `ignored_collision` when an ignored file sits at a path the default branch tracks, the root switch uses `--no-overwrite-ignore`, and the fast-forward is skipped (warning, still `moved`) when it would touch an ignored path.
- The live-session claim is checked in Preflight and again in Execute immediately before the release (the window after that is the one the report states).
- `ReleaseRoot` runs every git command with `Dir` = the root, never the caller's directory.
- Fast-forward only by `git merge --ff-only` and only when `origin/<default>` is a strict descendant of local `<default>`; never a merge, never `--force`; its failure never undoes the move.
- Contracts are additive: `restore-root-result.*` is new; `rescue-result.*`, `remove-result.*`, `cleanup-list.*` are unchanged and `rescue.Codes` does not grow.
- Guard tables stay exact: `internal/cleanup/losses_guard_test.go` (`rescue/preflight.go#Engine.Preflight` stays `{raw: 8}`; no new function reads `.Losses`), rescue's exactly-one `"update-ref"`, `TestEveryPackageThatRunsGitIsolatesIt` (new package `internal/rootmove` needs a `TestMain` calling `gitenv.IsolateForTest()`).
- Every `Test*` has a top-level comment saying what and why. Every implementer dispatch also runs `go test ./cmd/wt -run 'Rescue|Cleanup|Remove|RestoreRoot' -count=1` and the package's own tests (guard tests read sources across packages).
- Ad-hoc `wt` runs redirect `WT_REGISTRY`, `WT_LITELLM_CONFIG` and `XDG_CONFIG_HOME`; tests use `rescueApp`-style harnesses that set them. CI also runs `GOMAXPROCS=1 go test -count=1 ./...`.
- PR bodies say `Refs #522` and never `close`/`fix`/`resolve #522` anywhere (use `gh pr create --body-file`).

## Review Focus

Failure modes no task would otherwise exercise, most likely first (each has its test in the named task):

1. The root edited after the copy was verified: between verify and the reset, and while the confirmation prompt is held. A live claim appearing after Preflight is caught by the pre-release re-check. Nothing is reset or deleted; `release_refused` or `source_changed`; both places kept (Tasks 5, 7a, 12).
2. A clean root, or one whose only unfinished work is unpushed commits: Rescue's `nothing_to_keep` must not fire, no record and no copy are made, and the unpushed commits are still reachable from the moved branch (Tasks 2, 7a).
3. Untracked-file removal in the root: a carried path that became a directory, a symlink parent or a vanished file, and an ignored file of the same name, must be refused or left alone; a carried path the reset restored from HEAD (`git rm --cached foo` plus `foo` on disk) is skipped, never removed; ignored files at default-tracked paths are refused up front; nothing outside the carried list is removed (Task 5).
4. Default-branch edge cases: `origin/HEAD` unset, a default that exists only as `origin/<d>`, the default checked out in a linked worktree, local ahead of or diverged from origin: no merge, no refusal for a failed fast-forward, nothing switched to a branch that does not exist (Tasks 6, 7a, 7b).
5. "Same branch, not a copy": the branch ref never moves, its upstream and config survive, the record's trailers and a later `wt cleanup` read the new worktree sensibly, and a record that cannot be written (a ref-path conflict) blocks the release (Tasks 3, 7a, 12).

**Files:**

**Interfaces:**

- Produces:

  - `func ReleaseRoot(g cleanup.Git, r RootRelease) (ReleaseResult, error)` — ignores `g.Dir`: it builds `rg := cleanup.Git{Dir: r.Root, Timeout: g.Timeout, Config: g.Config}` and runs every git call with `rg` (status gate, `RecordCoversDirt(rg, ...)`, the `HEAD` read, reset, read-back, switch); `Root` must be absolute, a relative or empty one is a `*ReleaseRefused` before any write; untracked-path checks resolve against `r.Root`. Gates, in this order, any miss is `*ReleaseRefused` before any write: `Unchanged != nil` and returns `""`; if `NothingUncommitted`, `git status --porcelain=v2 -z --untracked-files=all` is empty; else `Verified`, `RecordRef` has `refs/wt/rescued/` prefix and `cleanup.RecordCoversDirt(rg, Root, HEAD, RecordRef)` is true (last, nearest the reset). Then `git reset --hard HEAD`; then remove exactly `Untracked` (each: relative, inside `Root`, no `..`, no symlinked parent, `Lstat` a regular file or symlink; already-gone is skipped; a carried path the index tracks after the reset (`git ls-files --error-unmatch -- <p>` succeeds, read after the reset) was restored from HEAD by the reset (the `git rm --cached foo` plus untracked `foo` case) and is skipped, never removed; a directory, a path outside `Root` or a symlinked parent is a `ReleaseFailed` at `remove_untracked`); a clean-status read-back (`verify_clean`); `git -c core.hooksPath=/dev/null switch --no-overwrite-ignore <Default>`, so an ignored file at a path the default tracks fails the `switch` stage instead of being overwritten (the reset has run by then: the root is clean on the branch and the work is safe, which the caller's text must say). Directories left empty are left (documented).
