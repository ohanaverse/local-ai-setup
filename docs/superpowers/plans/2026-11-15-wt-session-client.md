# wt-session Client (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the launcher (`wt`, becoming `wt-session`) a client of `wt-model`: every model decision (catalog, pin, start, stop, smoke, slot profiles, spend) goes over one endpoint and one token; direct routes, `[litellm] enabled`, `refcount` and the post-exit stop picker are gone.

**Architecture:** A new dependency-light package `internal/modelclient` (HTTP client, job driver with typed-problem answers, session heartbeat) consumes the Phase 1 wire contract (`internal/modelapi`). Wire rows become the session's model value through an adapter in `internal/catalog` (`FromWire`, `ToModel`), so drivers, pickers and tests keep `config.Model` / `catalog.Row` as their currency. Server-side additions (catalog fields, requester-aware stop, job list, gateway path allowlist, candidates, spend) land first and are additive. The client path is built beside the old one, selected only by an explicit `[model-server]` endpoint+token, then made the only path.

**Tech Stack:** Go 1.26.7, stdlib `net/http`, cobra, bubbletea (existing). No new module dependencies.

**Spec:** `docs/superpowers/specs/2026-11-15-wt-model-session-split-design.md` (Phase 2 of "Migration"; "Control API", "Auto-stop", "Connection and configuration", "Further decisions"). Style authority: `wt/docs/style-guide.md`. Phase 1 plan (house style): `docs/superpowers/plans/2026-11-15-wt-model-server.md`.

## Scope

**In Phase 2.** Everything the spec assigns to the client in "Migration" step 2, plus the server changes the client forces: (a) additive `wt-model` API changes (Tasks 1-3, including the gateway inference-path allowlist the spec names as Phase 2 work); (b) the client package and the explicit endpoint+token config (4-6); (c) launch, `-M` resolution, pickers, `start`, `stop <model>`, `job`, slot profiles and `smoke` on the API (7-13); (d) the flip: no `[model-server]` means a refusal, `[litellm] enabled` retired, `wt litellm on|off` retired (14); (e) deleting direct routes, pi's direct `models.json` rewrite, `refcount`, the stop picker, the ollama check and the in-process start/route code from the session paths (15); (f) binary naming and shims (16); (g) docs, skills, guides (17).

**Boundary rulings** (the spec left these open):
- **R1 Binary naming.** `wt/cmd/wt` is renamed `wt/cmd/wt-session` (Task 16, after the code tasks, which therefore name `cmd/wt` paths). `make build` produces `bin/wt-session` and `bin/wt`, the same binary under both names (two files, each codesigned; a copy, not a symlink); `make install` installs both; the `*-wt` shims keep `exec wt`. The stderr prefix and `--version` word stay `wt` (style guide N1: "stays `wt` until a rename is decided").
- **R2 Transitional dual path.** Tasks 9-13 add the client path beside the registry path; `a.models != nil` (a configured endpoint) selects it. Task 14 flips (no endpoint: refusal) and Task 15 deletes the old path. Nothing after Task 15 is reachable on two paths.
- **R3 Host commands stay in this binary until Phase 4.** `model init|add|edit|rm|list`, `cloud-sync`, `litellm sync|list|providers|status|restart|set`, `served`, `warm`, `stop <provider>|--all` and the Models tab still load the registry (host files, via `app.hostConfig()`); they print no pointer to `wt-model` yet. The session half of `model list` is `wt model list --server` (Task 11), so modeltiers' `wt model list --json` contract is untouched.
- **R4 Host LiteLLM key.** `[litellm] url/api_key` stays in `config.toml` as host state read by `wt-model serve` and `wt litellm set` only; session code never reads it (enforced by Task 15's boundary test). `wt-model`'s own config home waits for Phase 4's `wt-model litellm set`.
- **R5 Protocols.** Each driver keeps its one fixed wire to the gateway (LiteLLM translates); `row.protocols` is informational and filters nothing.
- **R6 Eligibility.** Per-agent `supported_providers` stay in `config.toml`; `config.SushiAgents` agents implicitly support provider `sushi`; the session cannot validate provider ids against a registry and does not try.
- **R7 Routed.** The catalog row gains `routed`; a launch of a local `running` row that is not routed runs a start job (it waits for the route), anything else launches directly.
- **R8 Cancel.** Ctrl-C detaches (the job continues; the id is printed); an explicit cancel is `wt job ID --cancel` and `c` on the TUI start screen. No client code refuses cancel "past routing" (`pastCancel` is deleted).
- **R9 Stale-pricing notice** stays on the session, driven by `Catalog.Pricing` (the registry's stamps are host data).
- **R10 `protectedPaths`** (`wt worktrees|remove` refusing a worktree that holds a registered artifact) keeps a best-effort registry read: absent or unparsable registry means no protection and no error. It is the one named exception in Task 15's boundary test.
- **R11 Token on disk.** The session token may live in pi's `models.json` and agent env; the file is written mode 0600. The spec forbids host credentials on the session, not the session token.

**Deferred.** *Phase 3:* untangling `internal/tui` and the import graph (this phase removes the calls, not the imports; the session binary still links `lifecycle`, `litellm`, `localmodels`). *Phase 4:* moving the admin commands and Models tab to `wt-model`, pointers in `wt-session`, `wt-model litellm set` and its config home, `wt-model check`, the session `litellm list|status`, the `wt-cloud-sync` skill rewrite, a host-side stale-pricing notice. *Issues:* #596 (slot profiles over LiteLLM aliases: slot profiles keep today's behavior over catalog rows here), #597 (subscription mixed slots: native rows stay un-gatewayed), #598 (restart/drain: the 503 wait stays as designed).

**Preconditions.** The W2 and W4 style-guide packages (single error line; approval-missing exits 3) are merged first; this plan uses `exitcode.New(3, err, false)` for approval-missing and `exitcode.New(1, err, false)` for "could not start", exactly as `cmd/wt/remove.go` does.

## Global Constraints

- API prefix `/control/v1/`, gateway `/v1/*`, `modelapi.APIMajor = 1`; additions are optional fields only (no major bump); a client refuses a server whose `api_major` differs and says which side to upgrade; unknown response fields are ignored.
- `wt-session` never starts `wt-model`, never guesses an address, never falls back to anything local; an unreachable server fails fast naming the address tried.
- Session ids are client-generated UUIDs; heartbeat every 20 s; the server's TTL is 60 s; no heartbeat means done; the session ends explicitly on exit; sessions are advisory for launch (a failed register or heartbeat is a `wt: note:`, never a refusal).
- Start is explicit; stop is automatic after the idle grace (server setting, default 10 min). The client never starts a model without a user act (`-M` pin, Enter on a start row, `wt start`, `wt smoke`).
- No LiteLLM master key, provider key or other `wt-model` credential on the session side; the gateway never forwards the session's credentials.
- Messages follow the style guide: M3/M6 (`wt: <what failed> — <why> — <way out>`, lower-case, upper-case placeholders, no `error:`), M7 (say what is still true), P1 (default-No), P3/P4 (prompts only from `/dev/tty`; no terminal means refuse, name the flag, exit 3), C9 (exit codes), J3/J7 (fixtures, constants).
- Tests: every `Test*` has a top-level `//` comment (what and why); seams are per-call values; packages whose tests reach config, git or lifecycle carry `TestMain` isolations (`config.IsolateConfigHomeForTest`, `gitenv.IsolateForTest()`, `tiers.IsolateForTest`, `lifecycle.IsolateProcessesForTest`); no test binds a fixed port (`httptest`, `127.0.0.1:0`); `modelclient`'s tests need none (no config, git or lifecycle).
- Never `os.Exit` outside `main`; a session ends (`DELETE sessions/{id}`) before any `os.Exit` branch in `runAgentCmd`.
- Run Go from `wt/`; scope test runs with `-run`; the full suite is ~10 min (use a background run for the gates).

## Review Focus

1. The server restarts, or a network gap exceeds 60 s, while an agent runs: the next heartbeat answers `410 unknown_session`, the client re-registers with its **full** model set silently, and heartbeat failures never kill the agent (Task 6, Task 9).
2. Ctrl-C during a start: the job keeps running, its id is printed with how to watch or cancel it, nothing is launched, exit 2; a second `wt start` for the same model attaches to the active job instead of queuing a duplicate (Task 2, 6, 11).
3. An answered question is never asked twice, and with no terminal the missing consent is named: `--replace`, `--others`, `--yes`, exit 3 (Task 6, 9).
4. A native row (`claude/native`, `copilot/native`) never receives the gateway origin or token, in any driver or slot profile (Task 1, 7, 8, 12).
5. Token handling: a token file looser than 0600 refuses to load, an inline `token` key in `config.toml` is refused, and pi's `models.json` that carries the token is written 0600 (Task 4, 8).

### Task 5: `modelclient` HTTP client

**Files:**
- Create: `wt/internal/modelclient/client.go`, `wt/internal/modelclient/errors.go`
- Test: `wt/internal/modelclient/client_test.go`, `wt/internal/modelclient/realserver_test.go`

**Interfaces:**
- Consumes: `modelapi.*` (Tasks 1-3), `Endpoint` (Task 4).
- Produces: `func New(ep Endpoint, opts ...Option) *Client`; `Option`s `WithHTTPClient(*http.Client)` (default: a client with a 5 s dial timeout and no overall timeout) and `WithSleep(func(time.Duration))`. Methods, all `ctx`-first, each sending `Authorization: Bearer <token>`:
