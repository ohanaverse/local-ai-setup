# wt-session Client (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the launcher (`wt`, becoming `wt-session`) a client of `wt-model`: every model decision (catalog, pin, start, stop, smoke, slot profiles, spend) goes over one endpoint and one token; direct routes, `[litellm] enabled`, `refcount` and the post-exit stop picker are gone from the session paths.

**Architecture:** A new dependency-light package `internal/modelclient` (HTTP client, job driver with typed-problem answers, session heartbeat) consumes the Phase 1 wire contract (`internal/modelapi`). Wire rows become the session's model value through an adapter in `internal/catalog` (`FromWire`, `ToModel`), so drivers, pickers and tests keep `config.Model` / `catalog.Row` as their currency. Server-side additions (catalog fields, requester-aware stop, job list, idempotent start, gateway path allowlist, candidates, spend) land first and are additive. The client path is built beside the old one, selected only by an explicit `[model-server]` endpoint+token, then made the only path.

**Tech Stack:** Go 1.26.7, stdlib `net/http`, cobra, bubbletea (existing). No new module dependencies.

**Spec:** `docs/superpowers/specs/2026-11-15-wt-model-session-split-design.md` (Phase 2 of "Migration"; "Control API", "Auto-stop", "Connection and configuration", "Further decisions"). Style authority: `wt/docs/style-guide.md`. Phase 1 plan (house style): `docs/superpowers/plans/2026-11-15-wt-model-server.md`.

## Scope

**In Phase 2.** Everything the spec assigns to the client in "Migration" step 2, plus the server changes the client forces: (a) additive `wt-model` API changes (Tasks 1-4, including the gateway inference-path allowlist the spec names as Phase 2 work); (b) the client package and the explicit endpoint+token config (5-7); (c) launch, `-M` resolution, pickers, `start`, `stop <model>`, `job`, `model list --server`, slot profiles and `smoke` on the API (8-17); (d) the flip: no `[model-server]` means a refusal, `[litellm] enabled` retired, `wt litellm on|off` retired, host commands moved onto `hostConfig()` (18); (e) deleting direct routes, pi's direct `models.json` rewrite, `refcount`, the stop picker, the ollama check and the in-process start/route code from the session paths (19); (f) binary naming and shims (20); (g) the llmbench message and the cross-cutting docs (21-22). Each behavior's docs, skill and fixture edits land in the task that changes it (D3); Task 22 holds only the cross-cutting pages.

**Boundary rulings** (the spec left these open):
- **R1 Binary naming.** `wt/cmd/wt` is renamed `wt/cmd/wt-session` (Task 20, after the code tasks, which therefore name `cmd/wt` paths). `make build` produces `bin/wt-session` and `bin/wt`, the same binary under both names (two files, each codesigned; a copy, not a symlink); `make install` installs both; the `*-wt` shims keep `exec wt`. The stderr prefix and `--version` word stay `wt` (style guide N1: "stays `wt` until a rename is decided").
- **R2 Transitional dual path.** Tasks 10-17 add the client path beside the registry path; a configured endpoint (`app.endpointConfigured()`) selects it. `app.cfg` stays `config.Load()` until Task 18, so no host command changes behavior before the flip; the client path reads `app.sessionCfg()` (`config.LoadSession`, never the registry). Task 18 flips (no endpoint: refusal) and Task 19 deletes the old path. Nothing after Task 19 is reachable on two paths.
- **R3 Host commands stay in this binary until Phase 4.** `model init|add|edit|rm|list`, `cloud-sync`, `litellm sync|list|providers|status|restart|set`, `served`, `warm`, `stop <provider>|--all` and the Models tab still load the registry through `app.hostConfig()` (Task 18 converts every call site); they print no pointer to `wt-model` yet. The session half of `model list` is `wt model list --server` (Task 15), so modeltiers' `wt model list --json` contract is untouched.
- **R4 Host LiteLLM key.** `[litellm] url/api_key` stays in `config.toml` as host state read by `wt-model serve` and `wt litellm set` only; session code never reads it (enforced by Task 19's boundary test). `wt-model`'s own config home waits for Phase 4's `wt-model litellm set`.
- **R5 Protocols.** Each driver keeps its one fixed wire to the gateway (LiteLLM translates); `row.protocols` is informational and filters nothing.
- **R6 Eligibility.** Per-agent `supported_providers` stay in `config.toml`; `config.SushiAgents` agents implicitly support provider `sushi`; the session cannot validate provider ids against a registry and does not try.
- **R7 Routed (tri-state).** The catalog row's `routed` is `true`, `false`, or omitted when the server could not ask LiteLLM. A launch of a local `running` row whose `routed` is `false` runs a start job (the server adds the route, an idempotent start of a running model); `routed` omitted (unknown) launches directly, and the gateway's `503`/`Retry-After` or the agent's own retry decides. Only an explicit `false` ever starts a job.
- **R8 Cancel.** Ctrl-C detaches (the job continues; the id is printed); an explicit cancel is `wt job ID --cancel` and `c` on the TUI start screen once the job has an id. No client code refuses cancel "past routing" (`pastCancel` is deleted).
- **R9 Stale-pricing notice** stays on the session, driven by `Catalog.Pricing` and the server's clock (R16); the registry's stamps are host data.
- **R10 `protectedPaths`** (`wt worktrees|remove` refusing a worktree that holds a registered artifact) keeps its registry read through `hostConfig()` **and its fail-closed rules unchanged** (`protectedPaths`/`noRegistry` in `cmd/wt/cleanup.go`): only a registry file absent at the default path means no protection and no error; an unreadable or unparsable registry, a malformed `local_path` or a registry at a redirected path is still `errRegistryUnavailable` (artifact protection OFF and removal refused), because a protected artifact is a quantized model wt never deletes. Its texts stay frozen for the `wt-repo-cleanup` skill (Task 18). It is the one named exception in Task 19's boundary test besides `hostConfig` itself.
- **R11 Token on disk.** The session token may live in pi's `models.json` and agent env; the file is written mode 0600. The spec forbids host credentials on the session, not the session token.
- **R12 Gateway retries.** The agent owns its own gateway retries (a `503` with `Retry-After` during a route restart reaches the agent, which wt cannot make retry; control calls never go through LiteLLM). wt retries only what it drives itself: `modelclient.WaitGatewayReady` (poll `GET /v1/models` through the gateway, honouring `Retry-After`, capped at the 3-minute drain bound) before a `smoke` row and once more when a row FAILs while the gateway answers `503`; a row that still sees `503` is SKIP, never FAIL. A non-retrying agent is a recorded limit in `wt/docs/wt-smoke.md` (#598).
- **R13 Session-only machines have no agent list to seed.** `config.Load` returns an empty config for an absent `config.toml` and the migrations run only on an existing file; nothing writes default agents. `config.LoadSession(driverNames ...string)` therefore adds, in memory and never saved, an agent for every model-driven driver (`agents.Names()` minus command agents) that `config.toml` does not name, with `AllProviders` set (`Agent.AllProviders bool toml:"-"`): eligible for every catalog row except another agent's native row. An entry in `config.toml` always wins, so an explicit `supported_providers` narrows. It also runs `migrateAgentRefs` on the file's entries in memory.
- **R14 `wt start` goes through the idle grace.** The server auto-stops only models some session registered (`Sessions.Seen`), so `wt start ID` registers a client session with the model before the start job and ends it right after the job succeeds; the grace clock then runs like any session's model, and nothing `wt start` loads stays up forever. Its output says so (Task 14). `wt smoke` registers one session for the whole run (Task 17).
- **R15 Exit codes** are one table (Global Constraints), carried by `remoteExit(err)` in `cmd/wt/models.go`.
- **R16 Server clock.** The client measures its offset to the server from the `Date` header of every response and exposes `Client.Now()`; the stale-pricing notice and the `spend` window bounds use it, and a job's elapsed time uses the client's monotonic clock, never server timestamps.
- **R17 Admin commands stay until Phase 4.** After Phase 2 this binary still runs `model add|edit|rm`, `cloud-sync`, `litellm sync|set|restart`, `stop <provider>|--all`, `served`, `warm` and the Models tab, reading and writing `registry.toml`/`config.yaml` through `hostConfig()`, and the `[litellm]` url/key stays in the file `LoadSession` also reads (as an inert table). That is the state the spec calls an anti-goal for a session; it is an interim limit recorded in `wt/docs/wt-session.md` and the spec, closed by Phase 4. Task 19's boundary test keeps every session path off it; Task 18's `TestHostCommandsStillLoadTheRegistry` shows the host commands still work.
- **R18 Terminal close.** wt does not trap `SIGHUP`/`SIGTERM` sent to itself; a killed wt cannot call `DELETE`, so its client session ends by the server's 60 s TTL (no heartbeat means done). Recorded as a documented limit in `wt/docs/wt-session.md`.

**Deferred.** *Phase 3:* untangling `internal/tui` and the import graph (this phase removes the calls, not the imports; the session binary still links `lifecycle`, `litellm`, `localmodels`). *Phase 4:* moving the admin commands and Models tab to `wt-model`, pointers in `wt-session`, `wt-model litellm set` and its config home, `wt-model check`, the session `litellm list|status`, the `wt-cloud-sync` skill rewrite, a host-side stale-pricing notice. *Issues:* #596 (slot profiles over LiteLLM aliases: slot profiles keep today's behavior over catalog rows here), #597 (subscription mixed slots: native rows stay un-gatewayed), #598 (restart/drain: R12 is the whole client-side answer here).

**Preconditions.** The W2 and W4 style-guide packages (single error line; approval-missing exits 3) are merged first; this plan uses `exitcode.New(3, err, false)` for approval-missing and `exitcode.New(1, err, false)` for "could not start", exactly as `cmd/wt/remove.go` does.

## Global Constraints

- API prefix `/control/v1/`, gateway `/v1/*`, `modelapi.APIMajor = 1`; additions are optional fields only (no major bump); a client refuses a server whose `api_major` differs, and a catalog whose `schema` is newer than `modelapi.SchemaVersion`, and says which side to upgrade; unknown response fields are ignored.
- `wt-session` never starts `wt-model`, never guesses an address, never falls back to anything local; an unreachable server fails fast naming the address tried.
- Session ids are client-generated UUIDs; heartbeat every 20 s (`defaultInterval`, held by a test); the server's TTL is 60 s; no heartbeat means done; the session ends explicitly on exit; sessions are advisory for launch (a failed register or heartbeat is a `wt: note:`, never a refusal).
- Start is explicit; stop is automatic after the idle grace (server setting, default 10 min). The client never starts a model without a user act (`-M` pin, Enter on a start row, `wt start`, `wt smoke`).
- No LiteLLM master key, provider key or other `wt-model` credential on the session side; the gateway never forwards the session's credentials.
- **Every control call is bounded.** Each `modelclient` call runs under a per-request timeout (`defaultRequestTimeout` 10 s, `WithRequestTimeout` for tests); only a gateway stream may be unbounded and wt-session opens none. `End` runs on `context.WithoutCancel(ctx)` with its own 3 s bound, so Ctrl-C and a dead server never leave the shell hanging or the session lingering.
- **Server text is untrusted (M11).** `modelclient` passes every string a typed error, `JobView`, `Problem` or catalog row carries through one `clean()` (same rule as `cleanup.Flatten`: controls and bidi dropped, whitespace collapsed to one line) at the decode boundary, so a hostile or buggy server cannot forge lines or repaint the terminal in any CLI line, TUI cell or status.
- **Wording (N7).** User text says `client session(s)` wherever the server's registry is meant (never bare "session"); `wt session` stays reserved for a launch that claims a worktree. `TestUserTextQualifiesSession` scans the string literals of the new `modelclient` and `cmd/wt` files for an unqualified `session`.
- Messages follow the style guide: M1 (results on stdout without the `wt:` prefix, everything else stderr), M3/M6 (`wt: <what failed> — <why> — <way out>`, lower-case, upper-case placeholders, no `error:`), M7 (say what is still true), P1 (default-No), P3/P4 (prompts only from `/dev/tty`; no terminal means refuse, name the flag, exit 3), P5 (a picker without a terminal names the flag that avoids it), C2 (`Long`/`Example`/exit paragraph), C9 (exit codes), D1 (a page per command), J1/J3/J4/J7 (fixtures, envelope, constants).
- **Exit codes (C9, one table for Phase 2).**

  | Code | When |
  |---|---|
  | 0 | done; a job that succeeded (a still-finishing stop included) |
  | 1 | could not start, nothing asked and nothing changed: not configured, unreachable *before* anything started, wrong token, API or schema skew, unknown model, a pin that is `blocked`, unknown job id, a `--json` command's failure envelope |
  | 2 | a started thing did not finish: a failed, blocked, stopped or cancelled job (`*JobError`), a lost server (`*LostServerError`), a lost job (`*JobLostError`), a detach (`*DetachedError`), `wt job ID` of a failed or cancelled job |
  | 3 | approval missing: no terminal and no flag, or the prompt was declined (`*DeclinedError`); nothing changed |
  | agent status | a launch ends with the agent's own exit status; `wt smoke` exits 1 on a FAIL row (C9's named exception) |

- Tests: every `Test*` has a top-level `//` comment (what and why); seams are per-call values; packages whose tests reach config, git or lifecycle carry `TestMain` isolations (`config.IsolateConfigHomeForTest`, `gitenv.IsolateForTest()`, `tiers.IsolateForTest`, `lifecycle.IsolateProcessesForTest`); no test binds a fixed port (`httptest`, `127.0.0.1:0`). `modelclient` imports no config, git or lifecycle package (it keeps its own `clean()`, held equal to `cleanup.Flatten` by a parity test in `modelserver`), so its tests need no isolation; the tests that run a real `modelserver.Server` live in `internal/modelserver` (which has the four isolations and the Phase 1 e2e fakes).
- Never `os.Exit` outside `main`; a session ends (`DELETE sessions/{id}`) before any `os.Exit` branch in `runAgentCmd`.
- Run Go from `wt/`; scope test runs with `-run`; the full suite is ~10 min (use a background run for the gates, and capture the exit code in the log, not only the wrapper's). Every task's final run also includes `go build ./... && go vet ./...` (vet compiles all test files).

## Review Focus

1. The server restarts, or a network gap exceeds 60 s, while an agent runs: the next heartbeat answers `410 unknown_session`, the client re-registers with its **full** model set silently, and heartbeat failures never kill the agent (Task 7, Task 11).
2. Ctrl-C during a start: the job keeps running, its id is printed with how to watch or cancel it, the session still ends (End is not cancelled with the context), nothing is launched, exit 2; a second `wt start` for the same model attaches to the active job, and the server returns one job for two simultaneous starts (Task 3, 7, 11, 14).
3. An answered question is never asked twice, and with no terminal the missing consent is named: `--replace`, `--others`, `--yes`, exit 3; a declined prompt exits 3 (Task 7, 11).
4. A native row (`claude/native`, `copilot/native`) never receives the gateway origin or token, in any driver or slot profile (Task 2, 8, 9, 16).
5. Token handling: a token file looser than 0600 refuses to load, an inline `token` key in `config.toml` is refused, pi's `models.json` that carries the token is written 0600, and a wrong or rotated token is a distinct refusal at launch and a distinct one-time note on a heartbeat (Task 5, 6, 7, 9, 11).
6. LiteLLM restarting or briefly unreachable: the catalog says `routed` is unknown rather than false, so no running model is re-started; the gateway answers `503` with `Retry-After`, the agent retries by itself, and `smoke` waits for the gateway and SKIPs rather than FAILs (Task 2, 8, 17; R7, R12).
7. A hung (half-open) server: no call blocks past its timeout, the heartbeat loop keeps beating and notes once, a poll counts hung requests toward `PollGrace`, and `End` returns within its bound (Task 6, 7).
8. Server text is a remote party's: newline and ESC in a step, message, label or block reason cannot forge a stderr line or repaint a TUI cell (Task 6, 11, 13).
