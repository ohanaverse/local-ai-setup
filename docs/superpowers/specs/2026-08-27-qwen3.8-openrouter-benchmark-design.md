# qwen3.8 Full Benchmark — Four OpenRouter Models + Local Backends (Design)

**Date**: 2026-08-27
**Status**: Approved

## Goal

Configure and run a full benchmark of the qwen3.8 model family across four backends — Ollama, llama.cpp, oMLX, and OpenRouter — each tested **with and without LiteLLM** (i.e., direct against the backend's native API, and routed through the local LiteLLM proxy).

The local models (Ollama, llama.cpp, oMLX) are already downloaded and configured. The new work is:

1. Configure the **four** qwen3.8 models on OpenRouter (currently only `qwen/qwen3.8-27b` is configured).
2. Extend the benchmark to test all four OpenRouter models both **direct** (OpenRouter API) and **via LiteLLM**.
3. Re-run the full benchmark (3 local backends + 4 OpenRouter models) in one pass.

## Components & Changes

### 1. LiteLLM config (`~/.config/litellm/config.yaml`)

Add 3 OpenRouter entries alongside the existing `qwen/qwen3.8-27b`, reusing the same `api_key` and `api_base`:

```yaml
- model_name: openrouter/qwen/qwen3.8-flash
  litellm_params:
    model: openrouter/qwen/qwen3.8-flash
    api_key: sk-or-v1-...
    api_base: https://openrouter.ai/api/v1
- model_name: openrouter/qwen/qwen3.8-2.4t-a95b
  litellm_params:
    model: openrouter/qwen/qwen3.8-2.4t-a95b
    api_key: sk-or-v1-...
    api_base: https://openrouter.ai/api/v1
- model_name: openrouter/qwen/qwen3.8-max
  litellm_params:
    model: openrouter/qwen/qwen3.8-max
    api_key: sk-or-v1-...
    api_base: https://openrouter.ai/api/v1
```

### 2. Benchmark script (`benchmarks/qwen3.8-benchmark` + `~/.local/bin` copy)

- Add an OpenRouter direct URL (`https://openrouter.ai/api/v1/chat/completions`) and the API key.
- Add a 4-model OpenRouter list (`flash`, `27b`, `2.4t-a95b`, `max`).
- Replace the current single hardcoded OpenRouter-via-LiteLLM call with a loop that tests each of the 4 models **direct** (OpenRouter API) and **via LiteLLM**.
- Extend `run_streaming` to accept an optional auth header (needed for direct OpenRouter calls, which require `Authorization: Bearer <key>`).

### 3. API key handling

Read the key from `~/.config/litellm/config.yaml` at runtime (via `grep`) rather than hardcoding a second copy of the secret into the script. Fallback to an `OPENROUTER_API_KEY` env var if present.

## Data Flow

1. **Setup** — ensure Ollama, oMLX, llama.cpp, and LiteLLM are all up.

2. **Local backends** (Ollama → oMLX → llama.cpp), each:
   - Unload all local models (isolation), then load only the one under test.
   - Run the prompt **direct** against that backend's native API.
   - Run the prompt **via LiteLLM** (`localhost:4000`).
   - Measure TTFT, total time, tokens, throughput for each.

3. **OpenRouter** (cloud, always live — no isolation needed):
   - Restore all local services to their normal running state.
   - For each of the 4 models (`flash`, `27b`, `2.4t-a95b`, `max`):
     - Run **direct** against `https://openrouter.ai/api/v1/chat/completions` with `Authorization: Bearer <key>`.
     - Run **via LiteLLM** using the `openrouter/qwen/...` model name.

4. **Output** — one timestamped Markdown file in `/tmp/qwen3.8-benchmark-<ts>.md` with per-backend tables (TTFT, total, tokens, throughput), plus the notes section.

The multi-pass wrapper (`qwen3.8-benchmark-multi 3`) runs this whole flow 3× with cool-down, and we take medians — same as the existing methodology.

## Error Handling

- **Per-model resilience** — if any single OpenRouter model fails (auth error, provider 429/5xx, timeout), the script records `N/A` for that cell and continues to the next model rather than aborting the whole run. The 4 OpenRouter models land on different upstream providers with varying reliability.
- **Auth failures** — if the OpenRouter key is missing (config `grep` fails and no `OPENROUTER_API_KEY` env var), the script prints a clear error and skips the direct OpenRouter tests (LiteLLM-routed tests still work since LiteLLM holds the key).
- **Non-200 responses** — `run_streaming` already tolerates curl failures (`wait "$pid" || true`); extend it to detect a non-`chat.completion` response and mark the row `N/A` instead of emitting garbage token counts.
- **Local isolation** — unchanged: warmup timeouts already return a warning and continue (existing `start_one_local` behavior).
- **`set -e`** — keep it but ensure the OpenRouter loop uses `|| true` guards so a single failure doesn't kill the run.

## Testing & Verification

1. **LiteLLM config check** — after editing `config.yaml`, restart LiteLLM and confirm `/v1/models` lists all 4 `openrouter/qwen/...` models.
2. **Direct OpenRouter smoke test** — one `curl` to `https://openrouter.ai/api/v1/chat/completions` with the key to confirm auth and response shape (usage/completion_tokens present).
3. **Script smoke test** — run `qwen3.8-benchmark 30` (small `max_tokens`) to verify the full flow works end-to-end before the real run.
4. **Full run** — `qwen3.8-benchmark-multi 3 200` (3 passes, 200 tokens), then compute medians.
5. **Result verification** — confirm the output Markdown contains 6 local rows (3 backends × direct/LiteLLM) and 8 OpenRouter rows (4 models × direct/LiteLLM), with no `N/A` cells except where a provider genuinely failed.

## Out of Scope

- No changes to the local backend configuration (already downloaded and working).
- No changes to the Ornith-1.5 benchmark (separate model family).
- No accuracy/quality evaluation — this is a performance/latency benchmark only.
