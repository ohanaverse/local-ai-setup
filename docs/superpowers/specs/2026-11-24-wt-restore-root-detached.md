# `wt restore-root` for a detached root (#584)

**Status:** the owner chose "E plus C" for issue #584 on 2026-11-24. Amends `2026-11-08-wt-restore-root-design.md` (its non-goal "A detached root: v1 refuses and names `git switch -c`", decision 2, Preflight step 2, the Execute flow, the recovery table and the JSON keys). Everything not said here is unchanged.

## Behavior

A detached root splits three ways, decided by git inside `rootmove.Preflight` (not by the cleanup row): `git for-each-ref --contains <HEAD> refs/heads refs/remotes` (a symref `*/HEAD` ignored; tags, the stash, `refs/wt/rescued/*` and other worktrees' HEADs do not count).

- **E, a branch holds HEAD.** There are no commits to park. Dirty work (staged, unstaged, untracked) is carried and verified into a new worktree under `.worktrees/` **left detached** at HEAD (no ref, no invented name; directory `--to NAME` or `detached-<first 8 hex>`), the record is written (`Wt-Dest-Branch: detached`), then `removal.ReleaseRoot` resets and switches the root to the default branch. A **clean** such root has nothing to keep: no worktree and no record; only the release runs (`NothingUncommitted`, same gates as the clean branch flow: fingerprint, empty status, hidden index, ignored at risk). Result `moved`, `created` false, no `dest_path`. Held only by a remote-tracking ref: a plan warning (a pruned ref could orphan a clean move's commits), never a refusal.
- **C, no branch holds HEAD and `--branch NAME`.** `NAME` is created at HEAD **in the new worktree** (`git switch --no-track -c NAME`, hooks off) after the verified copy and the record and **before** the release, never in the root. A failure there leaves the root untouched (`branch_create_failed`). A clean root still gets the worktree (NAME lives there) but no record. `--branch` on a root a branch already holds is honoured.
- **No branch holds HEAD, no `--branch`:** refused `detached_root`, naming `--branch`.

`--branch` is refused, nothing created: root on a branch (`branch_unneeded`), invalid name by `git check-ref-format --branch`, `@` or a `refs/` prefix (`branch_invalid`), existing `refs/heads/NAME` (`branch_exists`); empty/whitespace/padded is a usage error (exit 1). Re-checked at the creating step.

## Decisions taken (the implementer's calls, recorded)

1. **`removal.ReleaseRoot` keeps its own safety.** `RootRelease.DetachedAt` (the full HEAD id; "" keeps the old rule that the root is on a branch) lets it release a detached root only if HEAD equals it and a fresh `for-each-ref --contains` finds a branch. Only `ReleaseRoot` resets or switches the root (the allow-list and hard-reset guard tests are unchanged).
2. **Order for a detached root in Preflight:** `no_commit`, `branch_unneeded`, `branch_invalid`/`branch_exists`, `no_default_branch`, `default_in_worktree`, held read, `worktrees_not_ignored`, `hidden_index_flags`, rescue's root-mode Preflight (so `operation_in_progress`/`unmerged_paths` win over "name a branch"), `ignored_collision`, and last the reachability decision. `already_default` never applies to a detached root.
3. **rescue's root mode** accepts a source with no ref: `Engine.RootNewBranch` (NAME for C), `Plan.SourceDetached`; `Plan.Branch` is "" for E and NAME for C; `Counts.Commits` is `rev-list --count HEAD --not --branches --remotes` (the commits parked, 0 for E); the record's `Wt-Dest-Branch` is `detached` for E.
4. **Execute:** step 0 also re-reads that the root is still detached at HEAD and, for E, still held (for C, NAME still free); step 1 uses `worktree.CreateDetachedAtCommit` (no branch tip to compare); step 3b (new `stepBranch`) creates NAME; step 5 (switch the destination onto the branch) is skipped, the destination is final (detached, or on NAME); the read-back reads a detached or NAME destination, or the root alone for a clean E.
5. **Recovery table:** new row `branch_create_failed` (root untouched, still detached, work intact; the commits are held only by the root's HEAD and the record, so give them a branch first). After-reset rows for a detached root say `git switch <default>` in the root only, never a switch in the destination. Nothing deletes NAME or the worktree.
6. **JSON** (additive, version stays 1): `detached` (bool), `head` (commit id), `branch_created` (bool); `branch` is absent for E and NAME for C; `dest_path` is absent for a clean E; `carried` is also written for a detached plan. Codes `branch_unneeded`, `branch_invalid`, `branch_exists`, `branch_create_failed`; `detached_root` narrows to "no branch holds it and no `--branch`". Samples: `.detached`, `.detached-clean`, `.branch`, `.branch-exists`. A consumer must not assume `moved` implies `dest_path`.
7. **The list's `R`** (`rootmove.Offered`, which reads the row only): a detached root with `Losses.DetachedUnique` false (the default branch reaches HEAD, so E is certain) is offered; with it true the status line is `rootmove.DetachedUniqueLine` ("the root is detached at commits the default branch lacks: run `wt restore-root` (it needs --branch NAME if no branch holds them)"). **Known limit:** a root whose HEAD only a feature branch holds reads `DetachedUnique` true, so `R` explains although the command would succeed. An exact answer needs a gathered fact and a cleanup-list contract change; deferred (follow-up). **Superseded by #749:** the row now carries `Row.HeadHeld` (`head_held` in the cleanup-list JSON), read with the command's own reachability check (`cleanup.BranchesHolding`); `Offered` offers a detached root when it is true or unread and explains it with `rootmove.HeadNotHeldLine` ("the root is detached at commits no branch holds: run `wt restore-root --branch NAME` to give them one") when it is false. `DetachedUniqueLine` is gone.
8. `rootclaim.Hint` (the launch hint) stays silent for a detached root: whether `--branch` is needed is not known there.
