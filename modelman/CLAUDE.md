# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`modelman` is a Python 3.13 Textual TUI and CLI for managing LLM models across providers (Ollama, oMLX, MTPLX, mlx_lm_server, OpenRouter, native agents; llama.cpp is retired but its provider code is kept — see `../docs/reference/provider-artifacts.md`) and routing them through LiteLLM. **LiteLLM management is wt-owned (since 2026-09-21):** modelman never edits LiteLLM's `config.yaml` or restarts the proxy — it delegates to `wt litellm ...` and **requires `wt` on PATH** (`make install` from the repo root; write paths raise a clear error before changing any state when it is missing). User-facing behaviour (TUI keys, column formats, TOML schemas) is documented in `README.md`; this file covers internals and gotchas.

CLI (`src/modelman/main.py`, Typer; bare `modelman` opens the TUI via `@app.callback(invoke_without_command=True)`):

| Command | Purpose |
|---|---|
| `migrate` | One-time import of legacy `config.yaml` + `families/*.yaml` |
| `sync` | Reconcile state against providers, then one `wt litellm sync` |
| `litellm status\|on\|off\|set` | Passthroughs to `wt litellm ...` (wt owns routing state) |
| `start [model_id]` / `stop <id>\|--all` | Local-model lifecycle (`local_control.py`); bare `stop` is a usage error. No-arg `start` prints a live inventory (see "Local-model lifecycle") |
| `ollama-catalog sync [--dry-run] [--html F] [--yes [--approve-removals DIGEST]] [--force]` | Mirror ollama.com/pricing: update ollama cloud prices (incl. off-peak `time_prices`), add/remove registry entries, `ollama pull` missing cloud stubs and `ollama rm` unlisted ones; the CLI then applies pulls/deletes and runs one `wt litellm sync`, which rebuilds every page model's row from the registry with its current prices and drops the removed models' rows (wt restarts the proxy only when `config.yaml` actually changed). One confirmation (default No if anything is deleted), or `--yes` — which deletes only under the `--approve-removals` digest a reviewed `--dry-run` printed. Exit 1 a pull/rm/save failed / 2 fetch or `ollama list` failed / 3 page-shape change (HTML saved) / 4 mass removal (> half the cloud entries, re-tags excluded) without `--force` / 5 deletions not approved (digest mismatch, or the locked re-plan deletes more than was printed); 2–5 change nothing. Driven by the `ollama-catalog` skill |
| `refresh-prices` | Refresh OpenRouter-priced models' per-token prices from OpenRouter (`pricing.py`); stamps `price_refresh_last_run` only when it updated at least one model |
| `delete-family <name>` | Remove an empty family's lingering `[[families]]` entry (queue.py keeps families sticky); refuses if the family still has models |
| `provider isolate\|stop\|stop-all\|restore\|list` | Low-level per-provider lifecycle (`providers/lifecycle/cli.py`) |
| `benchmark ...` | `benchmark/cli.py`, plus `benchmark agent` / `benchmark eval` sub-apps |
| `usage report` | `usage/cli.py` — wt launch history × LiteLLM spend |

Sub-Typer apps mounted in `main.py`: `benchmark`, `usage`, `provider`, `litellm`.

## Monorepo context

- `wt/` (Go sibling) reads `registry.toml` and `modelman.toml` read-only. The cross-language schema is pinned by the `docs/contracts/` fixtures, loaded by `tests/contracts/` here and `wt/internal/config` there — change a fixture without updating both sides and both CI jobs fail.
- `modelman benchmark` and `local_control.py` call `providers/lifecycle/orchestrate.py` in-process (issue #79). Nothing in modelman shells out to `bin/`.

`uv` for packaging; Python `==3.13.*`. Run `make help` for targets.

- `make install` (`uv sync`), `uv run modelman` (TUI), `uv run modelman <subcommand>`
- `make test`; single test: `uv run pytest tests/path/to/test.py::test_name`
- `make check` = lint + `ruff format --check` + mypy; `make all` = format + test + check
- Focused subsets: `uv run pytest tests/test_litellm.py tests/test_queue.py -q`, `uv run pytest -k "not screen" -q` (skips the slow Textual screen tests)

The suite (~1500 tests; screen tests in `tests/screens/` dominate) runs in ~1.5 min. `tests/conftest.py` autouse fixtures stop it from restarting the live LiteLLM proxy or calling the live `ollama` daemon, so it is safe to run while agents use the proxy.

`/code-review` findings must be verified manually — it misreads indirect usage like `monkeypatch.setitem()` and in-function imports.

## Architecture

### Entry point and TUI hand-off

- `main.py::run_tui()` runs the app; the app returns `QueuedOps | None`, and `run_queued_ops()` applies it against **freshly loaded** on-disk state after `run()` returns.
- `main.py::litellm_app` — thin passthroughs to `wt litellm status|on|off|set [--url --api-key]` via `wt_bridge`. The TUI's LiteLLM status line and `l` toggle use the same bridge ("LiteLLM: unavailable" when wt is unreachable). The mount-time status read uses a 5s timeout (`wt_bridge.STATUS_TIMEOUT`) so an unreachable wt can't hang the first paint; other bridge calls keep the 120s default.

### Textual TUI

- `app.py` — `ModelmanApp(App[QueuedOps | None])`; `on_mount` pushes one registry-backed `ModelScreen` as the only screen (FamilyScreen is gone). Also runs a daily-gated OpenRouter price-refresh worker.
- `screens/__init__.py` — `reload_preserving_cursor(table, repopulate)` restores the cursor onto the same row key after `DataTable.clear()` (falls back to row 0 if the key vanished). `reconcile_model_state(models, registry, state, local_map)` is the reconcile write-path: per provider it tries `resolve_local()` (batch; ollama uses one `ollama list`) and falls back to per-model `is_downloaded()`/`size_of()`; a misaligned/failed batch result degrades to the per-model path. No hard-coded provider ids — batch support is a provider capability. For local-artifact models (`registry.model_has_local_artifact`) it writes `ready`/`disk_path`/`size_bytes`; for cloud models `ready` is left alone. A known `disk_path` is kept unless a fresh one is observed.
- `screens/models.py` — `ModelScreen`. Holds `queued_ready`/`queued_deletes`/`queued_moves`; there is no queued-expose and no exposure column — modelman stopped having an `exposed` flag in #179. Columns: FAMILY · PROVIDER · MODEL · LOC · STATUS · RUNNING · COST · SIZE. Invariants worth knowing before touching it:
  - **Routing is invisible here, and maintained elsewhere.** No column reports whether LiteLLM routes a row — `wt litellm list` is the answer. Routing stays current because a *sync* follows the state change: `_sync_routes_and_warn()` (main.py) runs one `wt litellm sync` at the end of every queue apply (success *and* its unexpected-exception path; not after Ctrl+C, which is a clean stop — the next sync converges), after `migrate`/`sync`/`refresh-prices`, and on a TUI exit whose `registry.toml` changed. `_run_reconcile` runs one too, **but only when it cleared a stale `running` flag** — that model's route would otherwise point at a dead backend, and nothing else would drop it (the flag lives in `modelman.toml`, which the TUI-exit gate reads past). Gating on `stale_ids` keeps an ordinary mount — the common case — from bouncing the proxy.
  - **RUNNING** renders `●` for a local model whose `state.running` flag is set. The on-mount reconcile worker (`_run_reconcile`) also calls `running_model_ids()`, which probes and clears stale flags, so after mount the column shows verified state.
  - `r` is a true file-presence toggle: ready-off queues artifact removal (provider `delete()`, or `state.disk_path` for flag-only providers); pressing it again cancels the queued flip.
  - `s` start/stop — see "Local-model lifecycle".
  - Discovered-but-unregistered artifacts (`discover_unregistered_models()`, run alongside the on-mount reconcile) render as synthetic `[cyan]+[/cyan]` rows outside the STATUS glyph priority chain (they have no id to queue against, so `r`/`s`/`d` do nothing on one); RUNNING shows `●` when the artifact is flagged running under its discovered id (`DiscoveredModel.model_id`); `enter`/`e` on one opens a pre-filled `ModelForm` with Provider/Model locked — the explicit way to give it an overlay. The `+`-row form (`_submit_discovered`) registers the artifact under its discovered id itself (`DiscoveredModel.model_id`, #194) — the id wt already routes and keeps history for — so a running one's flag is already on the row the registration writes (`_on_register_discovered`); the provider row the artifact was found through stays the entry's `provider_id` (`omlx-6bit` under an `omlx/…` id). The `a` add form spells `/` as `--` in its generic branch (omlx repo names, retired llamacpp, and cloud providers alike, e.g. `openrouter/z-ai--<name>`); its mtplx branch keeps the slash, so an mtplx overlay added with `a` is `mtplx/org/name` — matching its discovered id. For omlx-6bit, the generic branch produces `omlx-6bit/org--name` while the discovered id uses the family prefix `omlx/org/name`.
  - `_provider_list()` derives from `registry.providers` (sorted).
- `screens/forms.py` — `ConfirmModal`, `ModelForm`, `ConfirmExitDialog`, `ConfirmForceQuitDialog`, all on a shared `ModelmanModal` base (buttons left-to-right with cancel rightmost, priority-bound `escape` that cancels even inside an `Input`, `_focus_button(id)` for safe-default focus on destructive prompts). Family Select is display-only in edit mode (issue #52; id/provider/location/family immutable); in add mode its `NEW_FAMILY_VALUE` sentinel ("+ New family…") reveals `#new-family-input`, resolved by `_resolve_family()`.

### Thread safety in worker threads

`self.app` is safe to call directly from a `@work(thread=True)` worker (e.g. `ModelScreen._run_reconcile`) **while the widget is mounted** — no captured reference is needed, and none exists. Textual resolves `Widget.app` two ways: the `active_app` contextvar, which is genuinely *unset* on a worker thread, and a fallback that walks `self._parent` up to the `App`. That walk is thread-agnostic, so it is what actually answers in a worker. (Verified on textual 8.2.8: `active_app.get()` raises `LookupError` inside the worker, and `self.app` still returns the `App`.)

`self._app_ref` was real once but is gone. #85 (commit `ddceb69`) removed the capture along with its only two readers, and they were two different cases — which is why the note above is the rule and not a blanket ban:

- `_run_apply`'s download-status snapshot ran on `StatusScreen`'s worker thread while `ModelScreen` sat on the stack underneath it: **mounted**, so `self.app` would have worked. Its comment justified the capture with "`Screen.app` raises `NoActiveAppError` when accessed off the main thread"; that diagnosis was wrong — it is the unmounted case, not the threaded one.
- `_register_deferred_expose`'s closure (removed by #85 too; nothing like it exists in `src/` today) was the genuine case: it fired when the download finished, possibly long after `ModelScreen` was gone. Its shape is still the one to copy for any such deferred callback — it captured `registry_path`/`state_path` up front and re-loaded fresh registry/state at run time rather than touching `self`, keeping the app reference solely to post the notification.

Don't reintroduce the capture for the first case.

The one way `self.app` fails is an **unmounted** widget: with no path to an `App`, the walk ends at `None` and `Widget.app` raises `NoActiveAppError` (a detached `Static("x").app` raises it too, in any thread). So a worker that outlives its screen must carry the data it needs — paths, ids — and re-load state rather than reach back through the widget, or finish before the screen is popped. `ModelScreen` sidesteps the whole question: it is the app's only root screen and stays mounted for the app's lifetime, even though its workers are the ones that can run for minutes (a warmup). That is why `action_back()` checks `self.workers` for anything still running and raises `ConfirmForceQuitDialog`.

### Pending changes queue

- `queue.py` — `PendingChanges(registry, state, registry_path, state_path, providers, ready, deletes, moves, failures, cancelled)`; `ready` is `list[tuple[model_id, VariantSpec, target_ready]]`. `apply()` order: **deletes** (free disk first) → **moves** (pure registry metadata; a move for a same-apply delete is dropped) → **ready** (downloads / clears / flag flips) → `_persist()`. It touches no route directly: every caller runs `_sync_routes_and_warn()` after `apply()` returns, and wt derives the routes from the registry + live probes.
- `_persist()` saves the registry and merges only this run's touched model rows onto a freshly-loaded `modelman.toml` under `locked_state` — never a whole-file write from the stale snapshot. A deleted id is popped from the fresh store (writing `state.get(mid)` would resurrect it as a default row).
- Deletes and ready-off both: check `provider.is_downloaded()` first (absent ⇒ skip provider `delete()` but still clean registry/state and emit lifecycle events; a raising `is_downloaded()` ⇒ attempt the delete conservatively); check `registry.find_shared_artifact_owner()` (omlx dirs are keyed on repo basename, so colliding repos share one directory — the file is kept, reason surfaced). The guard compares what the delete would remove (`Provider.removable_paths()`, which must name exactly what `delete()` removes) against where every other entry lives (`artifact_paths()`, the configured directory whether present or not), both resolved through `expanduser` + `realpath` so a `local_path` typed with `~`, `..`, a trailing slash or through a symlink still matches, and a directory that exists is matched by device + inode too, so another letter case on a case-insensitive volume is the same directory. Ready-off skips ids queued for deletion. A route to a model whose artifact just went away is dropped by the following sync (wt's ollama rows require the model to be pulled), so `config.yaml` never keeps routing to a missing file.
- Ready-on routing: provider absent from `providers` (native/unmapped/openrouter), or `manages_own_cache` (mtplx) ⇒ flag flip only; otherwise `provider.download(variant, on_progress=...)`, sequentially. Flag-only ready-off removes the artifact in `state.disk_path` via `_remove_local_artifact`.
- Failures are captured per step and processing continues. `main.py::run_queued_ops` turns a provider that fails to instantiate into a per-item ready failure rather than silently flag-flipping it.

### Downloads (queued, applied on exit)

- Nothing runs while the TUI is open: every action (including a real download against ollama/omlx/mlx_lm_server) only fills `ModelScreen`'s queued dicts, so there is no download manager, progress screen or download quit-guard. Add/edit are the exception — `registry.toml` is written immediately.
- `Escape`/`ctrl+q` with a pending queue shows `ConfirmExitDialog`: `Apply` exits with a `QueuedOps`, `Discard` restores the pre-session snapshot and exits with `None`, `Cancel` stays. A Discard after this session saved the registry (an add or edit — `ModelScreen._registry_saved`) sets `ModelmanApp.route_sync_owed`, and `run_tui` then runs the one route sync even though registry.toml is byte-for-byte what it was: a model added, started and discarded was routed under an id that no longer exists (#194). A Discard of queued toggles alone owes no sync.
- **Ctrl+C during `run_queued_ops()`**: the `KeyboardInterrupt` unwinds through the download step's `except BaseException` (which removes the partial artifact via `_cleanup_partial_download` so the next reconcile can't promote a truncated download), then through `apply()`'s outer `except BaseException` safety net, which calls `_persist()` — so every step that fully finished (deletes, moves, completed downloads/flag flips) is saved. The runner then calls `pending.cancel()`, prints `Cancelled: N steps completed, M remaining skipped.`, and exits non-zero. Distinct path: the `aborted()`/`self.cancelled` early return (and `DownloadCancelled`) is a plain return, not an exception — see the cancellation tests in `tests/test_queue.py` and `../docs/superpowers/specs/2026-09-13-downloads-on-exit-design.md` before changing either.
- `providers/_progress.py` — shared progress helpers plus `DownloadCancelled`, raised by the HF `ProgressTqdm` bar when `should_cancel` returns True. omlx, mlx_lm_server and llamacpp wire `should_cancel` to their `_cancel_requested` flag, flipped by `cancel_current()` (from `PendingChanges.cancel()`, usually another thread). Only a concurrent `cancel_current()` while the download context is still set reliably stops an in-flight download: `download()`'s own flip on `BaseException` races the `finally` that clears the class-level context.

### Registry and state

- `registry.py` — `Registry` (providers + models + families). `ModelEntry.cost` is a flat `Cost` (legacy `kind`/`price_per_*` schema migrated on load); optional per-model `location` overrides the provider's. `ProviderEntry.protocols` (wire protocols, default `["openai-chat"]`) is intersected by wt with each agent's protocols. Path precedence `MODELMAN_REGISTRY` > `XDG_CONFIG_HOME` > `~/.config` (matches wt's `config.RegistryPath`). `LOCATION_LOCAL`/`LOCATION_CLOUD`/`is_local_location()` live here; legacy `None`/empty location counts as local. `DEFAULT_PROVIDER_IDS` drives default templates and sync's model-dir set.
- `state.py` — `StateStore` over `modelman.toml` (`MODELMAN_STATE`); `StateStore.set` is the single write path. `FamilyEntry`/`FamilyState.display_name` are still round-tripped (queue.py family stickiness, migrate.py) though nothing renders them.
  - The `[litellm]` table is a **legacy read-only fallback** for wt; modelman round-trips it verbatim and never alters it.
  - `ModelState.running` is a **hint** recording modelman's start/stop intent, never ground truth; an absent field reads `false`. Every reader confirms it with a live probe.
  - `locked_state()` is the process-locked read-modify-write. `local_control.py`'s flag writes and `main.py`'s `sync`/`migrate`/`refresh-prices` persist merge-style through it — a whole-file write from a stale snapshot could revert a concurrently-written `running` flag. Keep new writers merge-style too.
  - **No exposure flag (#179).** There is no `exposed`/`litellm_exposed` field any more: `state.py` reads past both and drops them on the next save, so a legacy file self-cleans. "Is this model routed?" has exactly one answer, `wt litellm list` (`config.yaml` membership), which wt derives from `registry.toml` + live probes. wt does not read them either — since #179 Phase B it reads no `[model_state]` key at all (not `ready`, not legacy `downloaded`, not `running`; from this file only `price_refresh_last_run` and the legacy `[litellm]` table); the keys are ignored rather than rejected so an old file still loads — never write them.
- `litellm.py` — writes nothing. Holds: read helpers for `modelman usage` (`load_litellm_config`, `_database_url_from_config`, `_reverse_model_index` — maps `litellm_params.model` → `model_name` for spend rows with a NULL `model_name`, first `model_list` entry wins); and `sync_routes()`, the one route-write path modelman has: it calls `wt_bridge.sync()` and returns wt's warnings, skipping wt entirely when the LiteLLM config file doesn't exist (nothing is routed on that machine, and the call would only fail). Every state change that can affect routing runs it once, after its writes are saved — see `main.py::_sync_routes_and_warn` and the start/stop paths in `local_control.py`.
- `wt_bridge.py` — subprocess wrapper for `wt litellm ...` (`sync`, `routed_ids`, `litellm_status[_text]`, `litellm_set_enabled`, `litellm_set`); parses `--json` (contract fixture `docs/contracts/litellm-cli.sample.json`); raises `WtNotFoundError`/`WtBridgeError`; **never puts argv into an error message** (it may carry `--api-key`). Sets `WT_LITELLM_CONFIG` for the child when given a config path.
- `sync.py` — reconciles state against ollama (`ollama list`) and the model-dir providers (`MODELDIR_PROVIDER_IDS` = `DEFAULT_PROVIDER_IDS` minus ollama, plus retired llamacpp). It skips cloud-located models (`is_model_local(..., missing_provider_is_local=True)` — ollama `:cloud` stubs have no `ollama list` size to observe; a model whose provider isn't in the registry is still reconciled), so their `ready` flag survives, matching the TUI reconcile; benchmark `discover_targets` uses the same predicate to keep `:cloud` models out of default/`--family` runs. `backfill_provider_defaults` fills a missing `auth.base_url`/`protocols` from the default template, never overwriting user values.
- `pricing.py` — OpenRouter price refresh. `_is_openrouter_priced` picks `openrouter` models plus models of non-native cloud *providers*. It keys on the provider's location, not the model's, so ollama cloud models (`location = "cloud"` on the local ollama provider, priced by `ollama-catalog sync`) are excluded (#151). wt's `agents.HasOpenRouterPricedModel` mirrors this rule for its stale-pricing notice, so change both together; `_merge_api_cost` preserves manually-set cache/subscription pricing.
- `migrate.py` — one-shot legacy import, plus `migrate_wt_gateway_to_litellm` (never clobbers set `[litellm]` values). `manifest.py` (legacy `families/*.yaml`) and `config.py` (`default_config_path()`, `MODELMAN_CONFIG`) are migrate-only — add no new callers; new config goes in `registry.toml`.
- `settings.py` — TUI preferences (theme) in `~/.config/local-ai/settings.yaml` (`MODELMAN_SETTINGS`); a corrupted file raises rather than falling back.
- `_toml_io.py` — `atomic_write()` (temp + rename; `preserve_mode=True` keeps permission bits), `atomic_write_toml()`, `drop_none`, `unknown_keys`. Registry/state saves rewrite the whole file — preserve unknown keys on round-trip so hand-edited fields survive.
- `time_pricing.py` — `Window`/`TimePrice` (`Cost.time_prices`, `[[models.cost.time_prices]]`): time-windowed overrides of the flat per-token prices, first-match-wins per field, reference resolver `price_at()`. Stored only (no TUI/wt reader yet); `_merge_api_cost` and the TUI edit (`screens/models.py::_carry_over_unedited`) must carry them through.
- `ollama_catalog.py` + `ollama_catalog_cli.py` — `modelman ollama-catalog sync`. `parse_pricing` is the only code that knows ollama.com/pricing's HTML (header-keyed; raises `CatalogParseError` rather than writing partial data); `plan_sync` is pure (page name → the published cloud tag from `resolve_cloud_tags`, which reads `ollama.com/library/<name>/tags` concurrently on one shared `requests.Session` since sized-only models have no `:cloud` alias, skipping names `verified_tags` already knows from a pulled tag — but never a name two pulled entries both claim, which is what an interrupted re-tag leaves behind, so the lookup picks the current one; matched entries get `catalog_name` in model extra; an unresolved name protects every entry/pulled tag with its name stem from removal). An entry under an unpublished tag is re-tagged: removed and re-added under the real one, carrying its family, hand-set extras and `model_info` across — its LiteLLM route name is its id, so that one can't follow. The CLI saves price updates/additions under `locked_registry`, then hands pulls (`ready=True`) and removals (`deletes`) to `main.run_queued_ops` — queue.py's `is_downloaded` check skips `ollama rm` for never-pulled removals — whose closing `wt litellm sync` is what refreshes the prices: wt rebuilds each row from the registry, so a price change reaches `config.yaml` on the next sync rather than needing a re-expose. Tests use `tests/fixtures/ollama_pricing.html`; conftest guards its HTTP/ollama default runners.

### Provider plugin system

- `providers/base.py` — `Provider` ABC and `VariantSpec`/`LocalModel` TypedDicts (`VariantSpec` is `total=False`, with freeform `model_info`). Required: `name`, `is_downloaded`, `download`, `list_local`; `size_of` defaults to `None`. Optional: `path_of`, `resolve_local(variants)` (batch; `None` = unsupported). Capability class attributes replace hard-coded provider ids: `manages_own_cache` (`True` ⇒ `download()` always raises and `apply()` flag-flips ready-on; mtplx) and `supports_discovery` (`False` for `MLXLMServerProvider` — a target+draft pairing — and retired `LlamaCppProvider`; read by `local_control._provider_local_models()`). `running_flag_is_probed` (`False` for ollama only; read through `ProviderRegistry.running_flag_is_probed(row_id)`): whether a live probe confirms the running flag. `_probe_running` trusts an unprobed flag as set, so both reconcile paths (`sync.reconcile`, `screens.reconcile_model_state`, sharing `sync.stops_when_gone`) clear it themselves for a model they observe gone from disk (#233) — observed, not merely unqueryable. `modelman sync` carries those ids across its narrow state merge as `SyncResult.running_cleared`.
- `providers/registry.py` — `ProviderRegistry.register(cls)` / `.get(name, config)` / `.get_class(name)`. Each provider module (`ollama.py`, `omlx.py`, `mtplx.py`, `mlx_lm_server.py`, `llamacpp.py`) registers at import time; `providers/__init__.py` imports them all, so import from `modelman.providers`, not a submodule.
- `mtplx.py` is discovery-only over `~/.mtplx/models` (dir `<org>--<model>` ↔ repo `org/model` via `_dir_name`/`_repo_id`); the `mtplx` CLI manages its cache. Its server lifecycle lives in `lifecycle/backends/mtplx.py`, not the provider class.
- `OllamaProvider.is_downloaded` returns False only when `ollama show` stderr contains "not found" (case-insensitive, `_says_not_found` — shared with `delete()`, which treats an `ollama rm` "not found" as already done); any other failure raises (daemon down = unknown, not absent) so a delete still attempts removal instead of orphaning the artifact. `resolve_local` draws the same line for the batch path: a failed `ollama list` raises (callers fall back to per-model `is_downloaded`), never reads as "nothing pulled" — reconcile clears a running flag on observed absence (#233). `_listed_name` is the one name rule (exact, or tagless → `:latest`) shared by `resolve_local` and `sync._ollama_downloaded`.
- **Every `Provider` method that shells out must accept an optional `runner` arg** (like `is_downloaded`/`size_of`/`resolve_local`): the autouse `_never_call_real_ollama` fixture patches only module-level default runners, so a non-injectable subprocess call breaks suite hermeticity.
- `ollama_caps.py` — `auto_detect_model_info()` runs `ollama show` and maps `Capabilities` (e.g. `tools` → `supports_function_calling`); `ModelForm` calls it on add.
- Adding a provider: see the `adding-a-provider` skill (`.claude/skills/adding-a-provider/SKILL.md`).

### Provider lifecycle (`src/modelman/providers/lifecycle/`)

Isolate/stop/stop-all/restore for local providers (ported from bash, issue #79). `orchestrate.py` holds the operations; `backends/` has one backend per provider, registered in `backends/__init__.py`'s `BACKENDS`, with `SUPPORTED_PROVIDER_IDS` (`ollama`, `omlx`, `omlx-6bit`, `mlx_lm_server`, `mtplx`) excluding the retired-only `llamacpp`. mtplx and mlx_lm_server subclass `PidfileTrackedBackend` (`backends/base.py`); `pidproc.py`'s `PidfileProcess` is the spawn/stop/log-tail primitive; `probe.py`/`launchd.py`/`binaries.py` are shared primitives; `cli.py` is `modelman provider ...`. `src/modelman/local_process.py` is the neutral home for process/probe types shared with `benchmark/isolation.py` (living under either package would make the other's import backwards).

- `stop_all()`'s `keep` takes a **provider id** (like `isolate()`/`stop()`), resolved internally to its `occupancy_key` — `--keep omlx-6bit` keeps both omlx variants — and an unknown id returns `ok=False` before any teardown.
- **Testing pattern:** backend tests patch the name *as imported into the backend module* (`patch("modelman.providers.lifecycle.backends.mtplx.subprocess.run")`, `...backends.mtplx.probe.wait_for_port_closed`, `...backends.mtplx._PROC`), never the origin module — "patch where it's used" across the whole `lifecycle/` package. Distinct from the `Provider`-class `runner=` seam.

### Local-model lifecycle

`modelman start <id>` / `stop <id>` / `stop --all` and the TUI's `s` key are the sanctioned non-benchmark start/stop paths (`local_control.py`; design: `../docs/superpowers/specs/2026-09-14-local-model-lifecycle-design.md`). **Per-provider process limits:** multiple local models may run concurrently across providers (advisory only — nothing stop-alls on start). ollama is multi-tenant; omlx, mtplx and mlx_lm_server serve one model per process, so starting a different model on one of them replaces its current occupant. `omlx`/`omlx-6bit` are ONE occupancy domain (`_OMLX_PROVIDER_IDS`, shared port 8000). wt ignores the `running` flag and probes providers itself.

- **Start** (`start_local_model`): resolve the name — registry id, an existing model's native provider-side name, or a discovered artifact's native name (or its `<family>/<name>` id), started from an unsaved `_discovered_entry` WITHOUT registering it and with no family asked (`_resolve_local_model`, #179 Phase B; its flag is kept under the discovered id, which matches wt's — `running_model_ids` probes such a flag through `_flagged_target`, and `same_provider_occupant` counts it) → reject cloud models and providers outside `SUPPORTED_PROVIDER_IDS` → resolve launch args (mlx_lm_server pairing, mtplx model name, env vars) fail-fast *before any teardown* → if already flagged running, probe: serving ⇒ no-op, dead ⇒ clear and start. ollama is flag-only (lazy-loads on first request). Others find the same-provider occupant (`_same_provider_occupant`) and **clear its flag only after teardown is confirmed**: omlx calls `stop_provider()` first; mtplx/mlx_lm_server tear the occupant down inside `isolate_provider(..., solo=True)`, so the occupant's flag is cleared only after that call succeeds. `isolate_provider()` failure clears this model's flag and raises. Every start (including an already-running no-op) closes with one `wt litellm sync` — that call is what routes the model (#179), and it is also why an ollama start refuses up front when the daemon isn't answering (`_require_ollama_daemon`): wt reads a *refused* ollama probe as "nothing is pulled" and prunes every configured ollama route, the model just reported started included. Sync warnings ride on the result; they never fail the start.
- **Stop**: takes the flagged id — a registry id, or the discovered id of a model started without an entry (the provider is the id's prefix, so `omlx/<name>` stops the shared omlx server); no-op when the flag is false; ollama → `ollama stop <name>`, mtplx → `lifecycle.stop("mtplx")`, others → `stop_provider()`; then a locked flag clear and, after it and outside the lock, one `wt litellm sync` (wt probes the providers itself, so the process must already be gone). Routing is not sticky across stop/start: for a single-model provider the sync drops the stopped model's route (it must not stay routable to a dead backend), while a stopped **ollama** model keeps its route — wt's desired set counts a pulled model, not a loaded one, so a pulled model stays routable and lazy-loads. `stop_all_local_models()` is the only stop-everything path, with one sync for the lot. Sync warnings surface on `StopResult.warnings`/`StopAllResult.warnings` and never block.
- Subprocess calls run outside `locked_state`; only the short per-model flag writes take the lock.
- **Resolving and listing local models (#194).** `_resolve_local_model` tries, in order: a registry id; an **exact discovered id** (only when the typed text starts with a local family or row prefix — a bare name or a repo id like `mlx-community/Name` cannot be one and costs no provider listing; it is what the listing printed, so it beats the lenient name match that follows, which for omlx and mtplx compares name tails and would hand `mtplx/Org/Name` to a registered omlx `Name`); a registered model's native name (`_typed_name_matches`: lenient for omlx/mtplx, but **exact for ollama** — the name with or without the `ollama/` prefix and the implicit `:latest`, since a user namespace is part of an ollama name and `someuser/qwen3:8b` is not a registered `qwen3:8b`); a discovered artifact by name, where an artifact named exactly what was typed beats the tail matches (`qwen3:8b` is the pulled `qwen3:8b`, not ambiguous with `someuser/qwen3:8b`). A typed `<prefix>/…` whose prefix names a **local** family or row is a claim about where the model is and never starts another provider's artifact; a prefix that names a **cloud** provider is accepted only when the whole typed text is an artifact's name (`openai/whisper` pulled under ollama), never in front of a shorter one. Listings (`inventory_local_models`, `discover_unregistered_models`) go through `_listable`, which drops an artifact whose discovered id is already a registry model's id — it can be neither started nor routed, and the TUI's `+` row would register a duplicate id; `_find_discovered` keeps it so the start refusal can explain the clash. `OllamaProvider.list_local` skips `ollama list`'s cloud rows (SIZE `-`): nothing is on disk.
- **Ollama start checks the pull** (`_require_ollama_pulled`): the start is flag-only, so an unpulled registered model used to "start", read as running and get no route. It now fails with `<id> is not pulled — ollama pull <name>`, but only on a positive "not pulled": it reads `/api/tags` at the provider row's origin — the same server `_require_ollama_daemon` and wt's probe ask, parsed as wt does (`remote_host` entries are cloud models, implicit `:latest`) — never the local `ollama list` CLI, which describes a different server when `base_url` points elsewhere. A tags read with no usable listing is unknown and the start proceeds. `conftest.py` no-ops this check for the whole suite (it would otherwise GET the developer's real daemon); its own tests patch the real function back.
- **`modelman sync` writes only what it observed** (#231): `sync.reconcile` updates `ready`/`disk_path`/`size_bytes` on the existing row (`dataclasses.replace`), and the `sync` command merges just those three fields, for just the reconciled ids, onto the state as it is on disk when the scans finish — plus `running = false` for the ids in `SyncResult.running_cleared` (#233, an ollama model observed gone; see `running_flag_is_probed` under "Provider plugin system"). Rebuilding the row reset `running`, so every sync recorded every registered local model as stopped (`modelman stop` then said "is not running"); writing the pre-scan snapshot back whole also undid a start or stop made while sync ran and resurrected a discovered model's deleted row. Never construct a fresh `ModelState(...)` for an existing model, and never `update()` the on-disk store from an older snapshot.
- **Flag clears leave no empty state row** (`_clear_running_flag`, used by stop, `stop --all` and `_clear_stale_running_flag`): clearing a flag deletes the `[model_state."<id>"]` row when nothing else is left on it — a discovered model's row exists only for the flag. The TUI's `_resync_running_flags` therefore reads a row missing from disk as `running = false`.
- **Provider rows for installed tools** (`sync._ensure_provider_entries`, used by `modelman sync` and `modelman migrate`): a default local provider gets its row when a model references it **or its command is on PATH** (`_installed_local_providers`: ollama, omlx, mtplx; mlx_lm_server only by reference; an installed omlx adds no `omlx` row beside an existing `omlx-6bit` one — same server). There is deliberately no opt-out: a row deleted by hand for an installed tool comes back on the next sync (decided in the #194 review). This is what makes a fresh machine usable — `migrate` used to write `providers = []`. `conftest.py` stubs the PATH lookup to "none installed".
- **Probing** (`_probe_running`): omlx/omlx-6bit and mtplx match `/v1/models` ids lenient-prefix/strict-variant-tail — for omlx only after `_omlx_loaded` has cut the list down to what is loaded, because omlx lists its whole pool, loaded or not (wt#201): `/health`'s keyless pool counts say "none" or "all (and the list is the whole pool)", and anything else reads as not running, the safe direction (wt's `localmodels.ServedIDs` goes further and asks the key-protected status endpoint); mlx_lm_server needs only a non-empty `/v1/models` (its reported spelling need not match the registry). **ollama is exempt and always reads as running** — `ollama ps` lists only currently-LOADED models, so probing would self-clear a flag that was never wrong. `running_model_ids()` is the shared flag+probe read path; neither it nor `_clear_stale_running_flag()` touches routes (the TUI's mount reconcile syncs once per run that cleared a flag — see the ModelScreen invariants), and both stay wt-free so a plain read never shells out.
- **Discovery** (`modelman start` no-arg inventory, TUI `+` rows — registering one is a deliberate add-and-save step, never part of start): "is this *registered* model on disk?" uses the provider's `resolve_local()`/`is_downloaded()`/`size_of()` (`_registered_presence`); "what's on disk that isn't registered?" uses `list_local()` (`_provider_local_models`, gated on `supports_discovery`). A provider that can't be asked is named in a caveat line, never read as empty. A discovered artifact's id is `_discovered_id` — `<family>/<artifact>`, family-prefixed like wt's `config.DiscoveredModelID` (`ollama/<name:tag>`, `omlx/<dir basename>`, `mtplx/<org>/<name>` — mtplx keeps the `/`); the no-arg listing prints it with `(running)` when flagged and probe-confirmed. **`omlx-6bit` has no class of its own:** `ProviderRegistry` resolves it to omlx's (`providers/registry.py` `_ALIASES`, #194) wherever a class is looked up — discovery, reconcile, downloads, sync — and the instance is built from that row's own settings, so a registry whose only omlx-family row is `omlx-6bit` lists and starts an unregistered artifact as `omlx/<artifact>` (wt's id) through the `omlx-6bit` lifecycle backend. A row whose id names nothing modelman has code for is still unqueryable, never "reports nothing". **Two rows that resolve to the same class are one server, and anything keyed on a raw provider id is a place that can forget it** (`ProviderRegistry.resolve` is the comparison): the shared-artifact guard (`find_shared_artifact_owner`) checks entries on a sibling row too, each through its own row's settings, because the alias made `OMLXProvider.delete()` reachable for an `omlx-6bit` entry and that rmtree's a directory an `omlx` entry may own (#224); `modelman sync` picks model-directory rows and reconcilable entries by resolved class (`_is_modeldir_row`, and the same test in `reconcile`), where two fixed id lists used to skip `omlx-6bit` entries entirely (#225). The guard compares only what the deleting entry's `delete()` would really remove (`Provider.removable_paths`, default: all of `artifact_paths`) against everything the other entry lives in: omlx returns nothing for a `local_path` entry, whose delete is a no-op, so sharing a user-produced directory is not reported as a conflict (#227), while deleting a downloaded entry whose directory a `local_path` entry points at still is. mtplx does the same for its `local_path` entries. mlx_lm_server overrides it too, per side: only a target's or draft's repo-downloaded directory is removable, so two pairings sharing a `local_path` or `draft_local_path` directory are not a conflict. Its removable set is not a subset of its `artifact_paths` — a side carrying both a repo and a `local_path` (hand-edited; the forms reject it) removes the repo's downloaded directory, which `artifact_paths` does not list. The guard therefore compares the removable set as it stands, never its intersection with `artifact_paths`, so another entry living in that directory is still found (#229). When adding an alias or a new id-keyed gate, grep for `MODELDIR_PROVIDER_IDS`, `RECONCILABLE_PROVIDERS`, `DEFAULT_PROVIDER_IDS`, `SUPPORTED_PROVIDER_IDS` and `provider_id ==`/`in` tests.
- **TUI `s`** always confirms (`Stop <id>?`, or for a start that would replace a single-model provider's occupant, a dialog naming that occupant). `_lifecycle_worker_busy()` rejects a second `s` while a `model-start`/`model-stop` thread worker runs. Textual cannot cancel a thread worker, so a warmup can hold it for minutes.
- **Quit with workers running:** `ModelScreen.action_back()` (Escape and Ctrl+Q) checks `self.workers` for anything `is_running` (start/stop, reconcile, price refresh) and shows `ConfirmForceQuitDialog`. "Force quit" → `_force_quit()` restores the terminal then `os._exit(0)` — the only way out, since a normal exit hangs in `asyncio.run()`'s executor join and then `concurrent.futures.thread`'s untimed `atexit` join. Safe because `running` is a hint the next probe self-heals.
- **`ctrl+q` routing:** `ModelmanApp.request_quit()` (`app.py`) `isinstance`-checks the top screen (`ModelScreen` → `action_back()`, `ConfirmForceQuitDialog` → `dismiss(True)`, else `self.exit()`). `ctrl+q` is a priority `App` binding resolved before any modal's bindings, so **any new modal that can be topmost during quit needs its own branch in `request_quit()`**, or a second `ctrl+q` silently bypasses it.

### Usage/spend tracking

User guide: `../docs/guides/07-usage-and-spend.md`. `usage/` joins wt's `usage.jsonl` + `rotation.state` (`MODELMAN_WT_DIR`, default `~/.config/agent-wt`) with LiteLLM's `LiteLLM_SpendLogs`, read-only on both. Gotchas: `db.py::PostgresSpendStore` closes its connection explicitly (psycopg2's `with conn:` manages only the transaction); `database_url()` precedence is `MODELMAN_LITELLM_DATABASE_URL` → config.yaml `general_settings.database_url`, so the env var lets `usage report` run without a config file; `--model`/`--family` filters apply to every observed id, not just registry-known ones; malformed `usage.jsonl` lines are skipped.

## ModelForm parsing rules

`screens/forms.py::parse_model()` interprets the single `model` input per provider:

- **ollama**: tag verbatim (e.g. `ornith-1.5:35b`); slashes rejected.
- **llamacpp / omlx**: `org/repo` or `org/repo/file`; single-segment rejected.
- **native** (`provider_kinds[provider] == "native"`): verbatim; blank defaults to `native`.
- **cloud-only** (e.g. openrouter): stored whole, no repo/files split.

The model id is `provider/name` with `/` → `--` (native and mtplx keep the name as it is). `ModelScreen._variant_to_model_entry()` builds the `ModelEntry`. `parse_cost_fields()`/`parse_subscription_fields()` parse the two independent cost sections.

## Testing patterns

- TUI tests: `pytest-asyncio` (`asyncio_mode = "auto"`) with `ModelmanApp.run_test()` and `pilot.press(...)`. Focus the target `Input` explicitly before typing — Tab cycling is unreliable in tests.
- Provider tests inject `runner` (the `mock_runner` fixture in `tests/conftest.py`).
- CLI tests use `typer.testing.CliRunner` (`patch("modelman.main.run_tui")` for the TUI). Two layers per subcommand: orchestration helpers with `tmp_path` fixtures (`tests/test_litellm.py`, `tests/test_sync.py`), and wiring in `tests/commands/test_*.py` against env-redirected paths.
- Path redirects: `MODELMAN_REGISTRY`, `MODELMAN_STATE`, legacy `MODELMAN_CONFIG`/`MODELMAN_FAMILY_DIR` (migrate tests), `WT_LITELLM_CONFIG` > legacy `MODELMAN_LITELLM_CONFIG` (wt's precedence; `default_litellm_config_path()` — the usage reader, and `sync_routes` skips wt when that file is missing), `MODELMAN_LITELLM_DATABASE_URL`. Tests stub the wt bridge (conftest autouse guards) instead of writing config.yaml.
- **Run focused tests per change**, plus `make check`; run the full suite once when reviewing the whole change set.
- **Run `make check` before calling any task done**, not just the last: mypy flags things pytest can't (e.g. reusing a local name for two types across mutually exclusive early-return branches of one Typer command).
- **MagicMock provider stubs:** optional capabilities (`resolve_local`, `path_of`) auto-exist as truthy mocks — set `stub.resolve_local.return_value = None` (or a length-aligned list) when the code branches on them.
- **Ruff B905 is enforced:** `zip()` needs explicit `strict=`.
- **Formatting:** CI runs `ruff format --check` on `src/` and `tests/`; run `make format`. Scope any bare `ruff format` to `src/ tests/`. If it rewrites `except (A, B):` to `except A, B:` (known ruff bug), exclude the file via `[tool.ruff.format].extend-exclude`.
- In-function `from X import Y` in tests (e.g. `test_queue.py`) is intentional.
- `uv run`'s warning about an active pyenv `VIRTUAL_ENV` is expected; it uses the project `.venv`.
