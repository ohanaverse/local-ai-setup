# modelman local-model lifecycle: start, stop, probe, discover

Internals reference for `modelman/`, reached from [`modelman/CLAUDE.md`](../../CLAUDE.md). Backticked paths are relative to `modelman/` unless they start with `../`.

## Local-model lifecycle

`modelman start <id>` / `stop <id>` / `stop --all` and the TUI's `s` key are the sanctioned non-benchmark start/stop paths (`local_control.py`; design: `../docs/superpowers/specs/2026-09-14-local-model-lifecycle-design.md`). **Per-provider process limits:** multiple local models may run concurrently across providers (advisory only — nothing stop-alls on start). ollama is multi-tenant; omlx, mtplx and mlx_lm_server serve one model per process, so starting a different model on one of them replaces its current occupant. `omlx`/`omlx-6bit` are ONE occupancy domain (`_OMLX_PROVIDER_IDS`, shared port 8000). wt ignores the `running` flag and probes providers itself.

- **Start** (`start_local_model`): resolve the name — registry id, an existing model's native provider-side name, or a discovered artifact's native name (or its `<family>/<name>` id), started from an unsaved `_discovered_entry` WITHOUT registering it and with no family asked (`_resolve_local_model`, #179 Phase B; its flag is kept under the discovered id, which matches wt's — `running_model_ids` probes such a flag through `_flagged_target`, and `same_provider_occupant` counts it) → reject cloud models and providers outside `SUPPORTED_PROVIDER_IDS` → resolve launch args (mlx_lm_server pairing, mtplx model name, env vars) fail-fast *before any teardown* → if already flagged running, probe: serving ⇒ no-op, dead ⇒ clear and start. ollama is flag-only (lazy-loads on first request). Others find the same-provider occupant (`_same_provider_occupant`) and **clear its flag only after teardown is confirmed**: omlx calls `stop_provider()` first; mtplx/mlx_lm_server tear the occupant down inside `isolate_provider(..., solo=True)`, so the occupant's flag is cleared only after that call succeeds. `isolate_provider()` failure clears this model's flag and raises. Every start (including an already-running no-op) closes with one `wt litellm sync` — that call is what routes the model (#179), and it is also why an ollama start refuses up front when the daemon isn't answering (`_require_ollama_daemon`): wt reads a *refused* ollama probe as "nothing is pulled" and prunes every configured ollama route, the model just reported started included. Sync warnings ride on the result; they never fail the start.
- **Stop**: takes the flagged id — a registry id, or the discovered id of a model started without an entry (the provider is the id's prefix, so `omlx/<name>` stops the shared omlx server); no-op when the flag is false; ollama → `ollama stop <name>`, mtplx → `lifecycle.stop("mtplx")`, others → `stop_provider()`; then a locked flag clear and, after it and outside the lock, one `wt litellm sync` (wt probes the providers itself, so the process must already be gone). Routing is not sticky across stop/start: for a single-model provider the sync drops the stopped model's route (it must not stay routable to a dead backend), while a stopped **ollama** model keeps its route — wt's desired set counts a pulled model, not a loaded one, so a pulled model stays routable and lazy-loads. `stop_all_local_models()` is the only stop-everything path, with one sync for the lot. Sync warnings surface on `StopResult.warnings`/`StopAllResult.warnings` and never block.
- Subprocess calls run outside `locked_state`; only the short per-model flag writes take the lock.
- **Resolving and listing local models (#194).** `_resolve_local_model` tries, in order: a registry id; an **exact discovered id** (only when the typed text starts with a local family or row prefix — a bare name or a repo id like `mlx-community/Name` cannot be one and costs no provider listing; it is what the listing printed, so it beats the lenient name match that follows, which for omlx and mtplx compares name tails and would hand `mtplx/Org/Name` to a registered omlx `Name`); a registered model's native name (`_typed_name_matches`: lenient for omlx/mtplx, but **exact for ollama** — the name with or without the `ollama/` prefix and the implicit `:latest`, since a user namespace is part of an ollama name and `someuser/qwen3:8b` is not a registered `qwen3:8b`); a discovered artifact by name, where an artifact named exactly what was typed beats the tail matches (`qwen3:8b` is the pulled `qwen3:8b`, not ambiguous with `someuser/qwen3:8b`). A typed `<prefix>/…` whose prefix names a **local** family or row is a claim about where the model is and never starts another provider's artifact; a prefix that names a **cloud** provider is accepted only when the whole typed text is an artifact's name (`openai/whisper` pulled under ollama), never in front of a shorter one. Listings (`inventory_local_models`, `discover_unregistered_models`) go through `_listable`, which drops an artifact whose discovered id is already a registry model's id — it can be neither started nor routed, and the TUI's `+` row would register a duplicate id; `_find_discovered` keeps it so the start refusal can explain the clash. `OllamaProvider.list_local` skips `ollama list`'s cloud rows (SIZE `-`): nothing is on disk.
- **Ollama start checks the pull** (`_require_ollama_pulled`): the start is flag-only, so an unpulled registered model used to "start", read as running and get no route. It now fails with `<id> is not pulled — ollama pull <name>`, but only on a positive "not pulled": it reads `/api/tags` at the provider row's origin — the same server `_require_ollama_daemon` and wt's probe ask, parsed as wt does (`remote_host` entries are cloud models, implicit `:latest`) — never the local `ollama list` CLI, which describes a different server when `base_url` points elsewhere. A tags read with no usable listing is unknown and the start proceeds. `conftest.py` no-ops this check for the whole suite (it would otherwise GET the developer's real daemon); its own tests patch the real function back.
- **`modelman sync` writes only what it observed** (#231): `sync.reconcile` updates `ready`/`disk_path`/`size_bytes` on the existing row (`dataclasses.replace`), and the `sync` command merges just those three fields, for just the reconciled ids, onto the state as it is on disk when the scans finish. `running` is never written from the snapshot: the command ends by re-probing every flagged model with `running_model_ids()` (as the TUI's mount does), which clears a flag only on a probe made at that moment against the state it re-reads under the lock (#243), and reports `No longer running, marked stopped: …`. Rebuilding the row reset `running`, so every sync recorded every registered local model as stopped (`modelman stop` then said "is not running"); writing the pre-scan snapshot back whole also undid a start or stop made while sync ran and resurrected a discovered model's deleted row. Never construct a fresh `ModelState(...)` for an existing model, and never `update()` the on-disk store from an older snapshot.
- **Flag clears leave no empty state row** (`_clear_running_flag`, used by stop, `stop --all` and `_clear_stale_running_flag`): clearing a flag deletes the `[model_state."<id>"]` row when nothing else is left on it — a discovered model's row exists only for the flag. The TUI's `_resync_running_flags` therefore reads a row missing from disk as `running = false`.
- **Provider rows for installed tools** (`sync._ensure_provider_entries`, used by `modelman sync` and `modelman migrate`): a default local provider gets its row when a model references it **or its command is on PATH** (`_installed_local_providers`: ollama, omlx, mtplx; mlx_lm_server only by reference; an installed omlx adds no `omlx` row beside an existing `omlx-6bit` one — same server). There is deliberately no opt-out: a row deleted by hand for an installed tool comes back on the next sync (decided in the #194 review). This is what makes a fresh machine usable — `migrate` used to write `providers = []`. `conftest.py` stubs the PATH lookup to "none installed".
- **Probing** (`_probe_running`): omlx/omlx-6bit and mtplx match `/v1/models` ids lenient-prefix/strict-variant-tail — for omlx only after `_omlx_loaded` has cut the list down to what is loaded, because omlx lists its whole pool, loaded or not (wt#201): `/health`'s keyless pool counts say "none" or "all (and the list is the whole pool)", and anything else reads as not running, the safe direction (wt's `localmodels.ServedIDs` goes further and asks the key-protected status endpoint); mlx_lm_server needs only a non-empty `/v1/models` (its reported spelling need not match the registry). **For ollama the probe asks "still pulled?", never "loaded?"** (#242) — `ollama ps` lists only currently-LOADED models, so asking that would self-clear the flag of a model started and not yet requested. `_ollama_pulled` reads `/api/tags` at the provider row's origin (the same read `_require_ollama_pulled` makes, so a remote `base_url` is asked at the right server) and only a listing that positively lacks the model reads as not running; a daemon that is down or unreadable is unknown and stays running. That is what clears the flag of a model removed with `ollama rm`, registered or discovered (#233). It costs one local HTTP read per flagged ollama model per `running_model_ids()` call. `running_model_ids()` is the shared flag+probe read path; neither it nor `_clear_stale_running_flag()` touches routes (the TUI's mount reconcile syncs once per run that cleared a flag — see the ModelScreen invariants), and both stay wt-free so a plain read never shells out.
- **Discovery** (`modelman start` no-arg inventory, TUI `+` rows — registering one is a deliberate add-and-save step, never part of start): "is this *registered* model on disk?" uses the provider's `resolve_local()`/`is_downloaded()`/`size_of()` (`_registered_presence`); "what's on disk that isn't registered?" uses `list_local()` (`_provider_local_models`, gated on `supports_discovery`). A provider that can't be asked is named in a caveat line, never read as empty. A discovered artifact's id is `_discovered_id` — `<family>/<artifact>`, family-prefixed like wt's `config.DiscoveredModelID` (`ollama/<name:tag>`, `omlx/<dir basename>`, `mtplx/<org>/<name>` — mtplx keeps the `/`); the no-arg listing prints it with `(running)` when flagged and probe-confirmed. **`omlx-6bit` has no class of its own:** `ProviderRegistry` resolves it to omlx's (`providers/registry.py` `_ALIASES`, #194) wherever a class is looked up — discovery, reconcile, downloads, sync — and the instance is built from that row's own settings, so a registry whose only omlx-family row is `omlx-6bit` lists and starts an unregistered artifact as `omlx/<artifact>` (wt's id) through the `omlx-6bit` lifecycle backend. A row whose id names nothing modelman has code for is still unqueryable, never "reports nothing". **Two rows that resolve to the same class are one server, and anything keyed on a raw provider id is a place that can forget it** (`ProviderRegistry.resolve` is the comparison): the shared-artifact guard (`find_shared_artifact_owner`) checks entries on a sibling row too, each through its own row's settings (since #241 it does so for every row, so it no longer needs `resolve` to find the siblings), because the alias made `OMLXProvider.delete()` reachable for an `omlx-6bit` entry and that rmtree's a directory an `omlx` entry may own (#224); `modelman sync` picks model-directory rows and reconcilable entries by resolved class (`_is_modeldir_row`, and the same test in `reconcile`), where two fixed id lists used to skip `omlx-6bit` entries entirely (#225). The guard compares only what the deleting entry's `delete()` would really remove (`Provider.removable_paths`, default: all of `artifact_paths`) against everything the other entry lives in: omlx returns nothing for a `local_path` entry, whose delete is a no-op, so sharing a user-produced directory is not reported as a conflict (#227), while deleting a downloaded entry whose directory a `local_path` entry points at still is. mtplx does the same for its `local_path` entries. mlx_lm_server overrides it too, per side: only a target's or draft's repo-downloaded directory is removable, so two pairings sharing a `local_path` or `draft_local_path` directory are not a conflict. Its removable set is not a subset of its `artifact_paths` — a side carrying both a repo and a `local_path` (hand-edited; the forms reject it) removes the repo's downloaded directory, which `artifact_paths` does not list. The guard therefore compares the removable set as it stands, never its intersection with `artifact_paths`, so another entry living in that directory is still found (#229). The one repo-downloaded directory it keeps is one whose removal would take the pairing's own `local_path` or `draft_local_path` with it — the same directory, one inside it, or a parent, on either side (`_removable_dirs`, the same `paths_overlap` test): the guard skips an entry's own id, so the provider has to refuse that itself (#241). When adding an alias or a new id-keyed gate, grep for `MODELDIR_PROVIDER_IDS`, `RECONCILABLE_PROVIDERS`, `DEFAULT_PROVIDER_IDS`, `SUPPORTED_PROVIDER_IDS` and `provider_id ==`/`in` tests.
- **TUI `s`** always confirms (`Stop <id>?`, or for a start that would replace a single-model provider's occupant, a dialog naming that occupant). `_lifecycle_worker_busy()` rejects a second `s` while a `model-start`/`model-stop` thread worker runs. Textual cannot cancel a thread worker, so a warmup can hold it for minutes.
- **Quit with workers running:** `ModelScreen.action_back()` (Escape and Ctrl+Q) checks `self.workers` for anything `is_running` (start/stop, reconcile, price refresh) and shows `ConfirmForceQuitDialog`. "Force quit" → `_force_quit()` restores the terminal then `os._exit(0)` — the only way out, since a normal exit hangs in `asyncio.run()`'s executor join and then `concurrent.futures.thread`'s untimed `atexit` join. Safe because `running` is a hint the next probe self-heals.
- **`ctrl+q` routing:** `ModelmanApp.request_quit()` (`app.py`) `isinstance`-checks the top screen (`ModelScreen` → `action_back()`, `ConfirmForceQuitDialog` → `dismiss(True)`, else `self.exit()`). `ctrl+q` is a priority `App` binding resolved before any modal's bindings, so **any new modal that can be topmost during quit needs its own branch in `request_quit()`**, or a second `ctrl+q` silently bypasses it.
