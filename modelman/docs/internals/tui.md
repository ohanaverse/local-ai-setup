# modelman TUI: screens, worker threads, ModelForm

Internals reference for `modelman/`, reached from [`modelman/CLAUDE.md`](../../CLAUDE.md). Backticked paths are relative to `modelman/` unless they start with `../`.

## Textual TUI

- `app.py` — `ModelmanApp(App[QueuedOps | None])`; `on_mount` pushes one registry-backed `ModelScreen` as the only screen (FamilyScreen is gone). Also runs a daily-gated OpenRouter price-refresh worker. Only a missing `registry.toml` (`RegistryNotFoundError`) opens as an empty registry; any other load failure sets `registry_error`, exits with nothing mounted, and `run_tui` reports it and exits 1 (#240) — a caller that will save must never treat an unreadable registry as empty (`migrate` and `usage` follow the same rule through `registry.unreadable_registry_message`).
- `screens/__init__.py` — `reload_preserving_cursor(table, repopulate)` restores the cursor onto the same row key after `DataTable.clear()` (falls back to row 0 if the key vanished). `reconcile_model_state(models, registry, state, local_map)` is the reconcile write-path: per provider it tries `resolve_local()` (batch; ollama uses one `ollama list`) and falls back to per-model `is_downloaded()`/`size_of()`; a misaligned/failed batch result degrades to the per-model path. No hard-coded provider ids — batch support is a provider capability. For local-artifact models (`registry.model_has_local_artifact`) it writes `ready`/`disk_path`/`size_bytes`; for cloud models `ready` is left alone. A known `disk_path` is kept unless a fresh one is observed.
- `screens/models.py` — `ModelScreen`. Holds `queued_ready`/`queued_deletes`/`queued_moves`; there is no queued-expose and no exposure column — modelman stopped having an `exposed` flag in #179. Columns: FAMILY · PROVIDER · MODEL · LOC · STATUS · RUNNING · COST · SIZE. Invariants worth knowing before touching it:
  - **Routing is invisible here, and maintained elsewhere.** No column reports whether LiteLLM routes a row — `wt litellm list` is the answer. Routing stays current because a *sync* follows the state change: `_sync_routes_and_warn()` (main.py) runs one `wt litellm sync` at the end of every queue apply (success *and* its unexpected-exception path; not after Ctrl+C, which is a clean stop — the next sync converges), after `migrate`/`sync`/`refresh-prices`, and on a TUI exit whose `registry.toml` changed. `_run_reconcile` runs one too, **but only when it cleared a stale `running` flag** — that model's route would otherwise point at a dead backend, and nothing else would drop it (the flag lives in `modelman.toml`, which the TUI-exit gate reads past). Gating on `stale_ids` keeps an ordinary mount — the common case — from bouncing the proxy.
  - **RUNNING** renders `●` for a local model whose `state.running` flag is set. The on-mount reconcile worker (`_run_reconcile`) also calls `running_model_ids()`, which probes and clears stale flags, so after mount the column shows verified state.
  - `r` is a true file-presence toggle: ready-off queues artifact removal (provider `delete()`, or `state.disk_path` for flag-only providers); pressing it again cancels the queued flip.
  - `s` start/stop — see "Local-model lifecycle".
  - Discovered-but-unregistered artifacts (`discover_unregistered_models()`, run alongside the on-mount reconcile) render as synthetic `[cyan]+[/cyan]` rows outside the STATUS glyph priority chain (they have no id to queue against, so `r`/`s`/`d` do nothing on one); RUNNING shows `●` when the artifact is flagged running under its discovered id (`DiscoveredModel.model_id`); `enter`/`e` on one opens a pre-filled `ModelForm` with Provider/Model locked — the explicit way to give it an overlay. The `+`-row form (`_submit_discovered`) registers the artifact under its discovered id itself (`DiscoveredModel.model_id`, #194) — the id wt already routes and keeps history for — so a running one's flag is already on the row the registration writes (`_on_register_discovered`); the provider row the artifact was found through stays the entry's `provider_id` (`omlx-6bit` under an `omlx/…` id). The `a` add form spells `/` as `--` in its generic branch (omlx repo names, retired llamacpp, and cloud providers alike, e.g. `openrouter/z-ai--<name>`); its mtplx branch keeps the slash, so an mtplx overlay added with `a` is `mtplx/org/name` — matching its discovered id. For omlx-6bit, the generic branch produces `omlx-6bit/org--name` while the discovered id uses the family prefix `omlx/org/name`.
  - `_provider_list()` derives from `registry.providers` (sorted).
- `screens/forms.py` — `ConfirmModal`, `ModelForm`, `ConfirmExitDialog`, `ConfirmForceQuitDialog`, all on a shared `ModelmanModal` base (buttons left-to-right with cancel rightmost, priority-bound `escape` that cancels even inside an `Input`, `_focus_button(id)` for safe-default focus on destructive prompts). Family Select is display-only in edit mode (issue #52; id/provider/location/family immutable); in add mode its `NEW_FAMILY_VALUE` sentinel ("+ New family…") reveals `#new-family-input`, resolved by `_resolve_family()`.

## Thread safety in worker threads

`self.app` is safe to call directly from a `@work(thread=True)` worker (e.g. `ModelScreen._run_reconcile`) **while the widget is mounted** — no captured reference is needed, and none exists. Textual resolves `Widget.app` two ways: the `active_app` contextvar, which is genuinely *unset* on a worker thread, and a fallback that walks `self._parent` up to the `App`. That walk is thread-agnostic, so it is what actually answers in a worker. (Verified on textual 8.2.8: `active_app.get()` raises `LookupError` inside the worker, and `self.app` still returns the `App`.)

`self._app_ref` was real once but is gone. #85 (commit `ddceb69`) removed the capture along with its only two readers, and they were two different cases — which is why the note above is the rule and not a blanket ban:

- `_run_apply`'s download-status snapshot ran on `StatusScreen`'s worker thread while `ModelScreen` sat on the stack underneath it: **mounted**, so `self.app` would have worked. Its comment justified the capture with "`Screen.app` raises `NoActiveAppError` when accessed off the main thread"; that diagnosis was wrong — it is the unmounted case, not the threaded one.
- `_register_deferred_expose`'s closure (removed by #85 too; nothing like it exists in `src/` today) was the genuine case: it fired when the download finished, possibly long after `ModelScreen` was gone. Its shape is still the one to copy for any such deferred callback — it captured `registry_path`/`state_path` up front and re-loaded fresh registry/state at run time rather than touching `self`, keeping the app reference solely to post the notification.

Don't reintroduce the capture for the first case.

The one way `self.app` fails is an **unmounted** widget: with no path to an `App`, the walk ends at `None` and `Widget.app` raises `NoActiveAppError` (a detached `Static("x").app` raises it too, in any thread). So a worker that outlives its screen must carry the data it needs — paths, ids — and re-load state rather than reach back through the widget, or finish before the screen is popped. `ModelScreen` sidesteps the whole question: it is the app's only root screen and stays mounted for the app's lifetime, even though its workers are the ones that can run for minutes (a warmup). That is why `action_back()` checks `self.workers` for anything still running and raises `ConfirmForceQuitDialog`.

## ModelForm parsing rules

`screens/forms.py::parse_model()` interprets the single `model` input per provider:

- **ollama**: tag verbatim (e.g. `ornith-1.5:35b`); slashes rejected.
- **llamacpp / omlx**: `org/repo` or `org/repo/file`; single-segment rejected.
- **native** (`provider_kinds[provider] == "native"`): verbatim; blank defaults to `native`.
- **cloud-only** (e.g. openrouter): stored whole, no repo/files split.

The model id is `provider/name` with `/` → `--` (native and mtplx keep the name as it is). `ModelScreen._variant_to_model_entry()` builds the `ModelEntry`. `parse_cost_fields()`/`parse_subscription_fields()` parse the two independent cost sections.
