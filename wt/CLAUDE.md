Rules and gotchas live here; mechanisms, function lists and step-by-step detail live in [docs/internals/](docs/internals/) (each section names its page; [packages.md](docs/internals/packages.md) lists every file and package).

## What this repo is

The `wt` binary (`cmd/wt/`) launches an AI coding agent CLI (claude, codex, copilot, pi, agy, opencode) or a shell command in a chosen worktree, branch, and model. Three launch inputs:

1. **Where** — `--root` (the primary checkout, from anywhere), `--cwd` (the current directory; no git repository needed), `-W <name>` (named worktree; a new name is created and said so, `--new` is a no-op), or the worktree picker (internal/cleanup's rows: the root, the default branch and held rows included, each launchable). Outside a repository `-W` refuses (`not in a git repo`).
2. **What** — `-A <name>`: an LLM agent, or `shell` for a plain command. **Never defaulted**: omitting `-A` always shows the agent/command picker.
3. **Which model** — `-M <provider>/<name>`, filtered by `-T <tags>` / `-F <family>`, or picked (eligible models rotate on successive launches).

`bin/*-wt` are shims that forward to `wt` (`claude-wt` → `wt --agent claude`), so `wt` must be on `$PATH`. All logic lives in Go.

## Installation

`make install` builds `bin/wt` and copies it and the shims to `~/.local/bin/` (Go 1.26.7, see `go.mod`; `make help` lists targets). `make test` needs `make install` first — it exercises the installed binary.

> **macOS codesign.** `make build`/`install` re-seal the ad-hoc signature (`codesign --force --sign -`); a drifted one is rejected by AMFI ("Taskgated Invalid Signature") and SIGKILLs the binary (exit 137).

## Key flags

Any combination of `-W`, `-A`, `-M`, `-T`, `-F` is valid; missing flags come from pickers or defaults. The agent is never defaulted.

| Flag | Effect |
|---|---|
| `-W <name>`, `--worktree <name>` | Use the worktree for `<name>`; skip the worktree picker. An existing worktree is reused with no question of its own (one `launching in …` line when nothing warns). A name that creates anything is announced first by its creation line, one shape per case: `creating branch <b> and worktree <p>` (a new branch), `creating worktree <p> for branch <b>` (a worktree for an existing branch), `creating worktree <p> for branch <b> tracking <r>` (a local branch tracking a remote-tracking name). The one launch question is asked before it only when a warning also applies (on a terminal). The root's own branch names the root and launches there with the root warning |
| `--new` | Accepted and ignored: a name that matches nothing is created and said so either way (kept for old scripts). A usage error without `-W` or with `--cwd`/`--root`. The picker's "+ New worktree…" prompt never asks |
| `-A <name>`, `--agent <name>` | Pin the agent or `shell`; never defaulted |
| `-M <id>`, `--model <id>` | Pin model as `<provider>/<name>`: cloud or running → launch; a non-running local starts; a blocked model errors with that row's reason. Without `-A`, the agent is prompted first. `-M profile/<name>` pins a slot profile |
| `--replace` | With `-M`, start the model even if it means stopping a running one (same provider only) |
| `--others=keep\|stop` | Answer without asking when a start loads a model beside other providers' models (picker: `-M` row only). Unset: ask; with no TTY keep them and warn once (#412) |
| `-T <tags>`, `--tags <tags>` | Filter models by tag (comma-delimited, OR) |
| `-F <family>`, `--family <family>` | Filter models by family (comma-delimited, OR) |
| `--root` | Launch in the repository's primary checkout, found from anywhere (a linked worktree or subdirectory too); the flag consents to the root warning, which is then not shown (any other warning still asks). Exclusive with `--cwd` and `-W`; refuses outside a repository and in a bare one |
| `--cwd` | Launch in the current directory, repository or not. Standing in the repository root it warns and proceeds, terminal or not (a terminal with any warning is asked the one launch question first). Takes no value: a first argument before `--` naming an existing directory is refused (#392) unless `shell`'s first word is a bare name on `$PATH` |
| `--yolo` | Prepend the agent's skip-permissions flag |
| `--init` / `--check-guard` / `--no-guard` | Seed AGENTS.md + pointer files then exit / check / remove the `block-main-commit` guard |

## Passthrough args

Extra args forward to the launched agent; `--` is required when any argument begins with a dash. Agents append them to the command; `shell` (`ArgSetter`) takes them as argv (`d.args[0]` = binary).

```bash
claude-wt -W feat -- --verbose  # → claude --model X --verbose
shell-wt -W test -- npm test    # → exec npm test in .worktrees/test
```

## Post-exit flow

After the launched subprocess exits, the TUI and non-TUI paths run the same fixed sequence — [docs/wt-agents/README.md#post-exit-order](docs/wt-agents/README.md#post-exit-order). Change both paths together.

- `survey.ReleaseSession()` runs before the stop picker; the summary line (`agents.Summary`) never affects the exit code.
- **wt exits with the agent's status on both paths, after the whole tail** (#412): non-TUI `os.Exit(ee.ExitCode())`; TUI `tui.Run` returns the error and `runTUI` makes an `exitCodeError`. **Never `os.Exit` inside `internal/tui`.**
- A batch of stops costs one LiteLLM restart and one ollama wait (#379, #142); a stop ollama accepted and still lists at the bound is `*lifecycle.StillFinishingError`, not a failure.
- A slot-profile session's tail is release → stop picker → summary (no survey, no price notice).
- **There is no post-exit prompt.** `internal/exitprompt` (its `Offer`) is **deleted** (Task 304): nothing is asked when the agent exits and an untouched session worktree is never offered for removal — cleanup is user-driven (`wt worktrees`, `wt remove`). The agent's exit status (above) is the tail's only outcome. A `[launch] exit_prompt` key is tolerated and ignored (`config.LaunchState` round-trips it; no value is validated or consulted) and a non-empty value prints one note per process: `wt: note: config.toml: [launch] exit_prompt is no longer used and is ignored`.

Read [docs/internals/launch-flow.md](docs/internals/launch-flow.md) before changing the summary line, the stop picker, the stale-pricing notice, the survey, session handling, or profiles.

## Go tests

Every `Test*` has a top-level `//` comment stating **what** it tests and **why** it matters.

- **Test seams are per-call values, not package globals** — pass hooks and inputs where the call happens (`rootmove.Engine.Hooks`, `cleanup.GatherInputs.PRList`/`PRBaseList`, `internal/lifecycle`'s `env` struct), so parallel tests cannot leak stub state into each other. A package-var seam (`var x = realX`, swapped and restored around the test) is the migrating exception, not the rule: convert it to per-call when you touch its package.
- **Tests stay off the developer's machine**: each package's `TestMain` isolates what it reaches — `lifecycle.IsolateProcessesForTest()` (every process family's pidfile, signals, the wired-limit read), `tiers.IsolateForTest` (model-table packages), `config.IsolateConfigHomeForTest` (anything reaching `config.Dir()`), `gitenv.IsolateForTest()` (anything that can run git; `TestEveryPackageThatRunsGitIsolatesIt`). A new package or launch path needs the same (route check via `stubEnsureRoute(t)`); no test runs `psql`; scratch registries go through `WT_REGISTRY`.
- **Assert on unexported functions directly**; parsing rendered lipgloss output flakes under forced-color ANSI.
- **A test that creates worktrees builds a fresh repo per case** (`t.TempDir()` + `gitInit`): one wrong success leaves `.worktrees/<name>`, and the path-collision error then masks every later case. Use a branch name like `topic`, not `feature`, when a case also needs `feature/<x>` (git forbids a ref that is both a leaf and a directory).
- **A test that depends on filesystem case-sensitivity probes and skips** (write `CaseProbe`, stat `caseprobe`), and asserts on `git for-each-ref` output, never `refExists`: on a case-insensitive volume `show-ref` resolves `Feature/x` through `feature/x`'s ref file and says yes.
- **A test's `WarmupSeconds` must outlast the helper server's first answer.** Each warmup request is capped at the time left in the window, so a 1 s budget on a loaded runner fails on the deadline, not on the response you meant to assert on. Use 3 s or more.

Read [docs/internals/testing.md](docs/internals/testing.md) before adding a seam, a `TestMain`, or a test that launches, runs git, starts a model, or touches routes.

```bash
go test ./...
go test ./internal/agents -run TestOpenCodeOllamaPrefix   # one test
go vet ./...
make check   # shellcheck, shfmt, gofmt -l (wt-ci's gate); `make format` writes both
make -C .. test-all   # CI-equivalent: root lint + llmbench + modeltiers + wt
```

## Config (Go)

`~/.config/agent-wt/config.toml` is wt-owned and holds **only Agents, DefaultTag, the `[litellm]` table and the `[launch]` table** (`config.LaunchState`; its `exit_prompt` key is tolerated and ignored — parsed and round-tripped by a save, validated and consulted by nothing, and a non-empty value prints one note per process: `wt: note: config.toml: [launch] exit_prompt is no longer used and is ignored`); Providers/Models live in the registry and this file's write path never touches them.

- **Writers go through `(*Config).PatchSave` or `lockedApply`** (flock, re-read fresh, mutate only their own fields); `Save(cfg)` only for a known-fresh `Config`. **Any read-modify-write of a wt-owned file flocks via `config.WithFileLock`** — the one helper (`WithLock` for config.toml, `UpdateRegistry` for registry.toml, `slotedit.Apply` for slot-profiles.toml); a new write path without it can silently lose a concurrent edit.
- `wt config` launches even when `config.toml` fails validation, so the editor can repair it.

Read [docs/internals/config-and-registry.md](docs/internals/config-and-registry.md) before changing config load/save, migrations, the `[litellm]` table, registry loading, catalog membership, or location validation.

## LiteLLM routing state (wt-owned)

The `[litellm]` table (`enabled`/`url`/`api_key`) decides whether non-native models route through the proxy (`Config.IsLitellm()`); set with `wt litellm status|on|off|set`, read nowhere else, routing policy only (never touches the proxy): [docs/internals/config-and-registry.md](docs/internals/config-and-registry.md#litellm-routing-state-wt-owned).

## Registry

`~/.config/local-ai/registry.toml` holds the canonical Providers/Models. `config.Load` reads it fail-closed and never writes it; wt writes it through `config.UpdateRegistry` alone. Path precedence: `WT_REGISTRY` > `MODELMAN_REGISTRY` (legacy alias) > `XDG_CONFIG_HOME` > `~/.config`; llmbench's `registry_path` uses the same order — keep the two in sync (each has a precedence test).

- **`ResolveLocation` is the one judge of a location** (`config.ErrLocation`).
- **On-disk and running state come from live probes**; no per-model state key exists, and whether a model is routed is `wt litellm list`.
- **`config.UpdateRegistry` is the only write path**; its `apply` must be pure (it may run up to three times). `RegistryDoc` operations are patch-shaped — never round-trip a `config.Model` into the file.
- **An id on more than one model row is refused, never resolved to the first row** (`config.ErrModelAmbiguous`); find a row through `RegistryDoc.Model`/`PatchModel`/`RemoveModel`.
- **A malformed `fetch`/`draft` or `cost.time_prices` row reads as absent and never fails the load** (`Model.Malformed()`). Get a zone through `config.loadZone`, not `time.LoadLocation`.
- **`serve_args` is mtplx-only extra argv, one value judge** (#432): `provider.FamilySpec.ServeArgs` says which family takes it, `config.ServeArgsProblems` is the one judge (the loader's `Model.Malformed()`, the writer's `validateModelRow`, `wt model add|edit`, and `lifecycle.serveArgsFor` at a start, which stops with `*ServeArgsError` before spawning), and `provider.ProcessSpec.SpawnArgs`/`OwnedFlags` build the argv and derive the refused flags from the spec. A malformed value reads as absent and never fails the load. A change applies from the next start (wt cannot see a running server's flags). It is not in `docs/contracts/model-list.sample.json` (an omitempty key, like `target`/`draft`; `TestModelListJSONOutputMatchesTheFixture` exercises it) and llmbench ignores it.
- **`llamacpp` is still a provider row** (`internal/provider/table.go`) — retired as a *backend* on 2026-09-07 (no LaunchAgent, no llmbench backend) but never removed from the table, so a registry model naming that provider still resolves. It has no `Seed`, so it is never created automatically; `docs/reference/provider-artifacts.md` has the retirement record.
- **Read-side schemas are pinned by contract fixtures** in `../docs/contracts/`: a key added to or renamed in `modelListJSON`/`modelListRow` (`cmd/wt/model_list.go`) fails `cmd/wt/model_list_contract_test.go` until `model-list.sample.json` has it (modeltiers reads that document as its whole inventory).
- A missing registry lets an *unconfigured* agent launch as a native passthrough (`agents.BuildPassthroughCmd`); a configured one fails on model resolution.

> **`unknown provider "X"` errors are usually a registry data gap, not a wt bug.** Fix with `wt model init` on that machine (a provider it has no default row for is named in its output: a hand edit of `registry.toml`), not a code change here.

> **Fixture gotcha.** `config.toml` lives in `$XDG_CONFIG_HOME/agent-wt/`, `registry.toml` in `$XDG_CONFIG_HOME/local-ai/` — fixtures populate both. LiteLLM's `config.yaml` follows neither, so a fixture that redirects the registry also names it (`WT_LITELLM_CONFIG` or `litellm.Options.Path`), or route writes refuse with `litellm.ErrRegistryRedirected`. `migrateConfigSchema` always ensures an `agy` agent, so a registry fixture with agents needs an `agy` provider or `Load` fails with `unknown provider "agy"`.

Full rules: [docs/internals/config-and-registry.md](docs/internals/config-and-registry.md#registry). Adding a provider: the `adding-a-provider` skill.

## Local-model resolution

Every model row wt shows or resolves is built by `internal/catalog` from the agent's eligible list plus one live `localmodels.Inventory` snapshot (no stored flag). A row's action is **launch** (cloud, or local and running), **start** (local ollama/omlx/omlx-6bit/mtplx/rec/sushi, not running or still loading) or **block**.

- **`config.Provider.Origin` is the one reading of a provider's address** (#348): probes, routes, direct routes and pi's `models.json` all use it, and so must any new reader. A test never binds or dials the mtplx default port 8003.
- **`localmodels.ServedIDs` is the one answer to "what is this server serving"** (#201).
- A `-M` pin is looked up among all rows (`catalog.Find`, else `catalog.MissingReason`); without `-M`, the non-TUI path picks only launch rows — only a pin may start a model.
- **A slot-profile row is not a model row** (`Model` holds only `profile/<name>`, `Row.Profile` the rest): test `r.Profile != nil` before reading any other `Model` field, calling `ResolveRoute`, or launching/starting `Model`.

Read [docs/internals/local-models.md](docs/internals/local-models.md) before changing row policy, the inventory probes, omlx loaded-state detection, pin resolution, rotation, or `wt start`/`wt stop`.

## Lifecycle (`internal/lifecycle`)

The start/stop engine (`Start`, `Stop`, `BeginStops` + `SettleRoutes`); backends ollama (`Shared`), omlx (`Pool`), every process-server family (mtplx, rec and sushi, `Exclusive`; one spec-driven `processServer` backend, a `Process` row in `internal/provider/table.go`). rec is `ScopeMachine` (one instance per machine, found through `rec status`) and `ServedOnly` (no artifacts: only its registered `rec/flint` is listed). sushi is `ScopePort` and `ServedOnly`: one model-less `sushi serve` on port 12345 that loads the pack on the first request naming it, so wt lists no artifacts for it either.

- **Anything that displaces a model needs `AllowReplace`** (`*OccupiedError`); unknown occupancy is `*OccupancyUnknownError`, never assumed empty. Other providers' models beside the target need `Options.Others` (#412); `--replace` never answers it.
- **A start/stop wt performs updates `config.yaml`** through `internal/litellm` (route hook); `lifecycle.EnsureModelRoute` (#192) never fails a launch, a slot-profile launch uses the failing `profile_routes.go` calls.
- **Call `WaitPendingRoutes()` on every process exit and before handing a model to an agent**: the `config.yaml` write is synchronous, the proxy restart and readiness wait are async. The restart goroutine runs on `context.WithoutCancel(ctx)` on purpose.
- **A `Start` that returned nil is followed by one `SettleStart(ctx, out, cfg, target)`** (#343, #349); each package has one seam over it that its `TestMain` stubs (`lifecycleSettleStart` in `cmd/wt`, `settleStart` in `internal/tui`).
- **A failed start is printed once, by `main`** (#344): a new command that can return one needs `SilenceErrors` or `asStartError`/`printOnce`, or the message prints twice.
- **An ollama stop ollama accepted but has not carried out is `*StillFinishingError`, never nil** (#379); only the stop loop reads it as an outcome (exit 0). The TUI stops models only after the alt screen is gone.
- **wt signals a process only after identifying it** (`server_loading.go`): a pid is never enough (user's own, a process server's exact argv on the provider's port, recorded start time, rechecked before SIGKILL). The pidfile stays a bare pid (llmbench shares it).
- **An empty `Stop` means "signal the verified pid"** (sushi has no stop command, and running the bare binary is not a stop): `processServer.stop` calls `stopByPid`, which shares `signalVerifiedServer` with `stopLoadingServer` (SIGTERM to the group when wt recorded the start, else the pid alone; `stopGrace` 10 s; SIGKILL only if the same start time remains; the pidfile and `.wt` go once the process is gone; then `stopByPid` waits `stopTimeout` for the port to close). `loadingServer` refuses a pidfile pid <= 1 or wt's own. No verified pid: a port that does not answer is nothing to stop (nil), one that answers is `*NotStartedByWtError` ("… was not started by wt; stop it yourself"). `TestTableInvariants` requires `PidfileDefault`, `Subcommand` and `PortFlag` of a spec with an empty `Stop`. A sushi llmbench started has a bare-pid pidfile and no `.wt` record: `wt stop` still stops it when its argv matches, with no start-time check against pid reuse.
- **`ProcessSpec.WarmupSeconds` and `ReadyHTTP`.** `WarmupSeconds` (contract key `warmup_seconds`; mtplx 120, rec 120, sushi 400; required and positive, `warmupBudget` fails a start without one) is the warmup window and the cap on each chat request. `ReadyHTTP` (contract kind `http-get`, `Path "/health"`) is ready on exactly HTTP 200 and names no model: sushi answers it before any pack is loaded, so the warmup performs the cold load and then `confirmLoaded` requires the exact id among the loaded models.
- **The loaded-aware served list is opt-in per family** (`FamilySpec.LoadedOnly`, contract key `loaded_only`; today only sushi). `ServedIDs` (so `wt served` and the inventory's Running) reads such a family through `localmodels.FetchLoadedModelIDsKeyed`, which drops an entry only when its `loaded` is the JSON literal `false`; absent, null or non-bool keeps it. `confirmLoaded` always uses it. Every other call, including every other family's served list, the readiness poll and `requirePackListed` (exact id; an empty list skips the check; a failed fetch fails the start), goes through `FetchModelIDsKeyed`, which lists every id. omlx keeps its own pool branch.
- **A busy port holding a wt-started `ReadyHTTP` server is reused, not refused** (`processServer.start`): sushi answers `/health` with no pack loaded (or mid cold-load), so nothing shows Running and the port is busy. When `loadingServer` verifies the pidfile's process as wt's own, the start spawns nothing and signals nothing; it runs the pack check, the warmup (which loads the pack into that server) and `confirmLoaded`. A failure there does not kill it (it was not spawned by this start). A busy port with no verified pidfile is still `*PortBusyError`.
- **`config.Load` derives sushi for claude and pi in memory** when the registry holds a sushi model (`deriveSushiAgents`, `config.SushiAgents`): `wt model add` still writes it (`EnsureAgentProvider`), but a pack registered any other way works too. Removing sushi from an agent sticks only while the registry has no sushi model.
- **The wired-limit preflight** (`wiredlimit.go`, `wiredLimitFamilies` gates it by family id, today `sushi`) runs in `start` before the others question and before any stop. It reads `sysctl -n iogpu.wired_limit_mb hw.memsize` (0 means 75% of `hw.memsize`) and needs `floor(total *.safetensors bytes * 11 / 10 / 1048576)` MiB (`ngram_table.bin` excluded; 49,506,491,792 bytes, i.e. 47,213 MiB of bytes, is 51,934 MiB). Below that it fails with `sudo sysctl iogpu.wired_limit_mb=59000` (resets on reboot); wt never sets the sysctl. What it cannot measure prints `wt: skipping the memory check (<why>)` and the start goes on. llmbench applies the same integer rule, gated by the contract's `wired_limit` (a lifecycle test pins `wiredLimitFamilies` to it) and reading the pack directory from the contract's `model_dir` (the contract test pins it to `DefaultModelDir`). A failed sushi warmup gets the fix appended only for eight phrases (`memoryRefusalMarkers`; the bare word `iogpu` is not one), pinned by a test on each side. A warmup request is capped at the time left in the `WarmupSeconds` window, so the budget is the most a warmup can take.
- **A key the registry names goes with every probe of a process server** (`localmodels.FamilyAPIKeyErr`): a `secret_ref` that cannot be read ends a start before the spawn (`*KeyUnreadableError`); a refused key is `localmodels.ErrKeyRefused` (family `partial`, not `down`). rec's key (`exec:rec auth token`) also goes into its LiteLLM route. A `ScopeMachine` family's existing instance is adopted when it serves the target at the registry's address and asked about before it is replaced otherwise (details and known limits: `docs/internals/local-models.md`).

Read [docs/internals/local-models.md](docs/internals/local-models.md#lifecycle-internallifecycle) before changing start/stop, the route hook, the launch-time route check, restart or readiness waits, or replace.

## Rotation (Go)

Each successful single-model launch records its id in `~/.config/agent-wt/rotation.state` (`rotation.RecordFor`, which also writes `last-picked.state` and `usage.jsonl`); the picker cursor lands on the model after it (`FirstAfter`).

- **Marker and pointer are two files**: `rotation.state` stays one bare registry id; `last-picked.state` holds the `> ` marker's row. A slot-profile launch calls `RecordProfile` (never `rotation.state`); a profile row never rotates.
- **The sort order is also the default selection** — changing `sortRows` changes what a bare Enter picks. The marker is plain ASCII `> ` (Unicode misaligns CJK terminals).

Details and pinned tests: [docs/internals/local-models.md](docs/internals/local-models.md#rotation-go).

## Agents (Go)

Each agent registers a `Driver`; `BuildLaunchCmd(agent, m, worktreePath, yolo, cfg, extraArgs)` is the shared constructor for both launch paths (it resolves one `config.Route` via `cfg.ResolveRoute(m, agents.ProtocolsFor(agent))`).

- An empty agent/provider wire-protocol intersection forces LiteLLM regardless of the toggle — so **codex always routes through LiteLLM**. Litellm/forced routes use the registry id (`m.ID`); direct routes the provider-side name (`m.ModelName`).
- **copilot uses the chat-completions wire (`WIRE_API=completions`)** — its `responses` wire drops leading characters.
- **claude maps all four model slots on every non-native single-model launch** (`claudeSlotVars`); an applied profile's `env` is appended later and wins.
- **claude declares a gateway model's context window** (#405): `CLAUDE_CODE_MAX_CONTEXT_TOKENS` from the `context` of its `tiers.toml` entry **only when `context_basis` is `host`** (`claudeWindow`; #470: a `largest_row` window, or a file with no basis, is never declared; cloud models only, a local build has none). The single-model launch sets it unless the user's environment already has it; a slot profile sets the smallest window among the slots that have one, provided the default slot has one (`claudeSlotWindow`, #471; opusplan anchors on the smaller of opus and sonnet, none if either is unknown; a slot with no window is ignored, not a veto) unless the profile's env, `config_content.env` or the user's environment names it. The `loadTiers` seam is stubbed by tests and `tiers.IsolateForTest` closes the real file.
- agy is a native passthrough, not a command agent: `-A agy` without `-M` errors when more than one agy model is eligible.

Read [docs/internals/agents.md](docs/internals/agents.md) before changing a driver, `Route`, an optional capability (`Seeder`, `Syncer`, `ArgSetter`, …), or `ollamacheck.Check`. Per-agent env/args: [docs/wt-agents/](docs/wt-agents/). New driver: the `adding-a-wt-agent` skill.

## Profiles (`internal/profiles`)

Opt-in overlays from `~/.config/agent-wt/profiles.toml` (`profiles.Resolve`), applied on both launch paths and by `wt smoke`; operator reference [docs/wt-agents/profiles.md](docs/wt-agents/profiles.md).

- Call the `config_content` cleanup explicitly after the run — `runAgentCmd`'s `os.Exit` skips defers.
- Apply order is env/args → `config_content` (with `config_defaults`) → wrapper; load/validate/apply errors degrade to an unprofiled launch with a warning.

**Slot profiles** (`~/.config/agent-wt/slot-profiles.toml`, hand-editable and written by wt only through `wt profile slots add|set|rm` (`internal/slotedit`: dated backup, validate under a `config.WithFileLock` flock, comment-preserving); [docs/wt-agents/slot-profiles.md](docs/wt-agents/slot-profiles.md)) map an agent's model slots to registry models and are pinned with `-M profile/<name>`; claude is the only slot agent. ## Worktree (Go)

`internal/worktree` handles enumeration (`Enumerate`) and creation (`Resolve` then `Plan.Ensure` for `-W`; the picker's new-worktree, bare-branch and remote-only rows bind a `Plan` at the pick and their launch gate ensures it at the commit point, `internal/tui/launchgate.go`'s `launchCreation`, so a declined gate creates nothing). Every function takes `dir` (repo root) first for testability.

> **Worktree paths derive from the full branch name** (`worktreeDirName`): path separators on any platform, colon, and ASCII control characters flatten to `-`, so `feature/x` → `.worktrees/feature-x` and `feature/x` + `bug/x` get distinct directories (once they raced for `.worktrees/x`). A name that flattens onto another's directory (`feature/x` vs `feature-x`) errors "already in use by branch …" on every creation path, `-W` and the picker alike (one `pathCollision` check); the check asks the filesystem (`os.SameFile`) so `Feature/x` vs `feature/x` collide on a case-insensitive volume (macOS default) and stay distinct on a case-sensitive one; a flattened name over 255 bytes is refused with a "shorten the branch name" error (git stores a long ref as nested directories, but the flattened name is one entry); a worktree from the old last-component layout (`.worktrees/x` holding `feature/x`) keeps resolving by branch name (the reuse loop matches branches, never paths). Derived `.`/`..` are rejected — `filepath.Join` would clean `..` to the repo root and `.` to the container.

> **Validate the derived path before running git** (`worktreePath`/`newWorktreePath`): `git worktree add -b` creates the branch first, so a path that then fails (too long, taken) leaves a stray branch. Every creation site goes through those two helpers; a new site must too.

> **A launch that has a directory needs no repository**: the repo root handed to `runLaunchPath` gates the guard install and nothing else (state is keyed by model, agent and pid). Only `-W` and the worktree picker refuse outside one; don't key new launch state on the repository. [Details](docs/internals/launch-flow.md#launch-directory-and-the-repository).

> **The picker fetches on the user's `F`, never when it opens** (`worktree.FetchRemotes`: `git fetch --all --prune`, 5s; the outcome is rendered in the header — `fetch: ok, …` / `fetch: FAILED (…)` — a failure is never silently ignored); `Enumerate` (only `--debug-worktrees` still uses it) does not, `-W`/`--cwd` skip the picker, and creation never fetches (`Resolve`, `Plan.Ensure` and `EnsureForName` read only the remote-tracking refs already present).

> **The picker is a view over `internal/cleanup`'s rows and its PR tags never hold it up** (`internal/tui/picker_rows.go`, #384, #390): it paints from `cleanup.Gather` with `SkipPRs` (`PR ?`), then `loadRowPRsCmd` runs `cleanup.FillPRs` off the update goroutine and swaps the report in, the cursor kept; `dropStalePRTags` clears a reused branch name's ended PR (#451). Seams `cleanup.StubPRListForTest`/`StubPRBaseListForTest` or `GatherInputs.PRList`. [Details](docs/internals/tui.md).

> **Creation routes create from one plan**: `-W` (`worktree.Resolve`, then `Plan.Ensure`) and every picker creation (`launchCreation.ensure`, the commit point for a typed name's, a bare-branch row's or a remote-only row's plan). The plan is one classification: the creation line the launch warnings print before anything exists (`launchwarn.Creation` → `creationLine`) names the branch, the worktree and the tracking ref — the base is deferred, the frozen `creationLine` does not carry it — and `Plan.Ensure` creates from the same object (the plan still carries the base; a moved base is refused, #525); `EnsureForName` remains as a one-shot wrapper. Nothing records what a route made — the exit prompt's creation records died with it (`internal/exitprompt` **deleted**, Task 304), and nothing is asked when an agent exits. A brand-new branch is made only for a name that matches nothing (`Plan.Creates`): a reused worktree, a new worktree on an existing branch or tracking a remote (the picker's bare-branch and remote-only rows, whose owed creation the launch gate makes — its `Plan.Creates` is false for both), `--cwd` and `--root` never make one.

> **`IsRepo` uses `rev-parse --git-dir`, not `--show-toplevel`.** Bare repos and directories inside `.git` have no worktree; don't "simplify" `IsRepo` to delegate to `RepoRootAt`.

> **The default branch is an ordinary worktree name.** `EnsureForName`/`EnsureForBranch` create `.worktrees/<default>` like any branch (no `refuseDefaultBranch` guard remains; launch risk messaging is `internal/launchwarn`'s), and a second Ensure for the same name reuses the worktree at the derived path (`EnsureForBranch` reports what it made as `Created`). Git alone refuses a second worktree on a branch already checked out elsewhere, and its own error stays the user-visible message: surfaced verbatim from the captured stderr ("… is already used by worktree at …"), never wrapped away or replaced (`gitError`). `-W main` with the root on `main` still resolves to the root first (the reuse loop matches the root's entry) and launches there, with the root warning. `-W origin/feature` resolves like the picker (a local `feature` tracking it); `<remote>/HEAD` names no branch of its own and git refuses the `HEAD` name it would take.

## Cleanup classifier and removal (`wt worktrees` alias `wt cleanup`, `wt remove`)

`internal/cleanup` classifies every worktree, local branch and `origin` branch into proven / less_sure / unique_work / in_use from one snapshot and is **read-only** (apart from the `git fetch --prune <remote>` the commands run for every remote first, never prompting, which `--no-fetch` skips, it writes no ref, index or working file; it reads the `refs/wt/rescued/*` records `wt rescue` leaves (`ListRecords`, one `for-each-ref`) and lets a matching one make a clean rescued original removable (see "The record" under Rescue invariants); the merge-adds-nothing proof, `git merge-tree --write-tree`, may leave unreachable tree objects that `git gc` collects); `cmd/wt/cleanup.go` prints it (`--json`, `--plain`) or shows the tick list (`internal/tui/cleanup_list.go`), whose enter removes the ticked rows after a confirmation (`internal/tui/cleanup_confirm.go`; the list does not fetch on open, so its origin rows read `cannot_verify` (`FetchResult.NotAttempted`, worded "not refreshed in this list", not `--no-fetch`) and an origin branch is removed with `wt remove origin/<name> --remote`). `wt remove` (`cmd/wt/remove.go`) names targets on the command line. Both go through one engine, `internal/removal`, **the only deletion code in wt**. `wt rescue` (`cmd/wt/rescue.go`, engine `internal/rescue`) is the copy-only counterpart: it creates, it never deletes (see "Rescue invariants"). Design: [../docs/superpowers/specs/2026-11-04-wt-cleanup-design.md](../docs/superpowers/specs/2026-11-04-wt-cleanup-design.md) (PR B as built: [../docs/superpowers/plans/2026-11-05-wt-cleanup-pr-b.md](../docs/superpowers/plans/2026-11-05-wt-cleanup-pr-b.md) and its rulings; PR C, origin removal: [../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-c.md](../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-c.md)); command reference: [docs/wt-cleanup.md](docs/wt-cleanup.md); operator pointer: guide 08 §9.

- **Every git call the classifier runs has `GIT_OPTIONAL_LOCKS=0`** (`cleanup.Git`): without it `git status` may rewrite the index's stat cache in the worktree it inspects, which broke "writes no index" until `wt rescue` compared a source's index bytes before and after.
- **Fail closed.** A git error, an unresolved default branch, an unknown PR state or an unavailable gate is Unknown, never proven. `LookupUnknown` is the zero value of `Lookup`, so a missing map entry reads Unknown.
- **Deletion lives only in `internal/removal`**: `TestDeletionStringsOnlyInRemovalPackage` (a `go/ast` scan of every non-test file under `wt/`, with an explicit per-file allow-list for unrelated `os.Remove*` users) and `TestCleanupCmdContainsNoDeletion` (`internal/cleanup`, `cmd/wt/cleanup*.go`; also bans a `push` refspec `:<branch>` and `gh api -X DELETE`) and `TestRescueContainsNoDeletion` (`internal/rescue`, `cmd/wt/rescue*.go`; it bans the delete-flag shapes of `update-ref` and requires exactly one `"update-ref", ref, commit, ""` (create-only, the record's ref) in `internal/rescue/record.go`, checked by `riskyRescueSource`; `fileOpNever` also keeps both off the file-op allow-list). `TestDeletionStringsOnlyInRemovalPackage` is shape-based and needs no allow-list entry for the record. The command file is `remove.go`, not `cleanup_remove.go`, for that reason. Removal now also resets and switches the root (`internal/removal/root.go`, `ReleaseRoot`, for `wt restore-root`), only behind three proofs: an unchanged fingerprint, a verified copy and a record `cleanup.RecordCoversDirt` says still holds the root's index and working tree (or, with nothing uncommitted, an empty status). It refuses first when git repository variables (`GIT_DIR`, `GIT_INDEX_FILE`, ...) are set, when the root is detached, when the default branch is checked out in another worktree, when an index entry is assume-unchanged or skip-worktree (status cannot see its edit; so a sparse checkout is refused, failing closed), and it runs every git call with `core.fsmonitor=false` (a stale fsmonitor hook would hide an edit), and, last (after the record check), when the reset would delete or overwrite an ignored file (one inside a directory where HEAD tracks a file, at an index-deleted path, replacing a tracked directory, or under a directory-pattern-ignored directory holding paths HEAD tracks; names compared folded under `core.ignorecase` and, for case and Unicode normalization the volume aliases, by file identity on disk: ignored files are in neither the copy nor the record). It runs every git call in the root (never the caller's directory), removes exactly the untracked paths the copy carried whose content still equals the record (never `clean`), and runs its two writes, the reset and the switch (`--no-overwrite-ignore`), with `-c core.hooksPath=/dev/null -c submodule.recurse=false`; `TestRootMutationFunctionsAreExactlyTheAllowList` pins the functions that may reset, switch or delete files to `ReleaseRoot` and its helper, and `TestHardResetExistsNowhereOutsideRemoval` keeps `"--hard"`, `"reset"`, `"clean"`, `"checkout"`, `"restore"` and `"stash"` argv words out of every other package (the guards cover only those words). A failed reset or switch call is a `ReleaseFailed` with `Uncertain` set: git may have written part of the index or tree. `internal/rootmove` and `cmd/wt/restore_root*.go` are inside the deletion scan: `TestRootmoveContainsNoDeletion` bans `rootmoveBanned` (rescue's list plus `"--hard"`, `"reset"`, `"clean"` and any `"update-ref"`), with `TestRiskyRootmoveSourceBites` and `TestRootmoveIsInsideTheDeletionScanAndNeverAllowed` keeping the scan honest; rootmove only names `ReleaseRoot`.
- **A remote ref folds into the local row that tracks it** (`Row.Upstream`): the head's upstream when it is the same-named branch of its remote, else `origin/<name>` when the head has no upstream (exact refnames, so a case variant never folds); a gone upstream is `Upstream{Gone}` with no row. The folded remote row stays classified in `Report.Folded`, not `Rows`: **find a remote row through `Report.RemoteRows()`** (`Rescan`, `wt remove origin/<name>`), and list everything through `Report.AllRows()` (`Encode`, `Groups`, `--plain` and `--json` still show it as its own row); the kind-grouped terminal list renders the fold (`KindGroups`' `remoteOnly` leaves a folded ref out of REMOTE BRANCHES, so a folded origin branch is removed with `wt remove origin/<name> --remote` until the list offers it).
- **The base is `origin/<default>`**; the local default is only a fallback, and then every verdict is capped below proven (`capFallback`).
- **Weak signals are not proofs**: `git cherry` and patch-id equivalence (`WeakSignals`) show as less_sure, never proven (they pass a squash that was later reverted).
- **Refs passed to `Prove`/`WeakSignals` are fully qualified** (`refs/heads/<b>`, `refs/remotes/<r>/<b>`) or a 40-hex id, so a tag never shadows a branch.
- **Min-age (`DefaultMinAge`, 10m) gates `same-commit` and `ancestor` evidence**: wt creates branches from a local main behind `origin/main`, so a new branch reads as ancestor-merged. An old branch whose reflog expired takes its age from `packed-refs`' mtime, so it reads fresh for 10 minutes after any packed-refs rewrite (clone, gc, a fetch that prunes a packed ref); accepted, it heals.
- **`wt worktrees --json` (alias `wt cleanup`) carries the header's caveats in `notes`** (`cleanup.NoteLines`: lowered min-age, artifact protection off, no registry): a script acting on `rows` must read it, since with protection off no row has a `protected_artifact` blocker. The text header and `notes` come from the same function.
- **Evidence strings, reason and blocker codes are the JSON contract**: [../docs/contracts/cleanup-list.sample.json](../docs/contracts/cleanup-list.sample.json) + `cleanup-list.schema.json`, held by `cmd/wt/cleanup_contract_test.go`; change them only with the fixture.
- **`--min-age` has a floor** (`cleanup.MinAgeFloor`, 1m; less is a usage error); a value below 10m is named in the header.
- **Protected artifacts fail closed** (`protectedPaths`, `cmd/wt/cleanup.go`): a registry that did not load is `errRegistryUnavailable`; a malformed, unexpandable `~` or **relative** `local_path` is refused with an error naming the model (no tool agrees on a relative path's base). The listing still shows, with "artifact protection is OFF and removal is refused" in the header. Only a missing registry at the default (not redirected) path is "nothing to protect". The `protected_artifact` gate blocks both directions: an artifact in the worktree, or the worktree in (or equal to) an artifact.

**Removal invariants** (`internal/removal`; the rulings are in the PR B plan's note):

- **Rescan before acting.** Each item is re-classified by `cleanup.Rescan` immediately before it is touched (never a fetch; no `gh` for a worktree or branch, but a **remote** target asks `gh` live, once for who has the branch as head and once for who targets it); `Rescan` itself enforces the target's identity. A fresh status worse than `Saw`, a moved tip (`SawTip`) or worse losses than `SawLosses` (more dirt, unpushed or ignored entries; Ruling G) is `skipped_changed`, never an error.
- **Losses are raw in the classifier and effective in removal.** `Row.Losses` stays what the classifier counted (a preserved row still has `Unpushed > 0`). `Row.EffectiveLosses()` clears only `Unpushed > 0` and `DetachedUnique` of a row with `Preserved`; `-1`, `Dirty`, ignored files and `GatesUnknown` are untouched. `LossLines`, `ItemFromRow`'s `SawLosses`, the preview and the engine's force and loss checks read the effective view; `rescue.Preflight`/`Offered` and the `GatesUnknown` and `gitForce` reads stay raw (a second `wt rescue` of a preserved original must still be possible). `TestEveryLossesReadSiteIsLabelled` (with `TestLossesGuardBites`) (`internal/cleanup/losses_guard_test.go`, a name-keyed `go/ast` scan, no `go/types`) pins every function in `cmd/wt` and `internal/` that reads `.Losses`: a read needs a `// losses: raw, <why>` marker or must use `EffectiveLosses`, and the per-function counts are exact.
- **Exact refs, resolved paths.** The CAS uses the exact spelling from `for-each-ref` (`Row.Ref`); "checked out elsewhere" compares case-folded full refnames; paths go through `cleanup.ResolvePath` (`/var` vs `/private/var`). A `wt remove` argument matches a worktree path or exactly `refs/heads/<arg>` (a branch name also matches the worktree holding it; Ruling Q); `origin/<name>` (exactly) matches the origin row `refs/remotes/origin/<name>`, ambiguous with a local branch of that literal name.
- **A deleted branch's `branch.<name>.*` config is removed too** (`afterDelete`; `update-ref -d` leaves it, `git branch -D` does not), so a restore under that name starts without the old upstream. A failure is a warning, not an outcome change.
- **Branches go by compare-and-swap**: `git update-ref --no-deref -d <ref> <fresh tip>` after a fresh worktree list (`cleanup.HeldRefs`) shows no holder; a worktree that takes the branch in the window gets it back create-only. `update-ref` has none of `git branch -d`'s checks, so every guard is `branch.go`'s own. A branch is deleted unasked only when the branch alone is proven (`Row.BranchProven`, Ruling A); otherwise `retained_unmerged`. A branch with a sibling whose refname differs only in case is `retained_unknown` on every filesystem (on a case-insensitive volume `update-ref -d` removes both; Ruling X). A worktree that would need `--force` and holds submodules (an admin-dir `modules/`, even a leftover one, or any initialised module in `git submodule status`, including an embedded repository) is refused, and so is one whose check cannot be read: git skips its submodule check under `--force`. The restore line is `git branch <name> <sha>`, or the create-only `git update-ref refs/heads/<name> <sha> ""` for a name starting with `-` (it fails if the branch was re-created meanwhile).
- **Approvals are per item and sealed** (Rulings K-N): `Item.Approved` (`Needs{Confirm, Force, Delete}`) replaces any run-wide flag. An item reaches `Run` only unmodified from `ItemPreview.Confirmed(exactly its Needs)` or, for a worktree whose unmerged branch the user opted in to delete, `ConfirmedDeletingBranch`; previews are sealed too. `Run`/`Plan` refuse anything else ("invalid target: not confirmed").
- **Force scopes**: `Force` (`--force`) = lose a worktree's uncommitted changes or a detached HEAD's unique commits (`git worktree remove --force`); `Delete` (`-D`) = delete a branch not proven merged (unknowns about the merge verdict alone do not block it, identity/loss unknowns do; Ruling H); `Confirm` (`--accept-loss`, or the TUI's typed `delete`) = any non-proven item or any loss, mandatory on every path (Ruling P). No approval overrides a hard blocker (primary, current, locked, nested, operation in progress, protected artifact, and an open PR on an origin branch or one that targets it). A held item and the default branch are floors, not blockers: they need `--accept-loss`, and a branch not proven merged also `-D` (a default branch only when a remote default, not the local one itself, is the base).
- **Shared helpers, one copy each**: `removal.Headline`/`DetailLines` (the command's text and the tick list print the same loss, warning and restore-id lines), `removal.EncodeReport` (says whether the document is partial), `cleanup.IsFullCommitID`, `failWithEnvelope` in `cmd/wt/cleanup.go`, `isTerminalStream` and `writeResult` in `cmd/wt/prompt.go`. `wt remove --json` prints its error document for usage errors too (no target; a bad flag after `--json`). `cleanup.commonDir` is remembered per directory, so looping `HeldRefs` over worktrees costs one `rev-parse`.
- **Origin removal** (`internal/removal/remote.go`, the only code in wt that writes to a remote). Only a **proven** row of **origin**; the engine refuses everything else (`invalidRemoteItem`: the ref must be `refs/remotes/origin/<safe name>`, no path, Saw proven, a full sha; the default branch is `retained_default`). It needs its own approval, `Needs.Remote` (CLI `--remote`, TUI typed `delete origin`): required even for a proven item, covers nothing else, and `--yes`, `y`, `--accept-loss`, `-D`, `--force` and the plain `delete` never grant it. The row is proven only when origin was fetched cleanly *this run* (`--no-fetch`, a terminal list that fetched nothing — it does not fetch when it opens, `FetchResult.NotAttempted`, unless `--fetch` or the list's `F` ran — a failed fetch or no origin makes it `cannot_verify`; the fetch result is carried by `GatherInputs.Fetched` so a refresh keeps it), a live `gh pr list --base <n>` (made by `Gather` only when `GatherInputs.OriginRows` is set: the list and `wt remove origin/...` set it, `wt remove <local>` does not; `Rescan` re-asks for a remote target only; any head repository, no own-repo filter; truncation or error is unknown) finds nothing targeting it, and a MERGED PR into the default branch has `HeadRefOid` == the tip with its merge commit in the base (the classifier's answer, and `remoteGate` asks git again with `merge-base --is-ancestor` before the push). Origin-only checks never apply to another remote's row, and neither do the bare-name PR lookups (`Snapshot.PRs` and the open PRs `dependants` finds by base describe the repository origin points at): another remote's row is judged on git's proofs, so a PR found for `origin/foo` never informs `upstream/foo`; and because nothing asks gh about another remote, its pull-request state is unknown, so the row is at most less_sure with `not_checked` (fail closed, never proven by git alone; a dedicated code, not `cannot_verify`: no gh lookup failed, so present.go's gh wording and the header's gh line leave it alone). Order in `remoteAct`: preflight `git ls-remote --exit-code origin refs/heads/<n>` (exact refname, one line, sha == the listed tip, else `retained_moved`/`retained_unknown`, no push) then `git push --porcelain --no-verify --force-with-lease=refs/heads/<n>:<sha> origin :refs/heads/<n>`: the explicit sha makes the server the compare-and-swap (a bare lease would use the tracking ref, which a fetch may have moved), never `--force`, `-f`, a `+` refspec or a lease without a sha. Git runs with `cleanup.NonInteractive(dir)` env and a 120s limit. The result is judged by a fresh ls-remote, never the push's status (gone = `deleted`; still there = `retained_unknown`, or `retained_moved` on a lease refusal or another sha); `DeletedTip` is set before the push and kept while the ref is not proven present. A same-named local branch is not touched (a warning names it). An open race the tool cannot close: a PR opened against the branch after the last `gh` read.
- **Fetch is per remote** (`cleanup.Fetch`): `git fetch --prune <remote>` for each remote (skipping `remote.<r>.skipFetchAll` for every remote but origin, which is always fetched), `FetchResult.OK` meaning origin's, `Remotes` each one's; `Git.Env` carries `cleanup.NonInteractive(dir)`: `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never` and `GIT_SSH_COMMAND=ssh -o BatchMode=yes` only when neither `GIT_SSH_COMMAND` nor `core.sshCommand` is set (a user's own ssh command is left alone). Origin is fetched first and alone (120s); the other remotes then run concurrently under `otherFetchTimeout` (30s). With no origin `fetch.skipped` is `no origin remote` and `fetch.remotes` still lists the others. The header and `fetch.remotes` in the JSON name each remote.
- **Outcomes are frozen wire strings**: worktree `removed|skipped_changed|refused|failed|not_requested`, branch `deleted|not_attempted|retained_unmerged|retained_moved|retained_checked_out|retained_default|retained_unknown` ([../docs/contracts/remove-result.schema.json](../docs/contracts/remove-result.schema.json), held by `cmd/wt/remove_contract_test.go`). A deleted (or possibly deleted) branch's full sha is `Outcome.DeletedTip` / `branch_tip`, recorded before `update-ref` (or the origin push) runs (Rulings I, J). A remote item reuses them: `kind: remote`, `worktree` `not_requested` once acted on (`refused`/`skipped_changed` at a gate, branch `not_attempted`), `branch` describing the origin branch.
- **The result never drops an item** (Ruling O): an off-contract value becomes the `invalid` sentinel with an envelope `error` beside `items` (a partial report; treat every listed change as made).
- **`wt remove` exit codes**: 0 everything named removed (a kept unmerged/held/default branch of a removed worktree is fine), 1 could not start (no match or ambiguous argument, registry failed to load, `--min-age` below 1m), 2 some item refused/skipped/failed or a moved/unknown branch, 3 approval missing (no `--yes` and no terminal, or the prompt declined). The y/N prompt only replaces `--yes`; the tick list exits 0 after a run with refusals (Ruling R).
- **TUI**: typed `delete` for anything not proven (`y` only when every item is proven); `delete origin` (unreachable from `wt worktrees` today: its origin rows are never proven without a fetch) when any ticked item is an origin branch (an `ORIGIN BRANCHES` group and a banner with the count and the audience; the plain `delete` and `y` never run it; each item still gets only its own approvals, so Remote reaches origin items alone); the `-D` toggle is per item, off by default, offered only where the engine says so (Ruling S), and applies only to an entry whose decision lines are on screen; the prompt always states the item count and the force and `-D` counts, plus "N not shown" (Ruling U). While a run is in flight keys, ctrl+c, SIGINT and SIGTERM wait; every outcome is logged as it arrives and printed after the alt screen closes (Ruling T).

**Rescue invariants** (`internal/rescue`, `cmd/wt/rescue.go`; PR D; plan [../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-d.md](../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-d.md)):

- **Copy-only, never deletes.** `wt rescue <worktree-path-or-branch>` creates branch `rescued/<branch or directory>` (`--to NAME` is the full branch name) at the source's exact HEAD in a new worktree under `.worktrees/` (`worktree.CreateAt`: full commit id only, `--no-track`, never reuses a branch or worktree, `worktree.CheckNew` is its read-only twin). It carries unpushed commits (they are on the branch), staged changes (`diff --cached --binary --full-index --no-renames`, `apply --index`), unstaged changes (same, `apply`) and untracked non-ignored files (O_EXCL, mode kept, symlinks recreated, no path leaves the destination). Ignored files are not carried; the count is reported. It never removes or changes the original (a later `wt remove` has a small write window between its re-check and `git worktree remove`). `unpushed` counts remote-tracking refs only and the dirt is copied, not moved, so on its own the source still reads unique_work; what makes an original removable is the record, which `internal/cleanup` reads (see "The record"): a *clean* one (commits only) reads proven (PR B1), a dirty one (staged, unstaged or untracked changes) reads `less_sure` and takes `--accept-loss` only while its index and working tree equal what the record captured (PR B2). Any other dirty original is unchanged: unique_work, `--accept-loss --force -D`.
- **The source is only read.** All source git runs with `GIT_OPTIONAL_LOCKS=0` and `core.fsmonitor=false` (`internal/rescue/git.go` wraps `cleanup.Git`, whose `Config`/`Env` fields carry them; there is no second git runner). A fingerprint (HEAD, the branch ref HEAD names, the index's staged content via `ls-files --stage` not its file bytes, the porcelain-v2 status, a hash of every path it names; other refs and worktrees are deliberately out, a parallel session or fetch must not abort a rescue) is taken at `Preflight`, re-checked at the start of `Execute` (changed: `refused`, nothing created) and after the copy (changed: `failed`, `source_changed_while_copying`). Every refusal test asserts the fingerprint and the refs/worktrees are unchanged.
- **Every refusal is before anything exists** (`Preflight`, codes in `rescue.Codes`): not a worktree, primary (`wt rescue` refuses the primary checkout and names `wt restore-root`; root mode, `Engine.ForRoot`, skips `primary` and `nothing_to_keep`), nothing to keep, unreadable gates, operation in progress, unmerged paths, skip-worktree/assume-unchanged, submodule change, a path both staged and modified, intent-to-add, nested repository, special file, line-ending conversion (`checkLineEndings`: one `ls-files --eol -z` over the whole index with no path arguments, filtered in Go to the changed paths, so no ARG_MAX limit; judges the attr columns with `core.autocrlf`/`core.eol`, so an LF file that a `text` attribute plus `core.eol=crlf` would write as CRLF is refused too, naming only the affected changed paths), a `filter`, `ident` or `working-tree-encoding` attribute on a changed file (`content_filter`; `checkContentFilters` sends its paths to `check-attr --stdin -z`, never the argv), more than 20000 untracked files or 512 MiB of untracked files plus changed tracked files together (`too_large`; a changed tracked file counts as the larger of its working-file size and its index or HEAD blob, `blobSizes`, read from NUL-delimited `ls-tree -r -l -z HEAD` and `ls-files -s -z` listings so any path name is covered; a staged rename counts once, at the larger of the old path's HEAD blob and the new path's blob; a staged deletion of a big file counts), name unavailable (names `--to`; no silent suffix), a count of unpushed commits that cannot be read or contradicts the gate (an error, exit 1; `Counts.Commits` is never a silent 0). Current, locked and held sources are allowed (held gets a warning). The fingerprint is taken **before** `readWork` and again after it; a difference is `source_changed` (a change during the reads is never baked in).
- **The record (`refs/wt/rescued/<id>`) is written after the verified copy; `internal/cleanup` reads it for clean originals (B1) and, while they still equal the record, dirty ones (B2).** After `verify` passes, `buildRecord` (`internal/rescue/record.go`) makes two commits: I (the source's index tree, built in memory by `dirtsnap.IndexTree` from `ls-files --stage -z`, parent the source's HEAD; rescue never runs `git write-tree`, which would rewrite the source's raw index file) and W (the working-state tree from `dirtsnap.Build`, parent I); then `Execute` re-takes the source fingerprint (after the record's reads; seam `beforeRecordRef`) and, only if it equals the one the copy was verified against, `createRecordRef` creates the ref `refs/wt/rescued/<first 16 hex of W>` with one create-only `update-ref` (`RecordRefPrefix`; after a change only unreferenced objects are left, for gc). The record's git runs with `core.hooksPath=/dev/null` (a reference-transaction hook must not refuse it). `dirtsnap.Build` reads a path below a symlink, a file or a missing directory as absent (git's `has_symlink_leading_path`); `dirtsnap.IndexTree` differs from `write-tree` on an intent-to-add entry, so a caller refuses i-t-a first. The commits carry `Wt-*` trailers and a fixed identity, so no git config is needed. Any failure (unreadable or changed source, `ErrUnsupported`, `ErrTooLarge`, a git error) is one `record_not_written: ...` warning (`RecordWarningPrefix`) and the rescue stays `moved`. `internal/dirtsnap` builds the trees with no temporary index or file and has no deletion code. The result carries it as `record {ref, commit}` (additive in the schema) and the text output as one `record:` line. `internal/cleanup` reads it (the reading side, PR B1): `ListRecords` (`records.go`) parses every ref under `refs/wt/rescued/` (the cleanup package repeats the ref prefix and trailer keys, it cannot import `internal/rescue`); `preservedOf` (`preserved.go`) matches one to a branch or detached worktree row only when the ref is `refs/wt/rescued/<first 16 hex of its commit>`, `Wt-Version` is 1, source path, ref (`detached` for a detached HEAD) and head equal the worktree's, the record commit and its parent exist, the worktree has no dirt (or, B2, its dirt is covered, below), no gates error and no hard blocker, and `rev-list --count <HEAD> --not --remotes <record ref>` is 0. The classifier then applies it (`Row.Preserved`) in the clean case (B1) only when the row's own commits are the uncovered part: no ladder evidence, raw `Unpushed > 0` (branch) or `DetachedUnique` (detached), the fresh branch tip equals `Wt-Source-Head`. The row gets evidence `rescued` and the informational reason `preserved` (`judge.info`, a fifth slot: it never lowers the status) and can read `proven` (clean case); `wt remove <path> --yes` then removes it and its own branch (`BranchProven`) with no other approval. Everything else keeps its usual effect: PR checks (`open_pr`, `pr_unknown`, `pr_head_moved`), `base_is_local`, ignored files (`less_sure`, `--accept-loss`). `Rescan` lists records afresh; a listing failure degrades to "no records" (a `Rescan` error is `refused`). A malformed, unparsable, stale or object-missing record is ignored and the row reads as before. **Dirt (B2)**: `preservedOf` also accepts a dirty row when `dirtCovered` (`internal/cleanup/dirt.go`) holds: HEAD equals `Wt-Source-Head` (the chain is source head <- I <- W, so it is `W^^`, not `W^^^`), no unmerged paths, no skip-worktree/assume-unchanged flag, then `git diff-index --cached` against I (not `dirtsnap.IndexTree`, which would need the raw index; the index file is never rewritten) and `dirtsnap.Build` of the working tree equal to W's tree. The limits (`DirtMaxFiles` 20000, `DirtMaxBytes` 512 MiB) are duplicated from rescue's and pinned equal by `TestDirtLimitsMatchRescue` (cleanup may not import rescue); a state over them reads not covered. `Preserved.CoversDirt` is true then, and `Row.Preserved` attaches to a dirt-covered row independently of ladder evidence (a merged or pushed branch keeps its own evidence); the reason `preserved` is then weak, so the row is `less_sure` (open PR still gives unique_work, `pr_unknown`/ignored files/local base stay), `EffectiveLosses` also clears `Dirty`, and `Row.Tickable` stays proven-only so such a row is never default-ticked. `row.Losses.Dirty` stays raw. Removal: `Engine.worktreeAct` (not the gate: the preview would pay a second `Rescan` per row) does one more `rescan` right before `git worktree remove` when `fresh.Preserved.CoversDirt`; `coverLapsed` compares record, tip, blockers, status and losses with the item as previewed, and a change is `skipped_changed`, while a `Rescan` error there is `refused`. `gitForce` is recomputed from the raw `Dirty`, so the user passes no `--force` yet git gets `worktree remove --force` (the covered files are in the record). The preview adds the note `uncommitted changes are kept in <ref> (copy: <path>)`. Declared losses: ignored files, file modes beyond the exec bit, empty directories, and writes in the window between the re-check and `git worktree remove`. Cost: a covered-dirt row hashes its changed files on every `Gather` and `Rescan`, and once more before removal. Clean initialised submodules are not seen by the classifier's dirt checks; `submodulesIn` still refuses them at removal.
- **Hooks are off, modes are copied.** `worktree.CreateAt` runs `git worktree add` with `-c core.hooksPath=/dev/null` (a hook must not rewrite or fail the checkout); `Preflight` warns when a `post-checkout` hook exists (`postCheckoutHookWarning`). After `git apply`, `setFileModes` chmods each changed tracked file to the source's exact mode (apply writes `0666` minus umask). `CreateAt` returns typed errors: `*NotCreatedError` (`NameUnavailable` for a `CheckNew` refusal; nothing was made, so `Execute` reports a `refused` `name_unavailable` and never `BranchKept`/`Created`) and `*AddFailedError` (`BranchLeft`/`DirLeft`: absent just before the add, present after, so only this call's own leftovers are claimed).
- **`Plan.SkipStartRecheck()`** (sets the unexported `skipStartRecheck`): the `--yes` path (no prompt between `Preflight` and `Execute`) reuses Preflight's fingerprint and skips `Execute`'s start re-read (one fewer hashing of every changed file); a prompt keeps the re-read. The after-copy comparison always runs. `cmd/wt`'s `afterRescueConfirm` (a no-op test seam between the confirmation and `Execute`) lets `TestRescueStartRecheckDependsOnWhetherAPromptWasShown` edit the source there and see which path caught it; the rescue package exports no observation hook.
- **Known limit, `CreateAt`'s microsecond window**: a branch someone creates between its pre-add look at the name and `git worktree add` is indistinguishable from the add's own leftover, so a failed add can claim it as `BranchLeft`. Untestable without a race; deliberately not changed (the code comment in `internal/worktree/createat.go` says the same).
- **Verify before claiming `moved`**: the destination's `status --porcelain=v2 -z` must equal the source's byte for byte and every path it names must match in kind, mode, content and link target; directories the copy created get the source's modes (applied last, and best effort on a failed untracked copy, so a kept half-built worktree has them too) and are compared too.
- **A failure after the destination exists keeps it** (`created` true, the path in the reason; `branch_kept` when `CreateAt` failed after making the branch): there is no rollback, because the only rollback is a forced worktree removal of a directory holding carried work. `wt remove` clears it with its own proofs.
- **`--dry-run` never fetches** (`git fetch` rewrites remote-tracking refs); its `warnings` say the last fetch was used. The list's `r` key stops the signal forwarding (`runRescue`) before the rescue prompts, so Ctrl-C and SIGHUP work again; the forwarding is also released if the list panics.
- **Exit codes**: 0 moved (or `--dry-run` would), 1 could not start, 2 refused or failed, 3 approval missing (no `--yes` and no terminal, or declined). Outcomes `moved|would_move|refused|failed` and the codes are the JSON contract (`docs/contracts/rescue-result.*`, `cmd/wt/rescue_contract_test.go`).
- **The list's `r` key** (`internal/tui/cleanup_list.go`, offered by `rescue.Offered` from the row alone) quits the list and `RemoveFuncs.Rescue` runs the same executor (`rescueRow`) on the real terminal; the list is not refreshed in place.
- **`wt restore-root` reuses the engine in root mode.** `Engine.ForRoot` takes the primary checkout as the source, skips `primary` and `nothing_to_keep`, and plans a detached destination (`worktree.CheckNewDetached`); `ExecuteInto(plan, dest)` carries, verifies and records into a worktree the caller already made (`worktree.CreateDetachedAt`); `Plan.SourceUnchanged`, `HasDirt` and `UntrackedPaths` are the proofs `removal.ReleaseRoot` is handed, and `Plan.DestinationMatches` is the read-back. The three proofs for the release are the verified copy, the record and an unchanged fingerprint, ending in `cleanup.RecordCoversDirt`; the recovery table is `rootmove`'s `recovery` (below; a failed destination switch says to `git switch <branch>` there, except when the branch moved during the run, when it says not to switch blindly). The write window between the last check and the reset is declared.

**Restore-root invariants** (`internal/rootmove`, `cmd/wt/restore_root.go`, `internal/removal/root.go`; plan [../docs/superpowers/plans/2026-11-08-wt-restore-root.md](../docs/superpowers/plans/2026-11-08-wt-restore-root.md), spec [../docs/superpowers/specs/2026-11-08-wt-restore-root-design.md](../docs/superpowers/specs/2026-11-08-wt-restore-root-design.md) with its Amendments):

- **What it does.** `wt restore-root [--to DIR-NAME] [--dry-run] [--yes] [--json] [--no-fetch]` moves the root's branch (the same branch, not a copy) into a worktree under `.worktrees/` and puts the root on the default branch. `--to` names only the directory. `Preflight` reads only; `Execute`: detached `worktree add` (`CreateDetachedAt`), `ExecuteInto` (carry, verify, record), the claim re-check, `removal.ReleaseRoot`, `git switch --no-overwrite-ignore <branch>` in the destination, the fast-forward, a read-back of both checkouts; `moved` is claimed only after it. A root with nothing uncommitted skips the copy and the record; its release needs an unchanged fingerprint and a clean status.
- **Every refusal is before anything exists** (`Preflight`, `rootmove.Codes`, 32 entries: rescue's except `primary` and `nothing_to_keep`, plus `detached_root`, `already_default`, `default_in_worktree`, `root_held`, `no_commit`, `release_refused`, `release_failed`, `switch_failed`, `no_default_branch`, `ignored_collision`, `record_not_written`, `worktrees_not_ignored`; `TestCodesCoverEveryCodeRootmoveEmits` holds the list to the sources). Order: the primary checkout, `detached_root`, `no_default_branch` (none resolves with `cleanup.ResolveBase`, or only `origin/<d>`), `already_default`, `default_in_worktree`, `root_held` (a live `sessionclaim` of another process), `worktrees_not_ignored` (the root must ignore `.worktrees/`; the refusal prints the one-line remedy and nothing is written to the repository), `hidden_index_flags` (assume-unchanged or skip-worktree; a sparse checkout is refused), rescue's root-mode refusals, then `ignored_collision` (`removal.RootIgnoredAtRisk`, or an ignored file at a path the default tracks). `already_default` is outcome `refused` with exit 0. Exit codes: 0 moved, would move or `already_default`, 1 could not start, 2 refused or failed, 3 approval missing.
- **`removal.ReleaseRoot` is the only place the root changes.** Gate order: inputs, the fingerprint, the status, hidden index flags, the record check (`cleanup.RecordCoversDirt`), the ignored-files check last. Every git call runs in the root (never the caller's directory) with fsmonitor off; reset and switch run with hooks and submodule recursion off. A carried path the reset restored from HEAD is skipped; empty directories left by the removal stay. `*ReleaseRefused` touched nothing; `*ReleaseFailed` (`Uncertain` for any reset or switch call that errored) is `release_failed`. Execute repeats the claim check immediately before the release; the window after it is declared.
- **The recovery table** is `run.recovery` in `internal/rootmove/execute.go`: every `failed` reason ends with where the root, the new worktree and the work are and how to finish by hand (a failed root switch names both `git switch <default>` in the root and `git switch <branch>` in the destination). Nothing is rolled back. `restoreRootRun` holds SIGINT/SIGTERM/SIGHUP (`holdSignals`, `signal.Stop` on its own channel) from the confirmation until the result is written and reports a received one after the result; git children in the terminal's process group still get a Ctrl-C (the step fails with its row). A move killed from outside (SIGKILL, power loss) is recovered by the same table; a half-built `.worktrees/<name>` is cleared with `wt remove <path> --force --accept-loss`. A start re-check that cannot read is `refused unreadable` (nothing exists yet). If the branch moved during the run (`stepBranchMoved`), the destination is left detached at the old tip and the message says not to switch it onto the branch blindly. The destination read-back also checks its HEAD equals the branch tip (`DestinationMatches` ignores HEAD).
- **The fast-forward** runs only when `origin/<default>` is a strict descendant of the local default (`merge --ff-only`, hooks off, no submodule recursion, never a merge) and is skipped with a warning, status still `moved`, when the merge would overwrite an ignored file, an ignored parent path, or an ignored file under a path the merge replaces by a file (case-folded under `core.ignorecase`). "Already at origin" is a step in `completed`, not a warning.
- **Fetch.** A real run fetches every remote once through `cleanup.Gather` (as `wt cleanup`; it updates remote-tracking refs, nothing else); `--dry-run` and `--no-fetch` never fetch, and a dry run's warnings say so.
- **Output.** Reasons, warnings and `completed` print in full (`cleanup.Flatten`: one line, control characters stripped, no cap) because a failure's reason carries the recovery text. Known limitation: `wt rescue` still truncates at 200 characters. The result is `docs/contracts/restore-root-result.*`, a flat envelope (held by `cmd/wt/restore_root_contract_test.go`).
- **The hint.** `rootclaim.Hint` is one line, ``run `wt restore-root` to move it and put the root back on <default>``, printed by `cmd/wt`'s `confirmLaunch` and the TUI's `launchGate` after the warnings' question (the shared-root menu's `ConfirmRoot`/`Choose` are deleted). It is hidden on the default branch, on a detached HEAD, and when `origin/HEAD` is unset (`Root.Default` comes from `worktree.DefaultBranch`; `wt restore-root` itself still works there).
- **Declared losses.** Ignored files and empty directories stay in the root and ignored files are never overwritten; file modes beyond the exec bit; the write window after the last claim and record checks; after the move the record's `Wt-Source-Path` is the root, so `wt cleanup` does not mark the new worktree preserved by it. Cost: one fetch of every remote, one extra fingerprint at release.

## Verification commands

Run the Go test block above before any commit, then exercise the installed binary:

```bash
wt -W my-feature -A claude           # named worktree + launch (a new name is created and said so)
wt model list [--json]               # every registry model and local model found, with live status
wt cloud-sync --dry-run              # plan a price and ollama-catalog refresh; changes nothing
wt smoke <model-id> [--only claude,codex] [--prompt P] [--timeout 5m] [--json]
make test-agents                     # live agent × model matrix, both routing modes (flips `wt litellm off|on`)
```

The full command list (`wt served`, `wt warm`, `wt cleanup`, `wt remove`, `wt model add|edit|rm|init`, `wt profile list`, `wt stats`, `wt profile list|show`, `wt start|stop`, `wt litellm`, …): [docs/internals/testing.md](docs/internals/testing.md#verification-commands).

> Verifying a branch's behavior requires building it first (`D=$(mktemp -d)`, then `go build -o "$D/wt" ./cmd/wt`) — `~/.local/bin/wt` is whatever was last `make install`ed and may predate the branch.

> **A built wt that must not touch this machine** runs with every path redirected. Any one left out reaches the real file:
>
> ```bash
> env -i PATH="$PATH" HOME="$D/home" WT_REGISTRY="$D/registry.toml" \
>   WT_LITELLM_CONFIG="$D/config.yaml" WT_LITELLM_RESTART_CMD=true \
>   WT_MTPLX_PIDFILE="$D/mtplx.pid" WT_REC_PIDFILE="$D/rec.pid" WT_SUSHI_PIDFILE="$D/sushi.pid" "$D/wt" model list
> ```
>
> This redirects files, not servers: a start, stop or probe still reaches whatever answers at the registry's `base_url`s, and `wt cloud-sync` still runs the real `ollama`. `cmd/wt`'s `TestMain` (through `lifecycle.IsolateProcessesForTest`) sets `WT_SUSHI_PIDFILE`, like every other process family's pidfile variable, to a path that does not exist.
