# wt worktrees, removal, rescue and restore-root

Internals reference for `wt/`, reached from [`wt/CLAUDE.md`](../../CLAUDE.md). Backticked paths are relative to `wt/` unless they start with `../`. The rules that must hold in every change are one-liners in CLAUDE.md; the mechanisms, rulings and test names behind them are here. Moved out of `wt/CLAUDE.md` verbatim (links re-based); the wording is unchanged.

## Cleanup classifier and removal (`wt worktrees`, alias `wt worktree`; `wt remove`)

`internal/cleanup` classifies every worktree, local branch and `origin` branch into proven / less_sure / unique_work / in_use from one snapshot and is **read-only** (apart from the `git fetch --prune <remote>` the commands run for every remote first, never prompting, which `--no-fetch` skips, it writes no ref, index or working file; it reads the `refs/wt/rescued/*` records `wt rescue` leaves (`ListRecords`, one `for-each-ref`) and lets a matching one make a clean rescued original removable (see "The record" under Rescue invariants); the merge-adds-nothing proof, `git merge-tree --write-tree`, may leave unreachable tree objects that `git gc` collects; the `changes-in-base` containment check and the diffstat run against throwaway `GIT_INDEX_FILE` copies, so the real index stays byte-identical — `GatherFacts`/`FillDetails` stage the gather: the list paints facts first and fills gates, ladder and PRs behind the first paint); `cmd/wt-session/cleanup.go` prints it (`--json`, `--plain`) or shows the tick list (`internal/tui/cleanup_list.go`), whose enter removes the ticked rows after a confirmation (`internal/tui/cleanup_confirm.go`; the list does not fetch on open, so its origin rows read `cannot_verify` on a GitHub-recognised origin (the fetch wording hangs on the PR-lookup gate; a non-GitHub origin's rows read `not_checked` and never name the fetch state) (`FetchResult.NotAttempted`, worded "not refreshed in this list" and naming no flag, on a terminal run with no fetch flags; a `--no-fetch` run leaves the zero `FetchResult` and names the flag in the reason, "origin was not fetched this run (--no-fetch)") and an origin branch is removed from the list (tick a proven row — an origin row is never ticked for you — and type `delete origin` at the confirmation, which `y` and the plain `delete` never grant) or, as the CLI path, with `wt remove origin/<name> --remote`). `wt remove` (`cmd/wt-session/remove.go`) names targets on the command line. Both go through one engine, `internal/removal`, **the only deletion code in wt**. `wt rescue` (`cmd/wt-session/rescue.go`, engine `internal/rescue`) is the copy-only counterpart: it creates, it never deletes (see "Rescue invariants"). Design: [../docs/superpowers/specs/2026-11-04-wt-cleanup-design.md](../../../docs/superpowers/specs/2026-11-04-wt-cleanup-design.md) (PR B as built: [../docs/superpowers/plans/2026-11-05-wt-cleanup-pr-b.md](../../../docs/superpowers/plans/2026-11-05-wt-cleanup-pr-b.md) and its rulings; PR C, origin removal: [../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-c.md](../../../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-c.md)); command reference: [docs/wt-cleanup.md](../wt-cleanup.md); operator pointer: guide 08 §9.

- **Every git call the classifier runs has `GIT_OPTIONAL_LOCKS=0`** (`cleanup.Git`): without it `git status` may rewrite the index's stat cache in the worktree it inspects, which broke "writes no index" until `wt rescue` compared a source's index bytes before and after.
- **`Snapshot` is a plain value tests edit by hand** (e.g. `s.Claims = nil` before re-`Classify`): derive from its fields on read (`HeldOn`) rather than caching a map built in `readClaims`/`Gather`, or the edit is ignored.
- **Fail closed.** A git error, an unresolved default branch, an unknown PR state or an unavailable gate is Unknown, never proven. `LookupUnknown` is the zero value of `Lookup`, so a missing map entry reads Unknown.
- **Deletion lives only in `internal/removal`**: `TestDeletionStringsOnlyInRemovalPackage` (a `go/ast` scan of every non-test file under `wt/`, with an explicit per-file allow-list for unrelated `os.Remove*` users) and `TestCleanupCmdContainsNoDeletion` (`internal/cleanup`, `cmd/wt-session/cleanup*.go`; also bans a `push` refspec `:<branch>` and `gh api -X DELETE`) and `TestRescueContainsNoDeletion` (`internal/rescue`, `cmd/wt-session/rescue*.go`; it bans the delete-flag shapes of `update-ref` and requires exactly one `"update-ref", ref, commit, ""` (create-only, the record's ref) in `internal/rescue/record.go`, checked by `riskyRescueSource`; `fileOpNever` also keeps both off the file-op allow-list). `TestDeletionStringsOnlyInRemovalPackage` is shape-based and needs no allow-list entry for the record. The command file is `remove.go`, not `cleanup_remove.go`, for that reason. Removal now also resets and switches the root (`internal/removal/root.go`, `ReleaseRoot`, for `wt restore-root`), only behind three proofs: an unchanged fingerprint, a verified copy and a record `cleanup.RecordCoversDirt` says still holds the root's index and working tree (or, with nothing uncommitted, an empty status). It refuses first when git repository variables (`GIT_DIR`, `GIT_INDEX_FILE`, ...) are set, when the root is detached, when the default branch is checked out in another worktree, when an index entry is assume-unchanged or skip-worktree (status cannot see its edit; so a sparse checkout is refused, failing closed), and it runs every git call with `core.fsmonitor=false` (a stale fsmonitor hook would hide an edit), and, last (after the record check), when the reset would delete or overwrite an ignored file (one inside a directory where HEAD tracks a file, at an index-deleted path, replacing a tracked directory, or under a directory-pattern-ignored directory holding paths HEAD tracks; names compared folded under `core.ignorecase` and, for case and Unicode normalization the volume aliases, by file identity on disk: ignored files are in neither the copy nor the record). It runs every git call in the root (never the caller's directory), removes exactly the untracked paths the copy carried whose content still equals the record (never `clean`), and runs its two writes, the reset and the switch (`--no-overwrite-ignore`), with `-c core.hooksPath=/dev/null -c submodule.recurse=false`; `TestRootMutationFunctionsAreExactlyTheAllowList` pins the functions that may reset, switch or delete files to `ReleaseRoot` and its helper, and `TestHardResetExistsNowhereOutsideRemoval` keeps `"--hard"`, `"reset"`, `"clean"`, `"checkout"`, `"restore"` and `"stash"` argv words out of every other package (the guards cover only those words). A failed reset or switch call is a `ReleaseFailed` with `Uncertain` set: git may have written part of the index or tree. `internal/rootmove` and `cmd/wt-session/restore_root*.go` are inside the deletion scan: `TestRootmoveContainsNoDeletion` bans `rootmoveBanned` (rescue's list plus `"--hard"`, `"reset"`, `"clean"` and any `"update-ref"`), with `TestRiskyRootmoveSourceBites` and `TestRootmoveIsInsideTheDeletionScanAndNeverAllowed` keeping the scan honest; rootmove only names `ReleaseRoot`.
- **A remote ref folds into the local row that tracks it** (`Row.Upstream`): the head's upstream when it is the same-named branch of its remote, else `origin/<name>` when the head has no upstream (exact refnames, so a case variant never folds); a gone upstream is `Upstream{Gone}` with no row. The folded remote row stays classified in `Report.Folded`, not `Rows`: **find a remote row through `Report.RemoteRows()`** (`Rescan`, `wt remove origin/<name>`), and list everything through `Report.AllRows()` (`Encode`, `Groups`, `--plain` and `--json` still show it as its own row); the terminal list renders the fold (`ListOrder` — the list's one order: root first, then local worktrees and branches by display name, then the remote-only rows, no headings — leaves a folded ref out of the remote-only rows, so a folded origin branch is removed with `wt remove origin/<name> --remote` or `o` on its local row, which resolves the folded ref via `originTarget`).
- **The base is `origin/<default>`**; the local default is only a fallback, and then every verdict is capped below proven (`capFallback`).
- **Weak signals are not proofs**: `git cherry` and patch-id equivalence (`WeakSignals`) show as less_sure, never proven (they pass a squash that was later reverted). `changes-in-base` is the proof they lack: ladder rung 6, tried only after `merge-tree` declines, reverse-applies the tip's change-set onto the base's tree through a throwaway index (`contained.go`) — content, not hashes, so a squash merge proves even after the base later edited the same file, while a later revert fails closed. A change-set that only adds lines to a file that stays is anchored by context: the same change read with `-U3` must reverse-apply too (`containedWithContext`), or a branch adding a line base holds elsewhere (`}`, a blank line) would prove; an edit right beside a squashed addition therefore reads not proven (unknown), the cost of the stricter rule.
- **Refs passed to `Prove`/`WeakSignals` are fully qualified** (`refs/heads/<b>`, `refs/remotes/<r>/<b>`) or a 40-hex id, so a tag never shadows a branch.
- **Min-age (`DefaultMinAge`, 10m) gates `same-commit` and `ancestor` evidence**: wt creates branches from a local main behind `origin/main`, so a new branch reads as ancestor-merged. An old branch whose reflog expired takes its age from `packed-refs`' mtime, so it reads fresh for 10 minutes after any packed-refs rewrite (clone, gc, a fetch that prunes a packed ref); accepted, it heals.
- **`wt worktrees --json` (alias `wt worktree`) carries the header's caveats in `notes`** (`cleanup.NoteLines`: lowered min-age, artifact protection off, no registry): a script acting on `rows` must read it, since with protection off no row has a `protected_artifact` blocker. The text header and `notes` come from the same function.
- **Evidence strings, reason and blocker codes are the JSON contract**: [../docs/contracts/cleanup-list.sample.json](../../../docs/contracts/cleanup-list.sample.json) + `cleanup-list.schema.json`, held by `cmd/wt-session/cleanup_contract_test.go`; change them only with the fixture.
- **`--min-age` has a floor** (`cleanup.MinAgeFloor`, 1m; less is a usage error); a value below 10m is named in the header.
- **Protected artifacts fail closed** (`protectedPaths`, `cmd/wt-session/cleanup.go`): a registry that did not load is `errRegistryUnavailable`; a malformed, unexpandable `~` or **relative** `local_path` is refused with an error naming the model (no tool agrees on a relative path's base). The listing still shows, with "artifact protection is OFF and removal is refused" in the header. Only a missing registry at the default (not redirected) path is "nothing to protect". The `protected_artifact` gate blocks both directions: an artifact in the worktree, or the worktree in (or equal to) an artifact.

**Removal invariants** (`internal/removal`; the rulings are in the PR B plan's note):

- **Rescan before acting.** Each item is re-classified by `cleanup.Rescan` immediately before it is touched (never a fetch; no `gh` for a worktree or branch, but a **remote** target asks `gh` live, once for who has the branch as head and once for who targets it); `Rescan` itself enforces the target's identity. A fresh status worse than `Saw`, a moved tip (`SawTip`) or worse losses than `SawLosses` (more dirt, unpushed or ignored entries; Ruling G) is `skipped_changed`, never an error.
- **Losses are raw in the classifier and effective in removal.** `Row.Losses` stays what the classifier counted (a preserved row still has `Unpushed > 0`). `Row.EffectiveLosses()` clears only `Unpushed > 0` and `DetachedUnique` of a row with `Preserved`; `-1`, `Dirty`, ignored files and `GatesUnknown` are untouched. `LossLines`, `ItemFromRow`'s `SawLosses`, the preview and the engine's force and loss checks read the effective view; `rescue.Preflight`/`Offered` and the `GatesUnknown` and `gitForce` reads stay raw (a second `wt rescue` of a preserved original must still be possible). `TestEveryLossesReadSiteIsLabelled` (with `TestLossesGuardBites`) (`internal/cleanup/losses_guard_test.go`, a name-keyed `go/ast` scan, no `go/types`) pins every function in `cmd/wt-session` and `internal/` that reads `.Losses`: a read needs a `// losses: raw, <why>` marker or must use `EffectiveLosses`, and the per-function counts are exact.
- **Exact refs, resolved paths.** The CAS uses the exact spelling from `for-each-ref` (`Row.Ref`); "checked out elsewhere" compares case-folded full refnames; paths go through `cleanup.ResolvePath` (`/var` vs `/private/var`). A `wt remove` argument matches a worktree path or exactly `refs/heads/<arg>` (a branch name also matches the worktree holding it; Ruling Q); `origin/<name>` (exactly) matches the origin row `refs/remotes/origin/<name>`, ambiguous with a local branch of that literal name.
- **A deleted branch's `branch.<name>.*` config is removed too** (`afterDelete`; `update-ref -d` leaves it, `git branch -D` does not), so a restore under that name starts without the old upstream. A failure is a warning, not an outcome change.
- **Branches go by compare-and-swap**: `git update-ref --no-deref -d <ref> <fresh tip>` after a fresh worktree list (`cleanup.HeldRefs`) shows no holder; a worktree that takes the branch in the window gets it back create-only. `update-ref` has none of `git branch -d`'s checks, so every guard is `branch.go`'s own. A branch is deleted unasked only when the branch alone is proven (`Row.BranchProven`, Ruling A); otherwise `retained_unmerged`. A branch with a sibling whose refname differs only in case is `retained_unknown` on every filesystem (on a case-insensitive volume `update-ref -d` removes both; Ruling X). A worktree that would need `--force` and holds submodules (an admin-dir `modules/`, even a leftover one, or any initialised module in `git submodule status`, including an embedded repository) is refused, and so is one whose check cannot be read: git skips its submodule check under `--force`. The restore line is `git branch <name> <sha>`, or the create-only `git update-ref refs/heads/<name> <sha> ""` for a name starting with `-` (it fails if the branch was re-created meanwhile).
- **Approvals are per item and sealed** (Rulings K-N): `Item.Approved` (`Needs{Confirm, Force, Delete}`) replaces any run-wide flag. An item reaches `Run` only unmodified from `ItemPreview.Confirmed(exactly its Needs)` or, for a worktree whose unmerged branch the user opted in to delete, `ConfirmedDeletingBranch`; previews are sealed too. `Run`/`Plan` refuse anything else ("invalid target: not confirmed").
- **Force scopes**: `Force` (`--force`) = lose a worktree's uncommitted changes or a detached HEAD's unique commits (`git worktree remove --force`); `Delete` (`-D`) = delete a branch not proven merged (unknowns about the merge verdict alone do not block it, identity/loss unknowns do; Ruling H); `Confirm` (`--accept-loss`, or the TUI's typed `delete`) = any non-proven item or any loss, mandatory on every path (Ruling P). No approval overrides a hard blocker (primary, current, locked, nested, operation in progress, protected artifact, and an open PR on an origin branch or one that targets it). A held item and the default branch are floors, not blockers: they need `--accept-loss`, and a branch not proven merged also `-D` (a default branch only when a remote default, not the local one itself, is the base).
- **Shared helpers, one copy each**: `removal.Headline`/`DetailLines` (the command's text and the tick list print the same loss, warning and restore-id lines), `removal.EncodeReport` (says whether the document is partial), `cleanup.IsFullCommitID`, `failWithEnvelope` in `cmd/wt-session/cleanup.go`, `isTerminalStream` and `writeResult` in `cmd/wt-session/prompt.go`. `wt remove --json` prints its error document for usage errors too (no target; a bad flag after `--json`). `cleanup.commonDir` is remembered per directory, so looping `HeldRefs` over worktrees costs one `rev-parse`.
- **Origin removal** (`internal/removal/remote.go`, the only code in wt that writes to a remote). Only a **proven** row of **origin**, or a fully read **less-sure** one with the loss approval too (`needsOf`: `Remote` plus `Confirm`; the gate skips the PR proof for it and refuses an Unknown row, unique work and every blocker); the engine refuses everything else (`invalidRemoteItem`: the ref must be `refs/remotes/origin/<safe name>`, no path, Saw proven or less_sure, a full sha; the default branch is `retained_default`). The PR proof the gate re-checks is an exact-head merged PR, or, for evidence `trees-match`, any merged PR into the default branch whose merge commit is in the base (a branch that moved on after its PR merged but whose whole tree equals the base's; the classifier's `remotePRRung` and `Snapshot.checkMerges` give the same answer). It needs its own approval, `Needs.Remote` (CLI `--remote`, TUI typed `delete origin`): required even for a proven item, covers nothing else, and `--yes`, `y`, `--accept-loss`, `-D`, `--force` and the plain `delete` never grant it. The row is proven only when origin was fetched cleanly *this run* (`--no-fetch`, which leaves the zero `FetchResult` and names the flag in its row reason, or a terminal list that fetched nothing — it does not fetch when it opens; that state is `FetchResult.NotAttempted`, worded "not refreshed in this list" and naming no flag, unless `--fetch` or the list's `F` ran — a failed fetch or no origin makes it `cannot_verify`, and a non-GitHub origin's rows read `not_checked` and never name the fetch state (the fetch wording hangs on the PR-lookup gate); the fetch result is carried by `GatherInputs.Fetched` so a refresh keeps it), a live `gh pr list --base <n>` (made by `Gather` only when `GatherInputs.OriginRows` is set: the list and `wt remove origin/...` set it, `wt remove <local>` does not; `Rescan` re-asks for a remote target only; any head repository, no own-repo filter; truncation or error is unknown) finds nothing targeting it, and a MERGED PR into the default branch has `HeadRefOid` == the tip with its merge commit in the base (the classifier's answer, and `remoteGate` asks git again with `merge-base --is-ancestor` before the push). Origin-only checks never apply to another remote's row, and neither do the bare-name PR lookups (`Snapshot.PRs` and the open PRs `dependants` finds by base describe the repository origin points at): another remote's row is judged on git's proofs, so a PR found for `origin/foo` never informs `upstream/foo`; and because nothing asks gh about another remote, its pull-request state is unknown, so the row is at most less_sure with `not_checked` (fail closed, never proven by git alone; a dedicated code, not `cannot_verify`: no gh lookup failed, so present.go's gh wording and the header's gh line leave it alone). Order in `remoteAct`: preflight `git ls-remote --exit-code origin refs/heads/<n>` (exact refname, one line, sha == the listed tip, else `retained_moved`/`retained_unknown`, no push) then `git push --porcelain --no-verify --force-with-lease=refs/heads/<n>:<sha> origin :refs/heads/<n>`: the explicit sha makes the server the compare-and-swap (a bare lease would use the tracking ref, which a fetch may have moved), never `--force`, `-f`, a `+` refspec or a lease without a sha. Git runs with `cleanup.NonInteractive(dir)` env and a 120s limit. The result is judged by a fresh ls-remote, never the push's status (gone = `deleted`; still there = `retained_unknown`, or `retained_moved` on a lease refusal or another sha); `DeletedTip` is set before the push and kept while the ref is not proven present. A same-named local branch is not touched (a warning names it). An open race the tool cannot close: a PR opened against the branch after the last `gh` read.
- **Fetch is per remote** (`cleanup.Fetch`): `git fetch --prune <remote>` for each remote (skipping `remote.<r>.skipFetchAll` for every remote but origin, which is always fetched), `FetchResult.OK` meaning origin's, `Remotes` each one's; `Git.Env` carries `cleanup.NonInteractive(dir)`: `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never` and `GIT_SSH_COMMAND=ssh -o BatchMode=yes` only when neither `GIT_SSH_COMMAND` nor `core.sshCommand` is set (a user's own ssh command is left alone). Origin is fetched first and alone (120s); the other remotes then run concurrently under `otherFetchTimeout` (30s). With no origin `fetch.skipped` is `no origin remote` and `fetch.remotes` still lists the others. The header and `fetch.remotes` in the JSON name each remote.
- **Outcomes are frozen wire strings**: worktree `removed|skipped_changed|refused|failed|not_requested`, branch `deleted|not_attempted|retained_unmerged|retained_moved|retained_checked_out|retained_default|retained_unknown` ([../docs/contracts/remove-result.schema.json](../../../docs/contracts/remove-result.schema.json), held by `cmd/wt-session/remove_contract_test.go`). A deleted (or possibly deleted) branch's full sha is `Outcome.DeletedTip` / `branch_tip`, recorded before `update-ref` (or the origin push) runs (Rulings I, J). A remote item reuses them: `kind: remote`, `worktree` `not_requested` once acted on (`refused`/`skipped_changed` at a gate, branch `not_attempted`), `branch` describing the origin branch.
- **The result never drops an item** (Ruling O): an off-contract value becomes the `invalid` sentinel with an envelope `error` beside `items` (a partial report; treat every listed change as made).
- **`wt remove` exit codes**: 0 everything named removed (a kept unmerged/held/default branch of a removed worktree is fine), 1 could not start (no match or ambiguous argument, registry failed to load, `--min-age` below 1m), 2 some item refused/skipped/failed or a moved/unknown branch, 3 approval missing (no `--yes` and no terminal, or the prompt declined). The y/N prompt only replaces `--yes`; the tick list exits 0 after a run with refusals (Ruling R).
- **TUI keys** (`cleanup_list.go`): `space`/`a` tick, `enter` removes the ticked rows (the confirm says "ticked"), `F` fetch + refresh, `q` quit; `i` opens the row's **detail screen** (`detail.go`, `cleanupPhaseDetail`) and `x`, `d`, `o`, `r`, `R` open that same screen unarmed — the second press there is the action, which is `x` the selected row alone ("selected"), `d` that plus its unmerged branch (seeded on the confirm), `o` only its origin ref, `r` rescue or `R` restore root. The screen lists only the actions whose predicates hold (`detailActions`, the same predicates as `rowKeys`) plus `esc`; `x`/`d`/`o` confirm on it (a single-row confirm renders `detailBlock`, the same renderer as `i`) and `esc` there goes back to the screen, while `r`/`R` keep quitting for their hand-off. **The list has no headings**: `cleanup.ListOrder` orders it (root first, then local worktrees and branches by display name, then remote-only rows) and the verdict cell is one short word (`verdictWord`: `safe`, `check`, `work`, `locked`). **Hard stops lock a row, floors never lock a worktree or local branch** (`cleanupLocked`, `TestCleanupLockedOnlyForHardStops`): primary, current, locked, operation in progress, nested, protected artifact, an open PR on (or targeting) an `origin` branch and a missing directory lock, as does any `in_use` row and any remote row that is not a proven `origin` branch (it shows `[-]`); the default branch, a held row, root drift and no default branch only lower the verdict (tick them, type `delete`). The launch selector answers `x d o r R` through the same `RemoveFuncs` (its `/` filter owns every rune while open; a PR fill never swaps the funcs under a flow). While a report is still filling (the facts-first load), `rowKeys` omits `x d o r R` and manage-mode `enter`, and each handler refuses with its nil-RemoveFuncs status (`m.filling()`). No automatic cleanup anywhere: nothing runs at agent exit and the root is never switched for you.
- **The detail screen and a deferred fill** (`detail.go`, `cleanup_list.go`): a fill's removal-funcs build is held in `pendingRM` while a flow is open, and `esc` on the detail screen applies it (without that, `x d o r R` stay refused after a fill landed mid-screen). A report swap goes through `settleDetail`, which re-points the open screen at the same row of the new report or closes it; a new path that swaps `m.report` must call it. `cleanup.ReadRowDetail` reads a bare row or an unborn HEAD as empty with `RowDetail.Note`, never as an `Err`.
- **TUI**: typed `delete` for anything not proven (`y` only when every item is proven); `delete origin` (reachable from `wt worktrees` once a fetch proved the row — `--fetch` or the list's `F`; tick it, type `delete origin` at the confirmation; `wt remove origin/<name> --remote` is the CLI path) when any ticked item is an origin branch (an `ORIGIN BRANCHES` group and a banner with the count and the audience; the plain `delete` and `y` never run it; each item still gets only its own approvals, so Remote reaches origin items alone); the `-D` toggle is per item, off by default, offered only where the engine says so (Ruling S), and applies only to an entry whose decision lines are on screen; the prompt always states the item count and the force and `-D` counts, plus "N not shown" (Ruling U). While a run is in flight keys, ctrl+c, SIGINT and SIGTERM wait; every outcome is logged as it arrives and printed after the alt screen closes (Ruling T).

**Rescue invariants** (`internal/rescue`, `cmd/wt-session/rescue.go`; PR D; plan [../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-d.md](../../../docs/superpowers/plans/2026-11-07-wt-cleanup-pr-d.md)):

- **Copy-only, never deletes.** `wt rescue <worktree-path-or-branch>` creates branch `rescued/<branch or directory>` (`--to NAME` is the full branch name) at the source's exact HEAD in a new worktree under `.worktrees/` (`worktree.CreateAt`: full commit id only, `--no-track`, never reuses a branch or worktree, `worktree.CheckNew` is its read-only twin). It carries unpushed commits (they are on the branch), staged changes (`diff --cached --binary --full-index --no-renames`, `apply --index`), unstaged changes (same, `apply`) and untracked non-ignored files (O_EXCL, mode kept, symlinks recreated, no path leaves the destination). Ignored files are not carried; the count is reported. It never removes or changes the original (a later `wt remove` has a small write window between its re-check and `git worktree remove`). `unpushed` counts remote-tracking refs only and the dirt is copied, not moved, so on its own the source still reads unique_work; what makes an original removable is the record, which `internal/cleanup` reads (see "The record"): a *clean* one (commits only) reads proven (PR B1), a dirty one (staged, unstaged or untracked changes) reads `less_sure` and takes `--accept-loss` only while its index and working tree equal what the record captured (PR B2). Any other dirty original is unchanged: unique_work, `--accept-loss --force -D`.
- **The source is only read.** All source git runs with `GIT_OPTIONAL_LOCKS=0` and `core.fsmonitor=false` (`internal/rescue/git.go` wraps `cleanup.Git`, whose `Config`/`Env` fields carry them; there is no second git runner). A fingerprint (HEAD, the branch ref HEAD names, the index's staged content via `ls-files --stage` not its file bytes, the porcelain-v2 status, a hash of every path it names; other refs and worktrees are deliberately out, a parallel session or fetch must not abort a rescue) is taken at `Preflight`, re-checked at the start of `Execute` (changed: `refused`, nothing created) and after the copy (changed: `failed`, `source_changed_while_copying`). Every refusal test asserts the fingerprint and the refs/worktrees are unchanged.
- **Every refusal is before anything exists** (`Preflight`, codes in `rescue.Codes`): not a worktree, primary (`wt rescue` refuses the primary checkout and names `wt restore-root`; root mode, `Engine.ForRoot`, skips `primary` and `nothing_to_keep`), nothing to keep, unreadable gates, operation in progress, unmerged paths, skip-worktree/assume-unchanged, submodule change, a path both staged and modified, intent-to-add, nested repository, special file, line-ending conversion (`checkLineEndings`: one `ls-files --eol -z` over the whole index with no path arguments, filtered in Go to the changed paths, so no ARG_MAX limit; judges the attr columns with `core.autocrlf`/`core.eol`, so an LF file that a `text` attribute plus `core.eol=crlf` would write as CRLF is refused too, naming only the affected changed paths), a `filter`, `ident` or `working-tree-encoding` attribute on a changed file (`content_filter`; `checkContentFilters` sends its paths to `check-attr --stdin -z`, never the argv), more than 20000 untracked files or 512 MiB of untracked files plus changed tracked files together (`too_large`; a changed tracked file counts as the larger of its working-file size and its index or HEAD blob, `blobSizes`, read from NUL-delimited `ls-tree -r -l -z HEAD` and `ls-files -s -z` listings so any path name is covered; a staged rename counts once, at the larger of the old path's HEAD blob and the new path's blob; a staged deletion of a big file counts), name unavailable (names `--to`; no silent suffix), a count of unpushed commits that cannot be read or contradicts the gate (an error, exit 1; `Counts.Commits` is never a silent 0). Current, locked and held sources are allowed (held gets a warning). The fingerprint is taken **before** `readWork` and again after it; a difference is `source_changed` (a change during the reads is never baked in).
- **The record (`refs/wt/rescued/<id>`) is written after the verified copy; `internal/cleanup` reads it for clean originals (B1) and, while they still equal the record, dirty ones (B2).** After `verify` passes, `buildRecord` (`internal/rescue/record.go`) makes two commits: I (the source's index tree, built in memory by `dirtsnap.IndexTree` from `ls-files --stage -z`, parent the source's HEAD; rescue never runs `git write-tree`, which would rewrite the source's raw index file) and W (the working-state tree from `dirtsnap.Build`, parent I); then `Execute` re-takes the source fingerprint (after the record's reads; seam `beforeRecordRef`) and, only if it equals the one the copy was verified against, `createRecordRef` creates the ref `refs/wt/rescued/<first 16 hex of W>` with one create-only `update-ref` (`RecordRefPrefix`; after a change only unreferenced objects are left, for gc). The record's git runs with `core.hooksPath=/dev/null` (a reference-transaction hook must not refuse it). `dirtsnap.Build` reads a path below a symlink, a file or a missing directory as absent (git's `has_symlink_leading_path`); `dirtsnap.IndexTree` differs from `write-tree` on an intent-to-add entry, so a caller refuses i-t-a first. The commits carry `Wt-*` trailers and a fixed identity, so no git config is needed. Any failure (unreadable or changed source, `ErrUnsupported`, `ErrTooLarge`, a git error) is one `record_not_written: ...` warning (`RecordWarningPrefix`) and the rescue stays `moved`. `internal/dirtsnap` builds the trees with no temporary index or file and has no deletion code. The result carries it as `record {ref, commit}` (additive in the schema) and the text output as one `record:` line. `internal/cleanup` reads it (the reading side, PR B1): `ListRecords` (`records.go`) parses every ref under `refs/wt/rescued/` (the cleanup package repeats the ref prefix and trailer keys, it cannot import `internal/rescue`); `preservedOf` (`preserved.go`) matches one to a branch or detached worktree row only when the ref is `refs/wt/rescued/<first 16 hex of its commit>`, `Wt-Version` is 1, source path, ref (`detached` for a detached HEAD) and head equal the worktree's, the record commit and its parent exist, the worktree has no dirt (or, B2, its dirt is covered, below), no gates error and no hard blocker, and `rev-list --count <HEAD> --not --remotes <record ref>` is 0. The classifier then applies it (`Row.Preserved`) in the clean case (B1) only when the row's own commits are the uncovered part: no ladder evidence, raw `Unpushed > 0` (branch) or `DetachedUnique` (detached), the fresh branch tip equals `Wt-Source-Head`. The row gets evidence `rescued` and the informational reason `preserved` (`judge.info`, a fifth slot: it never lowers the status) and can read `proven` (clean case); `wt remove <path> --yes` then removes it and its own branch (`BranchProven`) with no other approval. Everything else keeps its usual effect: PR checks (`open_pr`, `pr_unknown`, `pr_head_moved`), `base_is_local`, ignored files (`less_sure`, `--accept-loss`). `Rescan` lists records afresh; a listing failure degrades to "no records" (a `Rescan` error is `refused`). A malformed, unparsable, stale or object-missing record is ignored and the row reads as before. **Dirt (B2)**: `preservedOf` also accepts a dirty row when `dirtCovered` (`internal/cleanup/dirt.go`) holds: HEAD equals `Wt-Source-Head` (the chain is source head <- I <- W, so it is `W^^`, not `W^^^`), no unmerged paths, no skip-worktree/assume-unchanged flag, then `git diff-index --cached` against I (not `dirtsnap.IndexTree`, which would need the raw index; the index file is never rewritten) and `dirtsnap.Build` of the working tree equal to W's tree. The limits (`DirtMaxFiles` 20000, `DirtMaxBytes` 512 MiB) are duplicated from rescue's and pinned equal by `TestDirtLimitsMatchRescue` (cleanup may not import rescue); a state over them reads not covered. `Preserved.CoversDirt` is true then, and `Row.Preserved` attaches to a dirt-covered row independently of ladder evidence (a merged or pushed branch keeps its own evidence); the reason `preserved` is then weak, so the row is `less_sure` (open PR still gives unique_work, `pr_unknown`/ignored files/local base stay), `EffectiveLosses` also clears `Dirty`, and `Row.Tickable` stays proven-only so such a row is never default-ticked. `row.Losses.Dirty` stays raw. Removal: `Engine.worktreeAct` (not the gate: the preview would pay a second `Rescan` per row) does one more `rescan` right before `git worktree remove` when `fresh.Preserved.CoversDirt`; `coverLapsed` compares record, tip, blockers, status and losses with the item as previewed, and a change is `skipped_changed`, while a `Rescan` error there is `refused`. `gitForce` is recomputed from the raw `Dirty`, so the user passes no `--force` yet git gets `worktree remove --force` (the covered files are in the record). The preview adds the note `uncommitted changes are kept in <ref> (copy: <path>)`. Declared losses: ignored files, file modes beyond the exec bit, empty directories, and writes in the window between the re-check and `git worktree remove`. Cost: a covered-dirt row hashes its changed files on every `Gather` and `Rescan`, and once more before removal. Clean initialised submodules are not seen by the classifier's dirt checks; `submodulesIn` still refuses them at removal.
- **Hooks are off, modes are copied.** `worktree.CreateAt` runs `git worktree add` with `-c core.hooksPath=/dev/null` (a hook must not rewrite or fail the checkout); `Preflight` warns when a `post-checkout` hook exists (`postCheckoutHookWarning`). After `git apply`, `setFileModes` chmods each changed tracked file to the source's exact mode (apply writes `0666` minus umask). `CreateAt` returns typed errors: `*NotCreatedError` (`NameUnavailable` for a `CheckNew` refusal; nothing was made, so `Execute` reports a `refused` `name_unavailable` and never `BranchKept`/`Created`) and `*AddFailedError` (`BranchLeft`/`DirLeft`: absent just before the add, present after, so only this call's own leftovers are claimed).
- **`Plan.SkipStartRecheck()`** (sets the unexported `skipStartRecheck`): the `--yes` path (no prompt between `Preflight` and `Execute`) reuses Preflight's fingerprint and skips `Execute`'s start re-read (one fewer hashing of every changed file); a prompt keeps the re-read. The after-copy comparison always runs. `cmd/wt-session`'s `afterRescueConfirm` (a no-op test seam between the confirmation and `Execute`) lets `TestRescueStartRecheckDependsOnWhetherAPromptWasShown` edit the source there and see which path caught it; the rescue package exports no observation hook.
- **Known limit, `CreateAt`'s microsecond window**: a branch someone creates between its pre-add look at the name and `git worktree add` is indistinguishable from the add's own leftover, so a failed add can claim it as `BranchLeft`. Untestable without a race; deliberately not changed (the code comment in `internal/worktree/createat.go` says the same).
- **Verify before claiming `moved`**: the destination's `status --porcelain=v2 -z` must equal the source's byte for byte and every path it names must match in kind, mode, content and link target; directories the copy created get the source's modes (applied last, and best effort on a failed untracked copy, so a kept half-built worktree has them too) and are compared too.
- **A failure after the destination exists keeps it** (`created` true, the path in the reason; `branch_kept` when `CreateAt` failed after making the branch): there is no rollback, because the only rollback is a forced worktree removal of a directory holding carried work. `wt remove` clears it with its own proofs.
- **`--dry-run` never fetches** (`git fetch` rewrites remote-tracking refs); its `warnings` say the last fetch was used. The list's `r` key stops the signal forwarding (`runRescue`) before the rescue prompts, so Ctrl-C and SIGHUP work again; the forwarding is also released if the list panics.
- **Exit codes**: 0 moved (or `--dry-run` would), 1 could not start, 2 refused or failed, 3 approval missing (no `--yes` and no terminal, or declined). Outcomes `moved|would_move|refused|failed` and the codes are the JSON contract (`docs/contracts/rescue-result.*`, `cmd/wt-session/rescue_contract_test.go`).
- **The list's `r` key** (`internal/tui/cleanup_list.go`, offered by `rescue.Offered` from the row alone) quits the list program and `RemoveFuncs.Rescue` runs the same executor (`rescueRow`) on the real terminal; `RunCleanupList` then re-enters the list from a re-read report (`RemoveFuncs.Refetch`, so it fetches) — the same for `R` (`RemoveFuncs.RestoreRoot`, offered by `rootmove.Offered`). A hand-off that changed nothing (declined, exit 3; refused before anything was created, exit 2 with a refused outcome) or finished returns a `tui.HandOffNote` (`cmd/wt-session`'s `rescueHandOffResult`/`restoreRootHandOffResult`) and the list re-enters with its text on the status line; a failure midway, could not start (exit 1) or a failed re-read ends the session and surfaces. Every removal outcome prints exactly once: the unprinted ones are flushed before each hand-off and the rest at session end; the picker's `r`/`R` end its session instead (`finishRowSession`, which flushes first and returns the note's own `Err`). In the picker ctrl+c cancels a confirm and waits in a run (only a list at rest quits); an OS signal during a picker run is remembered too and wt quits once the run's outcomes have printed — the picker's program forwards its signals to its row list, the manage list's own rule (#577).
- **`wt restore-root` reuses the engine in root mode.** `Engine.ForRoot` takes the primary checkout as the source, skips `primary` and `nothing_to_keep`, and plans a detached destination (`worktree.CheckNewDetached`); `ExecuteInto(plan, dest)` carries, verifies and records into a worktree the caller already made (`worktree.CreateDetachedAt`); `Plan.SourceUnchanged`, `HasDirt` and `UntrackedPaths` are the proofs `removal.ReleaseRoot` is handed, and `Plan.DestinationMatches` is the read-back. The three proofs for the release are the verified copy, the record and an unchanged fingerprint, ending in `cleanup.RecordCoversDirt`; the recovery table is `rootmove`'s `recovery` (below; a failed destination switch says to `git switch <branch>` there, except when the branch moved during the run, when it says not to switch blindly). The write window between the last check and the reset is declared.

**Restore-root invariants** (`internal/rootmove`, `cmd/wt-session/restore_root.go`, `internal/removal/root.go`; plan [../docs/superpowers/plans/2026-11-08-wt-restore-root.md](../../../docs/superpowers/plans/2026-11-08-wt-restore-root.md), spec [../docs/superpowers/specs/2026-11-08-wt-restore-root-design.md](../../../docs/superpowers/specs/2026-11-08-wt-restore-root-design.md) with its Amendments):

- **What it does.** `wt restore-root [--to DIR-NAME] [--dry-run] [--yes] [--json] [--no-fetch]` moves the root's branch (the same branch, not a copy) into a worktree under `.worktrees/` and puts the root on the default branch. `--to` names only the directory. `Preflight` reads only; `Execute`: detached `worktree add` (`CreateDetachedAt`), `ExecuteInto` (carry, verify, record), `removal.ReleaseRoot`, `git switch --no-overwrite-ignore <branch>` in the destination, the fast-forward, a read-back of both checkouts; `moved` is claimed only after it. A root with nothing uncommitted skips the copy and the record; its release needs an unchanged fingerprint and a clean status.
- **Every refusal is before anything exists** (`Preflight`, `rootmove.Codes`, 31 entries: rescue's except `primary` and `nothing_to_keep`, plus `detached_root`, `already_default`, `default_in_worktree`, `no_commit`, `release_refused`, `release_failed`, `switch_failed`, `no_default_branch`, `ignored_collision`, `record_not_written`, `worktrees_not_ignored`; `TestCodesCoverEveryCodeRootmoveEmits` holds the list to the sources). Order: the primary checkout, `detached_root`, `no_default_branch` (none resolves with `cleanup.ResolveBase`, or only `origin/<d>`), `already_default`, `default_in_worktree`, `worktrees_not_ignored` (the root must ignore `.worktrees/`; the refusal prints the one-line remedy and nothing is written to the repository), `hidden_index_flags` (assume-unchanged or skip-worktree; a sparse checkout is refused), rescue's root-mode refusals, then `ignored_collision` (`removal.RootIgnoredAtRisk`, or an ignored file at a path the default tracks). A held root refuses nothing at `Preflight`: one `root_held: ` line (`HeldWarningPrefix`) names the holder and rides the plan's `warnings`, never a `code`. The command layer (`cmd/wt-session/restore_root.go`) then needs the person to say so: the y/N prompt on a terminal, or `--yes --accept-loss`; `--yes` alone with a held root is exit 3 (approval missing), nothing changed. Nothing checks the claims again after `Preflight`. `already_default` is outcome `refused` with exit 0. Exit codes: 0 moved, would move or `already_default`, 1 could not start, 2 refused or failed, 3 approval missing.
- **`removal.ReleaseRoot` is the only place the root changes.** Gate order: inputs, the fingerprint, the status, hidden index flags, the record check (`cleanup.RecordCoversDirt`), the ignored-files check last. Every git call runs in the root (never the caller's directory) with fsmonitor off; reset and switch run with hooks and submodule recursion off. A carried path the reset restored from HEAD is skipped; empty directories left by the removal stay. `*ReleaseRefused` touched nothing; `*ReleaseFailed` (`Uncertain` for any reset or switch call that errored) is `release_failed`. Execute re-checks the fingerprint, never the session claims (nothing checks them again after `Preflight`'s read); the write window after the last check is declared.
- **The recovery table** is `run.recovery` in `internal/rootmove/execute.go`: every `failed` reason ends with where the root, the new worktree and the work are and how to finish by hand (a failed root switch names both `git switch <default>` in the root and `git switch <branch>` in the destination). Nothing is rolled back. `restoreRootRun` holds SIGINT/SIGTERM/SIGHUP (`holdSignals`, `signal.Stop` on its own channel) from the confirmation until the result is written and reports a received one after the result; git children in the terminal's process group still get a Ctrl-C (the step fails with its row). A move killed from outside (SIGKILL, power loss) is recovered by the same table; a half-built `.worktrees/<name>` is cleared with `wt remove <path> --force --accept-loss`. A start re-check that cannot read is `refused unreadable` (nothing exists yet). If the branch moved during the run (`stepBranchMoved`), the destination is left detached at the old tip and the message says not to switch it onto the branch blindly. The destination read-back also checks its HEAD equals the branch tip (`DestinationMatches` ignores HEAD).
- **The fast-forward** runs only when `origin/<default>` is a strict descendant of the local default (`merge --ff-only`, hooks off, no submodule recursion, never a merge) and is skipped with a warning, status still `moved`, when the merge would overwrite an ignored file, an ignored parent path, or an ignored file under a path the merge replaces by a file (case-folded under `core.ignorecase`). "Already at origin" is a step in `completed`, not a warning.
- **Fetch.** A real run fetches every remote once through `cleanup.Gather` (as `wt worktrees`; it updates remote-tracking refs, nothing else); `--dry-run` and `--no-fetch` never fetch, and a dry run's warnings say so.
- **Output.** Reasons, warnings and `completed` print in full (`cleanup.Flatten`: one line, control characters stripped, no cap) because a failure's reason carries the recovery text. Known limitation: `wt rescue` still truncates at 200 characters. The result is `docs/contracts/restore-root-result.*`, a flat envelope (held by `cmd/wt-session/restore_root_contract_test.go`).
- **The hint.** `rootclaim.Hint` is one line, ``run `wt restore-root` to move it and put the root back on <default>``, printed by `cmd/wt-session`'s `confirmLaunch` and the TUI's `launchGate` after the warnings' question (the shared-root menu's `ConfirmRoot`/`Choose` are deleted). It is hidden on the default branch, on a detached HEAD, and when `origin/HEAD` is unset (`Root.Default` comes from `worktree.DefaultBranch`; `wt restore-root` itself still works there). A launch in a drifted-root repository names the drift once, through `confirmLaunch`'s warning (`root is on <b>, not <d>` or `root is detached`) and this hint; `runLaunch` adds no second note. A detached root gets no pointer, because `wt restore-root` refuses a detached root — `Hint` withholds it there.
- **Declared losses.** Ignored files and empty directories stay in the root and ignored files are never overwritten; file modes beyond the exec bit; the write window after the last pre-release checks; after the move the record's `Wt-Source-Path` is the root, so `wt worktrees` does not mark the new worktree preserved by it. Cost: one fetch of every remote, one extra fingerprint at release.
