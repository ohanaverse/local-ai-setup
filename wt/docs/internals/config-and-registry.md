# wt config, LiteLLM routing state, and the registry

Internals reference for `wt/`, reached from [`wt/CLAUDE.md`](../../CLAUDE.md). Backticked paths are relative to `wt/` unless they start with `../`.

## Config (Go)

`~/.config/agent-wt/config.toml` (TOML) is wt-owned and holds **only Agents, DefaultTag, the `[litellm]` table (the read-only fallback for the proxy pair — the pair lives in the wt-model home, `~/.config/wt-model/`) and the `[launch]` table** (`config.LaunchState`; its `exit_prompt` key is tolerated and ignored — parsed and round-tripped by a save, validated and consulted by nothing, one note per process when non-empty). Providers/Models live in the registry (below); nothing that writes `config.toml` touches them.

Key helpers: `Dir()` (config dir), `WriteFileAtomic`, `OllamaBaseURL` (`http://localhost:11434`), `FirstTag(s, fallback)`.

**Concurrent writers.** `config.toml` has two writers after startup: the `wt config` editor (Agents/DefaultTag on its Agents tab; the `[model-server]` table through `modelmode`'s config step on its Mode tab), `wt-model setup` (the `[model-server]` table through `modelsetup`'s config step on its Setup tab) and `Load`'s one-time migrations. The `[launch]` table (`LaunchTable`) is hand-edited and no wt command writes it; the writers above carry it through unchanged, and `writeConfigFile` saves the file 0600 while the `[litellm]` table holds an `api_key` or `[model-server]` an inline `token`, never loosening an existing stricter mode. The proxy pair is no longer one of them: `SetProxy` (`proxyhome.go`) is the one writer of the `~/.config/wt-model/` home, the flock behind `wt-model litellm set` and `wt litellm set`. None may blind-write a possibly-stale snapshot: the editor goes through `(*Config).PatchSave(apply func(fresh *Config))` — flock on `config.toml.lock` (`WithLock`), re-read fresh under the lock, `apply` mutates only its own fields. `Load`'s migrations use `lockedApply(apply func(fresh *Config) (bool, error))`, the same pattern plus a "did anything change" return so it only writes (and prints its notice) when a fixup fired. `Save(cfg)` (also locked) is only for a `Config` known to be fresh (tests, one-shot tools); anything holding a `Config` across an await/goroutine/process boundary must use `PatchSave` or `lockedApply`.

**The `[model-server]` table** (`internal/config/modelserver.go`). `ModelServerState` holds `mode` (`native`, `local`, `remote`; empty is unset, which a launch refuses or, on a terminal, answers by opening the `wt config` Mode tab), `url`, `token_file` and an inline `token` that nothing authenticates with and `Problems()` reports; the four keys are `omitempty`, so an all-empty table is removed on save. The session reads it through `LoadSession`; the one writer is `UpdateModelServer(change)`, reached only through the `ConfigStore` seam of `modelmode` (the `wt config` Mode tab) and of `modelsetup`, which widens it (the `wt-model setup` Setup tab); the hand-edited route still works. Two entry points tolerate what `Load` does not. `ReadModelServerFile` never errors: it decodes the file into a generic map to find a syntax error (`ParseErr`, and nothing else is read) and then decodes the table alone (`TableErr` for a decode error inside it), so a wrong-typed key elsewhere in `config.toml` never hides the table. `UpdateModelServer` is stricter: under the config lock it refuses any decode error, a syntax error or a type error elsewhere in the file, with the file untouched, because the writer re-encodes the whole struct and would drop what it could not decode. The mode a session acts on is not this table alone: `modelclient.ResolveMode` combines it with `WT_MODEL_MODE` and the `WT_MODEL_*` endpoint variables ([wt-session.md](../wt-session.md)).

**Schema migrations.** `migrateConfigSchema` (`internal/config/migrate.go`) runs on every `Load` with self-extinguishing fixups: rename `google`→`agy` in agent refs; ensure an `agy` agent; rewire an existing `opencode` agent to ollama only; detect a legacy `[gateway]` block, print a one-time notice, and let the next save drop it (its url/api_key are not imported — use `wt-model litellm set --url URL --api-key KEY`). Provider/model fixups are intentionally absent (the registry owns that data).

Full data model: [docs/superpowers/specs/2026-08-14-model-registry-data-model-design.md](../superpowers/specs/2026-08-14-model-registry-data-model-design.md).

> **Invalid-config repair.** `wt config` launches even when `config.toml` fails validation, so the editor can repair it. Other launch paths exit early on config errors. The editor shows the error as its status line; when the repair is not in `config.toml` at all — a provider or model row is in `registry.toml` — it appends `config.RegistryFixHint(err)`, the same hint `configError` gives the commands that refuse to run (#209: one source for the wording). A save refused by validation appends it too. The status is wrapped to the terminal width (`statusBlock`) and the list is re-fitted after every message (`fitList`), because a terminal cuts a too-wide line at its right edge and the hint is the end of the line.
>
> **One function chooses the repair hint.** `config.LoadFixHint(err)` is the hint for any config load or validation error, and `configError` (`cmd/wt-session/helpers.go`) and `wt stats`' `--family` note (`registryNote`) both ask it — never write a hint out at a call site (#291: `wt litellm` did, and sent every registry problem to `wt config`). `wt config` edits `config.toml` and nothing else, so it is the hint only when nothing marks the error as a registry problem:
>
> | Error | Hint |
> |---|---|
> | `ErrRegistryMissing` | none — the error itself names `wt-model model init` |
> | `ErrRegistryLink` (a link that leads nowhere) | `fix the link or move it aside` |
> | `ErrRegistryFile` (the path cannot be examined — a file where its directory should be, a directory wt may not search — or the file cannot be read or is not TOML; the error names it; the reader and `config.UpdateRegistry` both mark it) | `fix that file by hand` |
> | `ErrRegistryTopLevel` (a top-level key a write will not accept; only `config.UpdateRegistry` returns it) | `fix that file by hand` |
> | `ErrLocation` (a location that is set and is not `local`/`cloud`) | `fix the entry in <registry path>` |
> | `ErrRegistryEntry` (any other provider or model row `Config.Validate` rejects: an empty or repeated id, no `model_name`, a model whose provider has no row, no location on the model or its provider) | `fix the entry in <registry path>` |
> | anything else (a `config.toml` parse error, `default_tag`, an agent entry) | ``run `wt config` to repair`` |
>
> A new kind of registry error needs a sentinel and a case in `RegistryFixHint`, or it falls through to the `wt config` hint; a new check in the provider or model loop of `Config.validate` is wrapped with `registryEntryError`. `TestLoadFixHint` (`internal/config`) pins the table; `TestLitellmLoadErrorNamesTheRepairThatWorks` and `TestStatsFamilyNoteNamesTheRepairThatWorks` (`cmd/wt-session`) pin it at the commands; `TestRegistryRowErrorNamesTheRegistry` does the same for a row error, which is a validation error and not a load error.

`wt config theme [list|show|set|unset]` and `wt config path` — see [docs/wt-config.md](../wt-config.md).

## LiteLLM routing state (wt-owned)

The proxy pair (`url`/`api_key`) is host state: the proxy's address and key, which `wt-model serve` reads (`LitellmBaseURL`, `LitellmAPIKey`) and `wt-model litellm set|status` (the `wt litellm set|status` twins) write and show — the wt-model home's `[litellm]` table (`~/.config/wt-model/config.toml`) first, this file's `Config.LitellmTable` its read-only fallback (resolution below). No session reads it (R4; `cmd/wt-session/boundary_test.go`): every session reaches its models through the model server's gateway, and there are no direct routes (`ResolveRoute` and `IsLitellm` were deleted with Task 19). Its `enabled` key is retired: still parsed and round-tripped on every save, read by nothing, and a true value prints one note per process (`IgnoredLitellmKeys`). `finalizeCfg` resolves the pair into the runtime state through `applyProxyState` (`internal/config/proxyhome.go`): the wt-model home's `[litellm]` table (`~/.config/wt-model/config.toml`, `docs/contracts/wt-model-config.sample.toml`) wins when it has one, this table is the read-only fallback when the home has none, and `(*Config).ProxySource()` reports which supplied it (pinned in `internal/config/proxyhome_test.go` and `internal/config/litellm_state_test.go`). A resolution error — an unparseable home `config.toml`, a dangling link, a loose or unreadable key file — leaves the pair empty, never a silent fall-back to the legacy values, and is kept as `(*Config).ProxyErr()` (a `*ProxyHomeError`) rather than failing the load: only the pair's users refuse on it (`wt-model serve`'s `loadServeConfig`, `wt-model litellm restart`, `lifecycle.RestartProxyTo`/`ProbeProxy`; `status` and `set` fail through `ResolveProxy`/`SetProxy`), so `wt-model model list` and the model server's per-request reload keep working (`TestABrokenHomeFailsOnlyWhatUsesThePair`). `LoadSession` never opens the home: it keeps its inert copy of the legacy table (the spec's "No session-behavior change"). A first `SetProxy` that would create the home's table and leaves out a field the legacy table holds is refused (`refusePartialFirstSet`, `TestSetProxyRefusesAPartialFirstSet`): sources never mix, so the left-out value would silently stop resolving. The home's two reads run under the flock `SetProxy` writes with (`config.toml.lock`), so one resolve always sees one writer's whole pair. `SetProxy`, behind `wt-model litellm set` and `wt litellm set`, is the home's one writer (key file 0600 with the key's bytes, created when it does not exist) and never writes the legacy table; the pair is configured when URL and key are both set.

Toggling is routing policy only — it never touches the proxy. `LitellmBaseURL()` trims trailing slashes so drivers append `/v1` (or nothing for claude) cleanly. The proxy reads `config.yaml` only at startup; see [docs/wt-agents/README.md#litellm-proxy-lifecycle](../wt-agents/README.md#litellm-proxy-lifecycle).

## Registry

`~/.config/local-ai/registry.toml` holds the canonical Providers/Models. Path precedence (`config.RegistryPath`): `WT_REGISTRY` > `MODELMAN_REGISTRY` > `XDG_CONFIG_HOME` > `~/.config`. `WT_REGISTRY` is the name wt and llmbench share; `MODELMAN_REGISTRY` is the older name and stays as an alias. llmbench's `registry_path` uses the same order, and each of the two has a precedence test — keep them in sync. A value starting with `~/` (or exactly `~`) is expanded via `ExpandHome` to match Python's `Path.expanduser()`; Go never expands `~` itself, so this parity is deliberate.

wt loads it via `config.Load` (fail-closed: missing/malformed registry is an error; `wt-model model init` creates one) and joins it in memory with `config.toml`. `Load` never writes it and never seeds it. Decoded extra fields: `model_info` (`Model.ModelInfo`, merged into the LiteLLM rows wt writes — `internal/litellm/entry.go`), `cost` (`config.ModelCost`, rendered as the picker's price columns), `model_dir`, `auth.base_url`, `auth.secret_ref`, a model's `pricing_updated_at` (`Model.PricingUpdatedAt`, typed `any` so that neither the string wt stamps nor a TOML date-time a hand edit left can fail the load; read it through `Model.PricingUpdated()`), a model's `serve_args` (`Model.ServeArgs`, a `config.ServeArgs`: the argv elements of an mtplx model, appended to its spawn by `provider.ProcessSpec.SpawnArgs`; a value that is not an array of strings reads as absent with `Malformed` set, and `Model.ServeArgsProblems()`, which `Model.Malformed()` includes, and `config.ServeArgsProblems` judge what the provider takes and refuse wt's own flags, `registry_validate.go` asking the same function on a write; the key sits after `tags` in `modelSchemas`), and a model's `fetch` and `draft` tables (`Model.Fetch`, `Model.Draft`, a `config.ModelArtifact` each: `repo` and `local_path` only, read to show a `local_path` and to name a pairing's two sides — `internal/modeladmin`; their other keys, `files` and `quantizations`, are not decoded. wt writes the two tables in one place only, `wt-model model add mlx_lm_server <target> --draft <draft>` — `modeladmin.Add`, through `RegistryDoc`, a `repo` or a `local_path` on each side — and never changes them afterwards. A side is a `local_path` when it starts with `/`, `~`, `./` or `../` (`modeladmin.IsLocalPath`); `cmd/wt-session` makes a `./` or `../` side absolute before the add (`absDotRelative`), since llmbench resolves a relative `local_path` against its own working directory, and `modeladmin` itself never reads the working directory. Two rows are the same pairing when their sides are, a `local_path` compared as the directory it names — `~` expanded and the path cleaned, `sideKey`).

**Reading the registry as a document.** `config.ReadRegistryDoc()` returns the same `RegistryDoc` `UpdateRegistry` hands to `apply`, read with no lock and never written: what a planner looks at before anything is decided (`wt-model cloud-sync`'s dry run). It refuses what a write refuses (a broken link, a file that is not TOML, an unknown top-level key) and a missing registry is `ErrRegistryMissing`. The document is detached; a write goes through `UpdateRegistry`, which reads the file again under the lock.

**Aliases and windows (#596, #626).** Besides `[[providers]]`, `[[families]]` and `[[models]]`, `registry.toml` has a top-level `[[aliases]]` array (`internal/config/alias.go`): `id = "alias/<name>"` and `targets = [{ model, order }]`, or in place of `targets` `redirect_to = "alias/<new>"` (#687, what `wt-model alias rename` leaves behind; never both, one hop, the target a real alias that is not itself a redirect), no other key in v1. A redirect has no targets of its own: every consumer reads `Config.AliasTargets(a)` (the target alias's, resolved at read time), never `a.Targets`, so the route rows, the window, the catalog row and the session expansion cannot drift from the target; `config.AliasFault` also refuses a chain or a missing target, and `RegistryDoc.RemoveAlias` refuses an alias a redirect points at (`config.ErrAliasRedirected`, naming it; `modeladmin.RemoveAliases` removes redirects first so one write can remove both). An older `wt-model` reads `redirect_to` as an unknown key, so it marks the alias malformed and freezes its rows. `config.AliasFault` is the one judge of the cross-table rules (a target names exactly one model, no alias or native target, at most one local target, the id is not a model id); `validate` and the writer both use it. A malformed alias (unknown key, `notes` included; a bad id or target) loads as `Malformed` and never fails `Load`, and the route path freezes its rows; two aliases with one id are the exception and fail `Load`. `RegistryDoc.RemoveModel` refuses a model an alias targets (`config.ErrModelInUse`, read from the raw file so a malformed alias still protects its targets), and a write touching a model or its provider re-checks every alias targeting it. An older `wt-model` refuses every registry write once `[[aliases]]` exists (`ErrRegistryTopLevel`), and the last `alias rm` removes the key so it can write again. A model's optional `context_window` is whole tokens; a malformed or non-integer value reads as absent (the write refuses it); `internal/windows` computes a model's window (registry value, else a cloud model's host-basis tiers window) and an alias's (the minimum over every target, 0 when any is unknown).

**A malformed `fetch` or `draft` never fails the load.** With `pricing_updated_at` (typed `any`, above) they are the only exceptions to "a value of the wrong type is a parse error": wt reads the two tables only to show a path and name a pairing, a single model's `local_path` entry is typed by hand and so was every pairing before `wt-model model add mlx_lm_server` wrote one (a registry may hold either from an older tool's form or an editor), and a slip such as `fetch = "org/S"` must not stop every wt command, launches included, over a key no launch reads. `ModelArtifact.UnmarshalTOML` (`internal/config/config.go`) is the one place that knows the shape (`artifactFields`: `repo` and `local_path`, each a string):

| In the file | Reads as |
|---|---|
| `fetch`/`draft` that is not a table (a string, a number, a boolean, an array, an array of tables) | absent — an empty `ModelArtifact` |
| a `repo` or `local_path` that is not a string | that key absent; the other key is still read |
| an empty table | an empty `ModelArtifact`, the same as no table |
| other keys (`files`, `quantizations`, a key neither tool models) | ignored by the reader, and kept by the writer as written (it is patch-shaped) |

Nothing else about the row changes, and the rows after it load as usual. `wt-model model list` still lists the row, with no path (or no target/draft for a pairing).

**The loader records what it tolerated, and `wt-model model list` is the one command that prints it.** `UnmarshalTOML` fills `ModelArtifact.Malformed` (a `config.ArtifactFaults`: `NotTable`, `Repo`, `LocalPath` — comparable, tagged `toml:"-" json:"-"`, so it is never encoded and a `ModelArtifact` can still be compared with `==`; it does not change what `Repo` and `LocalPath` hold). `Model.Malformed()` turns the two records into phrases in a fixed order, fetch before draft and `repo` before `local_path`: `fetch is not a table`, `fetch.repo is not a string`, `draft.local_path is not a string`. After them it names each `cost.time_prices` row the registry's validator refuses, `cost.time_prices[<i>]: <the validator's reason>` (`TimePrice.Problem`, which asks `validateTimePrice` about the typed row): the loader types such a row's values and checks no rule, `ModelCost.PriceAt` passes it over whole, and this is where its writer learns why it changes nothing. A window whose `end` is before its `start` is not refused: it runs past midnight, from `start` on each listed day to `end` on the next calendar day of the row's wall clock (`validateWindow` accepts it and `TimePrice.holds` reads it; the one refusal left of the old "start must be before end" is a `start` equal to its `end`). Both the validator and `holds` get a row's zone from `config.loadZone`, which reads the host's zone database once per zone per run. (A value of the wrong TOML type in a row is not tolerated: it fails the typed decode and the load, `TestLoadStopsOnATimePricesValueOfTheWrongType`.) `modeladmin.Row.Malformed` carries them, for the Models tab to show. `wt-model model list` prints one stderr line per affected row after the table, in the registry's order (not the table's), with the id escaped as in the table and the repair worded by `RegistryFixHint` — `<id>: <problem>, <problem>; wt reads it as absent (fix the entry in <registry path>)` (the same words close a line that names a `cost.time_prices` row, which is read and not applied) — and `--json` adds the phrases as each model's `malformed` array (always present, `[]` when there are none) and prints the same stderr lines. Stdout and the exit code are as without the note. Every other command stays quiet on purpose: a launch, `wt start` or `wt-model litellm sync` does not read `fetch` or `draft`, so a warning there would be noise on every run about a key that does not affect it; the listing is where a row that reads `missing` is looked up. The model picker does read `cost.time_prices`, and it too says nothing about a row it passes over: it applies the model's other rows, if any, and with none shows the model's own price with no `~`; the listing is where the reason is.

The malformed value is also named where wt would otherwise write it out again: the registry writer's touched-row check (`validateArtifact`, `registry_validate.go`, the same `artifactFields`) refuses a write that touches such a row with `fetch must be a table` or `draft.repo must be a string`, and leaves an untouched one alone, so an edit that repairs or removes the key goes through. Pinned by `TestLoadToleratesAMalformedFetchOrDraft`, `TestModelNamesItsMalformedFetchAndDraft`, `TestMalformedRecordIsNeverSerialised`, `TestUpdateRegistryValidatesOnlyTheRowsItTouched` (`internal/config`), `TestRowsCarryWhatIsMalformedInTheRegistryRow` (`internal/modeladmin`), and `TestModelListListsARowWithAMalformedFetch`, `TestModelListNamesAMalformedFetchOrDraft`, `TestModelListJSONNamesAMalformedFetchOrDraft` and `TestModelListIsQuietOnAWellFormedRegistry` (`cmd/wt-session`).

**A symlinked registry.** `resolveRegistryFile` (`internal/config/registry.go`) is the one place that decides what a registry path is (#248). A symlink that leads to a file is read through. A symlink that leads nowhere — its target is gone, or the links loop — is `config.ErrRegistryLink`, never `ErrRegistryMissing`: a link is the user's pointer at where their registry lives (a dotfiles checkout, a volume that is not mounted), so wt neither launches as if there were no registry nor offers to seed one. `RegistryFixHint` gives it the hint `fix the link or move it aside`. The same holds one level up: when the path is absent because a directory above it is a link that leads nowhere (the whole `local-ai` directory linked into a checkout that is not there), that is `ErrRegistryLink` too, naming the directory link. Only a path with nothing at it, under directories that are really there, is "missing".

**Writing the registry.** `config.UpdateRegistry(apply func(*RegistryDoc) error) (changed bool, err error)` (`internal/config/registry_write.go`) is the only way wt writes `registry.toml`. In order: flock on `<registry path>.lock` (the path as named, so a symlinked registry gets no lock file in its checkout); `resolveRegistryFile` (a resolving link is written through and survives, a broken one is `ErrRegistryLink` — asked once before the lock too, because under a broken directory link the lock file cannot be created and that failure would not name the link); read and decode with `internal/tomlw` (a missing file is an empty document; an unknown top-level key is `ErrRegistryTopLevel`, #247; a document whose key list and values disagree is a parse error, so a key the decoder lost is never written away); run `apply`; validate the rows `apply` touched and only those (`ErrRegistryInvalid` — wt's typed decode plus the required-field and cost rules, the legacy `cost.kind` shape's included, and `fetch`/`draft` being tables whose `repo` and `local_path` are strings — which the reader tolerates, see above — `registry_validate.go`; a `time_prices` zone is checked against the host's zone database, wt embeds none; and, for a model row, the two `Config.Validate` rules that need other rows: its `provider_id` names a provider row, and its `location` — its own, or the one it inherits from that row — resolves to `local` or `cloud` (`validateModelRefs`, which asks `ResolveLocation` over the document's provider rows as they are after `apply`, so a row seeded in the same write counts)); skip the write when the file exists and `apply` changed nothing (a missing registry is created by any `apply` that succeeds, even one that adds nothing); otherwise re-read the file and, if another program changed it, start over (three runs of `apply`, then `ErrRegistryBusy`); replace the file atomically with its mode kept (0600 when new).

- **`apply` must be pure**: it may run up to three times, so no printing, no commands, no server calls, and a result handed back through a captured variable is assigned afresh on each run.
- **`RegistryDoc` is patch-shaped** (`registry_doc.go`): `PatchModel(id, set, unset)`, `AddModel`, `CloneModel`, `RemoveModel` (returns the row), `SetTimePrices`, `AddProvider`, and the copying read views `Models()`/`Providers()` and `Model(id)` (one row). Keys are dotted paths inside a row (`cost.input_price_per_million`). A `PatchModel` is all or nothing: when one key fails, the row is as it was. Nothing writes a `config.Model`, so a key wt does not model is never touched and adding a field to `config.Model` cannot change a write (`TestAWriteNeverTouchesAKeyItWasNotAskedTo`). A value equal to the one already there is not rewritten — an integer price stays an integer. `model_info` is written only when a caller names it.
- **A row is found by its id, and an id on more than one row is refused.** `RegistryDoc.modelRow` is the one lookup behind `PatchModel`, `CloneModel` (its source), `RemoveModel`, `SetTimePrices` and the read `Model(id)`: no row is `ErrModelNotFound`, more than one is `ErrModelAmbiguous` — `model "<id>" is in the registry twice (providers A, B); wt cannot tell which one you mean — fix the entry in <registry path>` (`3 times` and so on for more; each row's `provider_id` in file order, `(none)` for a row without one; the first half is `config.DuplicatedModelText`, which `wt-model litellm sync`'s warning shares). Two rows under one id fail `Config.Validate` (`duplicate model id`), but `wt-model model edit` and `wt-model model rm` gate on the load error alone so that they can repair a registry — which made "the first row with the id" the row an edit or a removal silently landed on, exactly where the user most needs to choose. Nothing chooses for them (no `--provider`): the repair is a hand edit. An operation that only asks whether an id is taken (`AddModel`, `CloneModel`'s new id) still answers `ErrModelExists`. `modeladmin.Edit` reads its row through `Model(id)`, so the refusal comes before its cost rules, and `modeladmin`'s `describe` passes it on unchanged; `Config.CheckModelRow(id)` gives the same answers from a loaded config, for `wt-model model rm` to refuse the id before its question. Pinned by `TestOperationsRefuseAnIDTheRegistryHoldsTwice`, `TestADuplicatedIDLeavesTheOtherRowsReachable`, `TestCheckModelRow` (`internal/config`), `TestEditAndRemoveRefuseAnIDTheRegistryHoldsTwice` (`internal/modeladmin`), and `TestModelEditRefusesAnIDTheRegistryHoldsTwice`, `TestModelRmRefusesAnIDTheRegistryHoldsTwice` (`cmd/wt-session`).
- **New keys go at their schema position** (`providerSchemas`/`modelSchemas`): at the key's schema position, unmodelled keys ahead of the schema keys.
- **A no-op on a registry that exists leaves the file byte-identical**, hand-written comments included (on a missing one it creates the file). The first write that changes something lays the whole file out in tomli-w's form and drops comments.
- **wt never adds a top-level key** beyond `providers`/`families`/`models`: wt's own writer refuses a file that has any other (#247).
- **The registry write ignores `RegistryRedirected`**; the route sync a command runs afterwards is what `litellm.ErrRegistryRedirected` refuses.
- **A test binary cannot write the developer's registry**: `IsolateConfigHomeForTest` arms the `registryWriteGuard` seam with the registry paths the environment named before the redirect, and the guard follows symlinks on both sides (a linked file, a linked directory, `/tmp` for `/private/tmp`). It is a package variable, not an `import "testing"` in shipped code. The guard is off in a binary whose `TestMain` did not arm it; `config.RegistryWriteGuardArmed()` lets a test assert that it is on.

**Missing registry.** `config.Load` still returns `config.ErrRegistryMissing`, but `rootCmd().RunE` re-raises only other errors, and the returned `Config` keeps the parsed `Agents`/`DefaultTag` (empty catalog). A session reads no registry, so a launch does not care; a host command that needs one (`wt-model model list`, `wt-model served`, `wt-model litellm sync`, …) fails with the load error. The old bare passthrough of an agent absent from `config.toml` (`agents.BuildPassthroughCmd`, `IsConfigured`) was deleted with Task 19: a session synthesizes every model-driven driver's agent (R13). Design of the removed feature: [docs/superpowers/specs/2026-09-22-wt-unconfigured-agent-passthrough-design.md](../superpowers/specs/2026-09-22-wt-unconfigured-agent-passthrough-design.md).

**Read-side schemas are pinned by contract fixtures** at the monorepo root: [../docs/contracts/registry.sample.toml](../../../docs/contracts/registry.sample.toml), loaded by `internal/config` contract tests. The id of a discovered model is pinned the same way: [../docs/contracts/discovered-ids.sample.json](../../../docs/contracts/discovered-ids.sample.json), read by `internal/litellm`'s `TestDiscoveredModelIDMatchesContractFixture`.

**`wt-model model list --json` is pinned as an output.** [../docs/contracts/model-list.sample.json](../../../docs/contracts/model-list.sample.json) is one document in the shape the command prints. modeltiers reads its inventory from that command and nothing else, and its tests read this file (`INVENTORY` in `modeltiers/tests/conftest.py`). Two tests in `cmd/wt-model/model_list_contract_test.go` hold it to wt: `TestModelListFixtureMatchesTheDocumentTypes` checks it against `modelListJSON` and `modelListRow` in both directions (every key in the fixture is one the types write, with the JSON type they write it as; every key the types always write is in the document and in each row; an `omitempty` key such as `target` or `draft` may be absent; only a pointer field, `size_bytes` or `path`, may be null; the file decodes with unknown keys refused and encodes back to the same document), and `TestModelListJSONOutputMatchesTheFixture` compares its key sets with what `runModelList` prints. A key added to or renamed in either type must reach the fixture in the same change, and a changed fixture runs modeltiers-ci, which is where a key modeltiers needs and no longer gets fails.

**The written form is pinned too.** [../docs/contracts/registry.written.sample.toml](../../../docs/contracts/registry.written.sample.toml) is one registry exactly as tomli-w lays it out, with keys wt does not model at every level below the top (wt's writer refuses an unknown top-level key), integer and float prices, an empty array, inline and `[[header]]` arrays of tables, `time_prices`, and offset and local datetimes. It has no comments (tomli-w writes none), so its purpose lives in its tests: `internal/tomlw`'s `TestWrittenFixtureIsAFixedPoint` (decode, emit, same bytes), llmbench's `test_load_registry_reads_the_written_contract_fixture` and `internal/config`'s `TestTypedReaderLoadsTheWrittenFixture` (wt's own typed reader loads them). The two reader tests assert the fixture's ids and values, so a change to its rows updates them too. Regenerate it only with `tomli_w.dumps`; a hand edit that is not in tomli-w form fails `TestWrittenFixtureIsAFixedPoint`.

**Catalog membership.** `Config.InCatalog` (`internal/config/config.go`) decides tag/family/provider catalog membership (#179, "configured is exposed"): native models (`auth.type = "native"`), local models (location resolves to `"local"`), and cloud models are all in — no stored flag gates wt's lists, and a local model's *row* additionally needs the live inventory to find it (see Local-model resolution). The only exclusion is a registry data gap: a `provider_id` naming no provider, no location on model or provider, or a location that is neither `local` nor `cloud` (#200) stays out (fail-closed on `ResolveLocation`).

**`ResolveLocation` is the one judge of a location.** It returns an error for a missing location and for one that is set but is not `local`/`cloud` (`Location.Valid`; a typo such as `"Local"`), on the model or inherited from its provider. Every consumer keys off that error and so agrees: out of the catalog, out of the inventory, a gap for `sync` (rows kept, warned), and a validation error — which makes `wt`, `wt start`, `wt stop` and `wt smoke` refuse to run until the registry is fixed, exactly as for a missing location. Validation also checks each provider entry directly, so one with no models (or whose models all override it) is still reported. Never compare a resolved location to decide validity, and never interpret an unknown value. The error matches `config.ErrLocation`; `config.RegistryFixHint` turns that into the `fix the entry in <registry path>` hint, which `configError` (`cmd/wt-session/helpers.go`) and the `wt config` editor's status line both use, instead of pointing the user at `wt config`, which cannot edit the registry.

wt stores no per-model state: what is on disk and what is running come from wt's live probes, and the picker has no EXPOSED column. Whether a model is routed is `wt-model litellm list` (`config.yaml` membership). Design: [../docs/superpowers/specs/2026-10-02-configured-is-exposed-design.md](../../../docs/superpowers/specs/2026-10-02-configured-is-exposed-design.md), which supersedes the predicate design in [../docs/superpowers/specs/2026-09-15-wt-local-model-visibility-design.md](../../../docs/superpowers/specs/2026-09-15-wt-local-model-visibility-design.md).

> **`unknown provider "X"` errors are usually a registry data gap, not a wt bug** — e.g. models referencing `provider_id`s with `providers = []`. Fix with `wt-model model init` on that machine, not a code change here.

**Seeding.** `config.SeedRegistryDefaults(d *RegistryDoc, env SeedEnv)` (`registry_seed.go`) is the one seeding implementation, with one trigger beyond the default-provider rule. It appends the default row for ollama, omlx, mtplx, mlx_lm_server, rec or sushi when a model references it, when a configured agent lists it in `supported_providers`, or (ollama, omlx, mtplx and sushi, the four whose seed names a command) when that command is on PATH (`mlx_lm_server` has no command and `rec` deliberately none, since SoX ships its own `rec`, so those two seed only on a reference) — an installed omlx is skipped when an `omlx-6bit` row exists; a default row for openrouter when a model references it, when an agent lists it, or when an agent is itself named `openrouter` (name, address, `auth.type = "api_key"` and `auth.secret_ref = "OPENROUTER_API_KEY"` — the name of an environment variable, never a key: a row with no `secret_ref` would give a LiteLLM route with an empty `api_key`, where a named variable that is unset is refused, `resolved empty`, and the existing route kept); and a native cloud row for each agent in `config.toml` (an agent named after a provider with a default row gets that row instead). The agent trigger exists because `Config.Validate` refuses an agent that lists a provider with no row. The agents are read as the next `Load` will see them: `seedAgents` applies `migrateAgentRefs` (the agent half of `migrateConfigSchema`: an `agy` agent is added, `opencode` lists `ollama` only) to its own read of `config.toml`, because `Load` migrates that file only once the registry loads. A `config.toml` that is there and cannot be read names no agents and is carried as `SeedEnv.ConfigErr`, which `wt-model model init` prints as a warning. It returns the ids it added and, separately, the providers an agent lists that still have no row because wt has no default for them; `wt-model model init` names those (`providers_unseeded` in `--json`). It never edits a row that exists. It takes a `RegistryDoc`, so it runs inside the caller's own `UpdateRegistry`: `wt-model model init`, and `wt-model model add` and the Models tab's add (`modeladmin.Add`), which add the model row first so that seeding sees the provider it references. `config.DefaultSeedEnv()` reads the real machine; `cmd/wt-session` reaches it through the `seedEnv` seam.

**No subprocess discovery.** `newApp()` only loads config. `localmodels.Inventory` does HTTP + filesystem discovery only, so no model is discovered by running a command. wt does exec elsewhere: `internal/lifecycle` (`omlx`, `mtplx`, `ollama stop`), `ollama show` in `internal/modeladmin`, the ollama CLI in `wt-model cloud-sync`, `exec:` secret helpers (`internal/config`), `psql` (`internal/spend`), the LiteLLM restart command (`internal/litellm`), git (`internal/worktree`, `internal/guard`, `internal/smoke`), and the launched agent itself.

> **Fixture gotcha.** `Dir()` and `RegistryPath()` both honor `XDG_CONFIG_HOME` (and `RegistryPath()` also `WT_REGISTRY` and `MODELMAN_REGISTRY`) but use *different* subdirs: `config.toml` → `$XDG_CONFIG_HOME/agent-wt/`, `registry.toml` → `$XDG_CONFIG_HOME/local-ai/`. Test/smoke fixtures must populate both. LiteLLM's `config.yaml` follows **none of them** (`litellm.DefaultPath`: `WT_LITELLM_CONFIG`, legacy alias, else `~/.config/litellm/config.yaml`), so a fixture that redirects the registry must also name config.yaml (`WT_LITELLM_CONFIG` or `litellm.Options.Path`): otherwise `applyPlanned`/`PlanSync` refuse with `litellm.ErrRegistryRedirected` (`checkRegistryPairing`, asked after `Open` so a missing config.yaml still answers `ErrMissing`) rather than reconcile the developer's real proxy config against the fixture. Also, `migrateConfigSchema` unconditionally ensures an `agy` agent — any registry fixture with agents needs a matching `agy` provider or `Load`/`Validate` fails with `unknown provider "agy"`.

- **A malformed `fetch` or `draft` reads as absent and never fails the load** (`ModelArtifact.UnmarshalTOML`); `wt-model model list` says so (a stderr line per row and `malformed` in `--json`, from `Model.Malformed()`), the Models tab says so for the selected row (`Row.Malformed`), and the writer's touched-row check names it. `Model.Malformed()` also names a `cost.time_prices` row the validator refuses (`TimePrice.Problem`: an unknown timezone, a time that is not `HH:MM`, a window whose start is its end, a negative price); such a row loads, `ModelCost.PriceAt` never applies it, and a model with no other row is not `TimePriced`. Keep `Problem` asking `validateTimePrice` itself, so the reader and the writer cannot come to disagree about a rule. One rule has two homes and they change together: a window whose `end` is before its `start` runs past midnight, which `validateWindow` accepts and `TimePrice.holds` reads by wall clock (at or after `start` on a listed day, or before `end` on the day after one; never start plus a number of hours, which is wrong on the two nights a year a zone's clock jumps: `TestPriceAtAWindowPastMidnightFollowsDaylightSavingTime`). A value of the wrong TOML type in a row still fails the load (`TestLoadStopsOnATimePricesValueOfTheWrongType`). Get a zone through `config.loadZone` (read from disk once per run), not `time.LoadLocation`: both callers run for every row while a picker is built.


## Detail moved from wt/CLAUDE.md

The full text of rules that [CLAUDE.md](../../CLAUDE.md) now keeps as one-line summaries.

- The proxy pair (`url`/`api_key`) is the `wt-model` home's (`~/.config/wt-model/`), which `wt-model serve` reads; it is set with `wt-model litellm set --url URL --api-key KEY` (the `wt litellm set` twin writes the same home) and shown by `wt litellm status`, and read from nowhere else. The `[litellm]` table of wt's `config.toml` is its read-only fallback. Its `enabled` key is retired and ignored; `wt litellm on|off` are hidden stubs that exit 1. Details: [docs/internals/config-and-registry.md](config-and-registry.md#litellm-routing-state-wt-owned).

- `~/.config/local-ai/registry.toml` holds the canonical Providers/Models. wt loads it via `config.Load`, fail-closed, and joins it in memory with `config.toml`. `config.Load` never writes it; wt writes it through `config.UpdateRegistry` alone: `wt-model model init` (provider rows), `wt-model model add|edit|rm` and the Models tab of `wt-model model` (model rows, `internal/modeladmin`), and `wt-model cloud-sync` (cloud prices and the ollama cloud entries). Path precedence: `WT_REGISTRY` > `MODELMAN_REGISTRY` (the older name, kept as an alias) > `XDG_CONFIG_HOME` > `~/.config`. llmbench's `registry_path` uses the same order — keep the two in sync; each has a precedence test.

- **`config.UpdateRegistry` is the only registry write path**: flock, symlink write-through, touched-row validation, no-op skip, re-check before rename. Its `apply` must be pure (it may run up to three times). `RegistryDoc`'s operations are patch-shaped — never round-trip a `config.Model` into the file.

- **An id on more than one model row is refused, never resolved to the first row** (`config.ErrModelAmbiguous`, from `RegistryDoc.modelRow`): `wt-model model edit` and `wt-model model rm` run on a registry that fails validation, and a duplicated id is one such registry. Find a row for a write through `RegistryDoc.Model`/`PatchModel`/`RemoveModel`, not a loop of your own.

- **A malformed `fetch` or `draft`, or a `cost.time_prices` row the validator refuses, reads as absent and never fails the load**; `Model.Malformed()` names it, and `wt-model model list` and the Models tab say so. A value of the wrong TOML type still fails the load. `TimePrice.Problem` asks `validateTimePrice` itself, so reader and writer cannot disagree; a window whose `end` is before its `start` runs past midnight and is read by wall clock (`TimePrice.holds`), never start plus hours. Get a zone through `config.loadZone`, not `time.LoadLocation`.

- **Read-side schemas are pinned by contract fixtures** in `../docs/contracts/`, loaded by wt's Go tests (and, for the two `registry*.toml` fixtures, llmbench's). `tiers.sample.toml`, modeltiers' output, is parsed by `internal/tiers/contract_test.go`, which asserts known entries' codes and aligned scores. One pins an output instead: `model-list.sample.json` is the `wt-model model list --json` document, which modeltiers reads as its whole inventory and its tests read as theirs. A key added to or renamed in `modelListJSON` or `modelListRow` (`cmd/wt-model/model_list.go`) fails `cmd/wt-model/model_list_contract_test.go` until the fixture has it, and a changed fixture runs modeltiers-ci.

> **Fixture gotcha.** `config.toml` lives in `$XDG_CONFIG_HOME/agent-wt/` and `registry.toml` in `$XDG_CONFIG_HOME/local-ai/` — fixtures populate both. LiteLLM's `config.yaml` follows neither variable, so a fixture that redirects the registry also names config.yaml (`WT_LITELLM_CONFIG` or `litellm.Options.Path`), or route writes refuse with `litellm.ErrRegistryRedirected`. `migrateConfigSchema` always ensures an `agy` agent, so a registry fixture with agents needs an `agy` provider or `Load`/`Validate` fails with `unknown provider "agy"`.
