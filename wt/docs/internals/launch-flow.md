# wt launch flow: launch directory, post-exit, survey, sessions, profiles, slot profiles

Internals reference for `wt/`, reached from [`wt/CLAUDE.md`](../../CLAUDE.md). Backticked paths are relative to `wt/` unless they start with `../`.

## Launch directory and the repository

The root command's `RunE` (`cmd/wt/main.go`) picks one of four entries into `runLaunchPath(…, launchPath, root)`, tried in this order:

| Entry | `launchPath` | `root` | Outside a git repository |
|---|---|---|---|
| `-W <name>` | the worktree `EnsureForName` returned | the checkout root | refused: `not in a git repo: <git's error>` |
| `--cwd` | `os.Getwd()`, absolute | the checkout root, or `""` when `worktree.RepoRoot` finds none | launches |
| no flag, outside a repository (`!worktree.IsRepo(".")`) | `"."` | `""` | this is that case |
| no flag, inside one | `""` (the worktree picker resolves it) | `""` (the caller installs the guard itself) | never reached |

- **`root` gates the guard install and nothing else.** `runLaunchPath` calls `maybeInstallGuard` when `root != ""`. Nothing downstream reads it: `launchFiltered`, `launchSlotProfile`, `launchPassthrough` and `tui.Run` take the directory only.
- **No launch state is derived from git.** `rotation.state` and `last-picked.state` hold a model id, `usage.jsonl` is keyed by agent and model, `refcount.jsonl` by pid and model, and a session's name is the agent's own business. So `--cwd` outside a repository has no key to invent: it writes the same files as a launch inside one, under the same config directory, and cannot collide with a repository's state because no state belongs to a repository. The directory matters in two places, both by path and neither by repository: the agent's working directory (`cmd.Dir`), and an automatic profile's `config_content` target for claude (`<dir>/.claude/settings.local.json`, written only when a profile with that mechanism or `config_defaults` applies, and restored after the run). That target's backup under `profile-backups/` is the one piece of wt state keyed by a directory: `profiles.ConfigFileTarget` makes the path absolute before it is hashed, so two directories never share a backup, repository or not.
- **The TUI's `repoRoot` is already optional.** `newRunModel` seeds it from `worktree.RepoRootAt(prePath)` and leaves it `""` on an error; it is read only when the TUI creates a worktree (the new-worktree prompt, a branch row), and a pre-resolved path starts past the worktree picker.
- **`--cwd` and the no-flag launch outside a repository are the same launch**, except that `--cwd` passes an absolute path where the other passes `"."`. Both name the same directory; `agents.RelativeArgNotes` and `profiles.ConfigFileTarget` resolve either form. The no-flag branch is kept as it is rather than folded into `--cwd`'s.
- **`RepoRoot` (`--show-toplevel`) and `IsRepo` (`--git-dir`) disagree in a bare repository and inside `.git`**: a git directory with no checkout. `--cwd` there used to be refused and now launches with `root == ""`, so no guard is installed by that launch; the no-flag launch there still goes to the worktree picker.
- **`wt smoke --cwd` never asked git.** `runSmoke` reads the flag and `os.Getwd()` only, so it ran outside a repository before this and is unchanged. An agent may still refuse the directory itself (codex: "Not inside a trusted directory"), which is why the default row directory is a temporary repository ([smoke.md](smoke.md)).

Pinned by `cmd/wt/cwd_norepo_test.go` (a real launch with a recording agent, inside and outside a repository, comparing the state files written) and `TestRunLaunchPath`.

## Post-exit flow

After the launched subprocess exits, the TUI and non-TUI paths run the same fixed sequence — order and user-facing behavior are in [docs/wt-agents/README.md#post-exit-order](../wt-agents/README.md#post-exit-order); don't reorder one path without the other. Code notes:

- **Summary line** (`wt: <agent> · <model-id> · <duration>`): formatter `internal/agents.Summary`, the single source for both paths. Printed on success and non-zero exit; never affects the exit code. Duration is measured when the agent exits.
- **Exit status, last** (#412): wt exits with the agent's status on both paths, after everything below. The non-TUI paths `os.Exit(ee.ExitCode())` after `lifecycle.WaitPendingRoutes()` (`runAgentCmd`, `runSlotAgentCmd`). The TUI cannot exit from inside `tea.Program`: `runAndWaitCmd` and `runSlotAndWaitCmd` return `launchDoneMsg{err, ran: true}`, the handler keeps `err` on `model.agentErr` (and still sets the `agent exited: …` status), and `Run` returns it from `runResult` after `printPendingSummaryAndSurvey`. `cmd/wt`'s `runTUI` passes it through `agentExitStatus`: an `*exec.ExitError` becomes a quiet `exitCodeError` with the agent's code (a signal-killed agent's -1 becomes 255, what `os.Exit(-1)` gives the other path), cobra is silenced for it, and `reportExit` prints no `wt:` line; `main` waits for routes and exits with `exitCodeOf`. Any other run error is printed and exits 1, as `runAgentCmd`'s return does. A profile applier error (`ran` false) is printed where it happens and `Run` still returns nil. Pinned by `internal/tui/launch_exit_status_test.go` and `cmd/wt/tui_exit_status_test.go`.
- **Refcount release first.** `survey.ReleaseSession()` (`internal/survey/stop.go`, → `refcount` `Release(pid)`) drops wt's own entry before the stop picker — otherwise the model just used would always count as in use.
- **Stop picker** (`survey.Picker`): offers running local models with refcount zero, a trusted probe, and a stop backend (`lifecycle.CanStop`). Its prompt (`chooseLabeled`, shared with `wt stop`) is one line applied on Enter — space-separated numbers, `a`/`all`, or nothing — with no ticked state and no confirming Enter (#139); an unreadable line rejects the whole line and re-prompts. Deliberately no more than that: whatever it leaves running, `wt stop` stops. Its loop (`stopEntries`, shared with `wt stop`) runs the models as one `lifecycle.BeginStops` batch (#379: every ollama stop sent first, one shared wait) and finishes each with the batch's `Stop` (route removal written, no restart); a wait past 2 seconds continues the model's open line with the `lifecycle.StopNotice` (through `lifecycle.WithStopNotice`, onto the loop's writer — the picker runs after the TUI's alt screen is gone, pinned by `TestModelStopsRunOnlyAfterTheAltScreen`), and a `*lifecycle.StillFinishingError` ends the line `still finishing a request; ollama unloads it when that ends` and is not a failure. The loop settles from a `defer`, so it reaches `lifecycle.SettleRoutes` on every exit path including Ctrl+C and failures — but only when some stop owed a restart, since a batch that removed nothing must not bounce the proxy. So N stops cost one LiteLLM restart, not N overlapping `kickstart -k`s (#142). Silent for non-TTY stdin, command agents, and native models. Ctrl+C/SIGTERM is caught on the picker's own context: at the prompt the read (on a goroutine raced against the ctx) is abandoned; during a stop the in-flight stop is cancelled and the rest skipped, and the stops ollama had already accepted are named (`StopBatch.Accepted`), since ollama still carries them out. That reader goroutine prints the prompt and the picker goroutine prints `cancelled`, so both write through one `lockedWriter` — a signal landing mid-prompt is otherwise a data race (on a test's `bytes.Buffer`) and interleaved output on a terminal. Either way it prints `cancelled`, runs the TTY drain, and still reaches the summary.
- **Stale-pricing notice**: printed when the registry's OpenRouter prices are more than 7 days old, or were never refreshed (`wt: token pricing last refreshed <date> — run 'wt cloud-sync'` / `… has never been refreshed …`). Nothing stores the date: `agents.LastPriceRefresh` takes the newest `pricing_updated_at` among the OpenRouter-priced models (`Model.PricingUpdated`), and `wt cloud-sync`'s openrouter flow stamps every model it matches, changed or not, so the newest stamp is the last refresh. A missing or mistyped stamp is skipped, never an error, and so is one more than a day ahead of the clock (a typo such as 2062, which would otherwise silence the notice until then). wt never refreshes on its own (a refresh is a network call, a registry write and possibly a proxy restart); the notice is the only reminder. Skipped for command agents (`m.ID == ""`) and when the catalog has no OpenRouter-priced model (`agents.HasOpenRouterPricedModel`, #151: a model whose `provider_id` is `openrouter`, and no other; ollama cloud models and other cloud providers' models don't count): `wt cloud-sync` would have nothing to refresh. `internal/cloudsync.OpenRouterPriced` is the same rule over registry rows; `docs/contracts/catalog-predicates` pins both.
- **A slot-profile session has its own tail.** `runSlotAgentCmd` (`cmd/wt/slot_launch.go`) and the `launched.profile` branch of `printPendingSummaryAndSurvey` (`internal/tui/app.go`) run release → stop picker → summary, with no survey and no price notice. The summary is `agents.Summary` over an id-only `config.Model{ID: "profile/<name>"}`. Change the two together, as for the single-model tail.

## Session survey (Go)

> **The survey is switched off** (`survey.Enabled = false`, `internal/survey/prompt.go`; 2026-10-05, #136). `PromptRun` returns `""` at once, so no launch path asks anything or prints an after-survey block. Everything below still describes the code, which is kept so the survey can come back by flipping that one value: the questions, the store, `wt stats` and the picker's SURVEY column (both keep reporting the answers already in `survey.jsonl`, which thin out as they pass the 30-day window). The package's `TestMain` turns `Enabled` on so the kept code stays tested; `TestSurveyIsSwitchedOff` pins the shipped value. The stop picker lives in this package but is not the survey and is unaffected.

`internal/survey` records a post-session verdict (worked? speed? quality? task description) for every launch with a model — skipped for command agents (`m.ID == ""`) and native models (`m.Native`). `survey.PromptRun` is the single implementation for both paths (`cmd/wt/launch.go runAgentCmd`, and `internal/tui` via the same capture-then-emit pattern the summary uses). It no-ops when stdin is not a TTY and **returns** the after-survey stats block rather than printing it, so the caller can place it after the stop picker and summary.

- **Paste drain:** after the last question, `PromptRun` flushes the kernel TTY input queue (`drainTTYInput`: `TIOCFLUSH` darwin / `TCFLSH` linux / no-op elsewhere) — a multi-line paste at the free-text question delivers all its lines at once and anything unconsumed would otherwise execute as shell commands in the parent terminal after wt exits. Targeted at `os.Stdin`, not the injected reader, because the residue lives in the kernel queue for fd 0. Don't remove this to "simplify" the survey.
- **Store:** `~/.config/agent-wt/survey.jsonl`, wt-owned, 30-day retention, pruned on every write (mirrors `internal/usage`).
- **Worked%** = `worked / (worked + failed)` over *answered* surveys; skips are recorded but excluded from the denominator. The model picker's SURVEY segment (`✓<pct> q<quality> s<speed> n<answered>`) shows `⚠` instead of `✓` when `WorkedPct < 70%` and `Answered >= 3`.
- **Model ids:** surveys and usage key on a free-form id and never require a registry entry. Unregistered on-disk models use `config.DiscoveredModelID(family, artifact)` (the probe family — `omlx` for an `omlx-6bit` row); a registry match keeps its registry id.
- Reporting: `wt stats` — see [docs/wt-stats.md](../wt-stats.md).

## Profiles (`internal/profiles`)

Opt-in overlays from `~/.config/agent-wt/profiles.toml` (absent = enabled, zero profiles), resolved per agent × model (`profiles.Resolve`). Operator reference and per-agent mechanisms: [docs/wt-agents/profiles.md](../wt-agents/profiles.md).

- **Where applied:** both launch paths via `applyProfileForLaunch` (`cmd/wt/launch.go`; the TUI reaches it through the `profileApplier` seam set in `main.go`), and `wt smoke` via `applyResolvedProfile` directly. Skipped for command agents and native models.
- **Confirmation:** an interactive launch asks `apply? [Y/n]` on `/dev/tty` (`confirmProfile`); with no TTY it auto-applies (default yes). `wt smoke` never prompts.
- **Apply order** (`applyResolvedProfile`): env/args → `config_content` (with `config_defaults`) → wrapper. Smoke's one-shot args are inserted after profile flags but before the wrapper — codex silently drops a `-c model_provider=...` that trails `exec <prompt>`, and the wrapper splices the current argv.
- **`config_content`** backs up and rewrites the agent's config file (claude `<worktree>/.claude/settings.local.json`, codex `~/.codex/agent-wt-profile.config.toml`; opencode merges into `OPENCODE_CONFIG_CONTENT` instead). The cleanup must be called explicitly after the run (not deferred — `runAgentCmd`'s `os.Exit` would skip it). `SelfHeal` restores an orphaned backup from a killed session; it runs on *every* launch of that agent, before profiles.toml is even loaded.
- **`config_defaults`** (claude only, `MechanismConfigDefaults`) rides on the same `ApplyConfigContent` call and the same backup: after `config_content` is merged, `collectAbsentLeaves` takes each defaults leaf the merged document does not have (a path that crosses a non-object counts as present) and `setLeaves` writes it. Its leaf records go into the same `.keys` marker as `config_content`'s, so restore cannot tell them apart; a value the file already had is never written, recorded or reverted (#402). "Absent" means absent from `settings.local.json`; `.claude/settings.json` and `~/.claude/settings.json` are never read. `ApplyConfigContent` is a no-op only when both tables are empty, and refuses `config_defaults` for any other agent (`profile: agent %q does not take config_defaults`), behind `Validate`'s own refusal. Slot profiles have no such field.
- **Failure posture:** load/validate/apply errors degrade to an unprofiled launch with a stderr warning (a `config_content` failure also reverts env/args already applied). The one fatal case: a wrapper naming a missing binary.
- **CLI:** `wt profile list`, `wt profile show -A <agent> -M <id>` (dry run), `wt profile status`, `wt profile on|off` (refuses to write if profiles.toml failed to parse).

## Slot-profile launch

A slot profile (`~/.config/agent-wt/slot-profiles.toml`, hand-written; operator reference [docs/wt-agents/slot-profiles.md](../wt-agents/slot-profiles.md)) is its own launch unit, not a model with extras. It is loaded and statically validated once in `newApp` (`profiles.LoadSlots`, `profiles.ValidateSlots`, into `app.slotChecks`), becomes a catalog row only for a caller that opts in (`catalog.Input.SlotProfiles`), and is launched by one function per path that runs the same ten steps.

| Step | Non-TUI (`launchSlotProfile`, `cmd/wt/slot_launch.go`) | TUI (`internal/tui/slot_flow.go`) |
|---|---|---|
| 1 Re-resolve | `catalog.ResolveSlotProfile` over a fresh `probeInventory` | the same call over `runInventory`, in the first stage's command |
| 2 Passthrough | `agents.CheckSlotPassthrough` | the same |
| 3 Cloud routes | `lifecycle.EnsureModelRoutes` over `ProfileRow.Cloud()`, restart deferred | the same |
| 4 Start | `startForLaunchOwed(cfg, *Local, allowReplace, owed)` when the row is a start row; a Ctrl+C that lost to the start is its error `started <id>; launch cancelled` | `beginStartOwed`: the existing start flow, with `lifecycle.Options.RestartOwed` |
| 5 Local route | `EnsureModelRoutes` for the local model: one already running, and again after a step-4 start | the same (`finishSlotRoutes`): in the first stage for a running model, in the second stage after a start |
| 6 Restart | `lifecycle.RestartProxy` when still owed | `lifecycle.RestartProxyTo`, printing into the stage's notes buffer |
| 7 Wait, probe | `waitPendingRoutes()`, then `lifecycle.ProbeProxy`, on every launch | the same; after a start steps 5 to 7 are the second stage (`settleSlotAfterStart`) |
| 8 Build | `agents.BuildSlotLaunchCmd(row.Profile.Launch(), …)` | the same, in `launchSlot` |
| 9 Apply | `applySlotProfile` | `tui.SlotProfiles.Apply`, which `main.go` sets to `applySlotProfile` |
| 10 Run | record, then `runSlotAgentCmd` | `runSlotAndWaitCmd` records and runs |

- **Fail closed.** Every abort returns before the agent starts and before anything is recorded. No error on this path degrades to a launch without the profile. `applySlotProfile` is therefore not `applyResolvedProfile`, which reverts and launches unprofiled: it applies a hand-built `profiles.ResolvedProfile` holding only `ExtraArgs` and `Wrapper`, returns an `ApplyWrapper` error, never prompts and writes no file.
- **Automatic profiles are never applied.** Neither path calls `applyProfileForLaunch`, and the TUI's `runSlotAndWaitCmd` never calls `profileApplier`. `selfHealAgentConfigContentTarget` still runs first, so a leftover `settings.local.json` of an earlier automatic-profile session is restored.
- **`config_content` is delivered by the driver, not the applier.** For claude it travels in the inline `--settings` JSON (`claudeDriver.BuildSlots`, `internal/agents/claude_slots.go`); `.claude/settings.local.json` is never written. The proxy token is in the process environment only, never in argv.
- **The proxy, whatever the toggle says.** Nothing on this path reads `cfg.IsLitellm()`. The url and key come from `cfg.LitellmBaseURL()` and `cfg.LitellmAPIKey()`; a missing one blocks the row (`ResolveSlotProfile`, the url and api-key checks).
- **One restart at most.** `EnsureModelRoutes` never restarts on success and reports whether a restart is owed. A start is handed that debt as `Options.RestartOwed`, so its one restart publishes the cloud routes too. A refusal (`*OccupiedError`, `*OccupancyUnknownError`) touched nothing and does not spend the debt (`lifecycle.RestartStillOwed`): the caller retries with it, or calls `lifecycle.SettleRoutes` when it gives up.
- **The route is checked after a start too.** `lifecycle.Start`'s route hook never fails the start: a write error is printed and `litellm.ErrMissing` is not even that. So both paths run step 5 for the model they just started and abort on its error, as they do for a running model. A row the start wrote compares equal, changes nothing and owes no restart, so the one-restart rule holds.
- **Ctrl+C that lost to the start launches nothing.** The engine returns nil once the model is up and `SettleStart` drops cancellation, so on the non-TUI path only the signal context remembers the key: `startForLaunchOwed` reads it after the settle and returns `started <id>; launch cancelled`, the TUI's words for the same key. `startForLaunch`, which `wt start`, `wt smoke` and the single-model `-M` pin share, does not: there a started model is the result.
- **Recording** is two calls at the commit point, after the applier succeeded: `rotation.New().RecordProfile(agent, row.Model.ID)` (the usage event and `last-picked.state`; never `rotation.state`) and `refcount.NewStore().RecordAll(os.Getpid(), ids)` with the id of each `ProfileRow.Distinct()` model. A failed write prints a `note:` line and does not abort.
- **The pin.** `resolveModel` returns the sentinel error `*slotPin` for a `-M profile/<name>` pin whose row is not blocked, and `launchFilteredImpl` hands its row to `launchSlotProfile`. A blocked pin needs no code of its own: `pickerBlockedReason` returns the row's reason. `launchSlotChecks` is process-wide CLI state like `allowReplace`; `runLaunchPath` sets it and prints `slotWarnings` once per run, and once more after `tuiRun` has returned, because the alternate screen covered the first print.
- **What `slotWarnings` says.** The load error; one line per key of the file the schema does not name (`profiles.SlotStore.Unknown`, from the decoder's undecoded keys, with the keys under the free-form `config_content` left out; kept in `app.slotUnknown`, which can be set while `slotChecks` is nil); one line per profile that is not Usable; one line when the registry holds the `profile/` prefix while a profile is Usable; and one line per driver warning about a passing profile's `config_content` (`slotContentNotes`, `agents.SlotConfigWarnings`; claude's unrouted or non-string `modelOverrides` targets, #412), read from the static checks, so no probe. `catalog.SlotPrefixReserved` is the one predicate for that prefix (`slotRows`, the warning, `wt profile list`, `wt profile show`): a provider with id `profile`, or a model whose id begins with `profile/` under any provider, since registry validation does not tie an id to its provider; `catalog.SlotPrefixHolder` words which. A value of the wrong TOML type is not one of these: it fails `toml.Decode` for the whole file and is the load error.
- **The row and the route write share one predicate.** The last of `ResolveSlotProfile`'s per-slot rules is `lifecycle.Routable`, which is `modelRouteChange`'s own answer, the one `EnsureModelRoutes` fails on with `ErrNotRoutable`. A model the named rules let through and the write would refuse (a cloud model under a provider whose auth is native) is therefore a blocked row, not a launch that fails at step 3. `internal/catalog` imports `internal/lifecycle` for it and still imports nothing of `internal/agents`.
- **A blocked row still says whether its local model runs.** `ResolveSlotProfile` builds the local model's own row (`slotLocalRow`) at its last rule, and that row gives a launch or start row its `Running` and `Loading`. A row blocked by an earlier rule, a static error included, gets the same two values from `slotLocalState`: the one distinct local model the file's slots name that is in the registry, judged by the same single-model row. Both stay false for no local model, for two, for one with no row, and for the one row of a duplicate-name group, which stands for several profiles. `ProfileRow.Local` stays nil on a row blocked before the local model was judged, so nothing can start or route from it, and the verdict, the reason and the rule order do not depend on any of this.
- **A driver's `config_content` rule is static.** `profiles.ValidateSlots` asks `SlotDrivers.ConfigContent`, which `agents.SlotDrivers()` backs with the driver's `SlotCapable.CheckConfigContent`. For claude a `config_content.env` that is not a table is the static error `config_content.env must be a table`, and a `config_content.modelOverrides` that is not one `config_content.modelOverrides must be a table` (#412), so the row is blocked and `wt profile list` and `wt profile show` report it. `claudeDriver.BuildSlots` applies the same functions again (`claudeConfigEnv`, `claudeModelOverrides`), as a second line of defence.
- **Every quit of the TUI flow settles what it owes.** `flushRouteNotesAfterRun` runs once the alt screen is gone. `settleQuitSlot` settles a stage in flight and starts the restart that stage or the replace dialog left owed. While the local model starts, the engine holds the debt (`Options.RestartOwed`): a quit while a cancel drains does not wait for that start, so `settleQuitSlot` starts the restart itself (a second one is possible if the engine also restarts); a quit at the routing stage is waited for (`settleQuitStart`), and `settleQuitSlotStart` then reads the start's outcome from `startState.result`, a `startResult` the goroutine sets before it reports, because the quitting flow drops the `startDoneMsg`, and settles only a refusal (`lifecycle.RestartStillOwed`). `main` waits for the restart either way. Two ways out start the owed restart while the alt screen is still up, and go back to the picker: backing out of the replace dialog (`dropSlot`) and a refused start that ends under a cancel (`finishStart`). They call `lifecycle.SettleRoutesTo` with `settleOut`, a `startOutput`, so what that restart prints from its goroutine (a warning, the cut-off notice) is kept off the picker, and the notice that the proxy is finishing a request in flight goes to the next screen that waits on it (`startOutput.RestartNotice`, `drainView`); `flushRouteNotes` prints what was kept with the route notes, and `flushRouteNotesAfterRun` then releases it, so a restart that outlives the picker prints straight to the terminal. The settles made after the alt screen pass no writer and print to stderr.
- **Commands.** `wt profile list` prints `writeSlotProfileList` whatever `profiles.toml` did. `wt profile show -A <agent> -M profile/<name>` is `showSlotProfile`: one probe, `catalog.Build` with the opt-in input, `catalog.Find`, then `agents.BuildSlotCommand` with the key already masked (`maskKey`), so the real key cannot reach the output. `wt stats` gives a profile's launches a row with no spend (`isSlotProfileID` in `buildUsageRows`).
- **The probe sees the last restart.** `internal/lifecycle` remembers the outcome of the most recent proxy restart attempt in the wt process (`lastRestart`, set by `RestartProxy` and by the asynchronous `bounceProxyAsync`, nil when it worked). `lifecycle.ProbeProxy` returns `the last LiteLLM proxy restart failed, so routes written since may not be live: <cause>` before it probes anything, because a proxy that was not restarted is usually still up and answers its liveness check while it rejects every route written since it booted. The refusal stands until a later restart succeeds or a new wt process starts. A restart still in flight has recorded nothing yet, so both paths call `lifecycle.WaitPendingRoutes` (the `waitPendingRoutes` seam) immediately before the probe; `RestartProxy` also waits for one first.

## Sessions (Go)

wt does not manage agent sessions and never resumes one (#198, #204): no lookup, no prompt, no resume flag, on any launch path. `BuildLaunchCmd` appends the user's passthrough args unchanged, so continuing a conversation is the agent's own flags after `--` — in the picker too:

| | Continue the latest | A specific session | Fork it |
|---|---|---|---|
| claude | `claude-wt -- --continue` | `claude-wt -- --resume <id>` | `claude-wt -- --continue --fork-session` |
| opencode | `opencode-wt -- --continue` | `opencode-wt -- --session <id>` | `opencode-wt -- --continue --fork` |

claude's `--continue` means "the most recent conversation in the current directory", and wt starts the agent in the worktree (or, with `--cwd`, the directory the command was typed in), so it finds the sessions for that directory.

> **Don't bring the lookup back.** wt used to find the newest session recorded for the launch directory and add the agent's resume flag itself (the `Resumer` capability, `agents.ResumeSession`, the `internal/session` package, opencode's `opencode db` query, the picker's resume prompt, `--debug-session`). That appended a one-shot run (`-- -p "..."`) to whichever conversation was newest, including one another process was using (#204), failed an opencode launch whose resumed session had stored a different model (#198), and doubled the flag when the user passed their own. All of it is removed; claude's project-directory slug survives only as the unexported `claudeProjectSlug` in `internal/agents/claude.go`, for `StateDir`.

> **Native models are not special-cased.** Whether a resumed session's stored model overrides the chosen one is the agent's behaviour; wt does not guard against it.
