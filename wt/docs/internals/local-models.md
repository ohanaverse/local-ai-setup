# wt local models: rows, inventory, lifecycle, rotation

Internals reference for `wt/`, reached from [`wt/CLAUDE.md`](../../CLAUDE.md). Backticked paths are relative to `wt/` unless they start with `../`.

## Local-model resolution

Every model row wt shows or resolves — the TUI picker, `wt start`/`wt smoke`'s picker, and the non-TUI launch path — is built by `internal/catalog` from the agent's eligible list plus one `localmodels.Inventory` snapshot. The TUI only decorates rows (counts, survey, sort, rendering).

- **rows** — local rows come only from the inventory (#179 Phase B): a registry local model is listed when its entry is running, on disk, or of a family whose discovery failed (status `unknown`, so a flaky probe hides nothing); one confirmed missing from disk, a non-running model of a running-only family (`localmodels.RunningOnly`: an `mlx_lm_server` pairing), or one with no inventory entry has no row. A registry entry is an overlay matched by family + `model_name` (`source.matchArtifact`, `inventory.go`); unmatched artifacts are `new` rows under `config.DiscoveredModelID`, hidden whenever `-T`/`-F` is set. A hidden registry id still reserves its id, so an unregistered artifact spelling the same id is not listed under it.
- **launch** — a cloud row, or a local model the probe reports running.
- **start** — a non-running local row of ollama/omlx/omlx-6bit/mtplx (a pulled ollama model is a start, not a launch).
- **block** — a non-running row of a provider with no start engine (`modelman start <id>` hint; a stopped `mlx_lm_server` pairing has no row at all, so its pin gets the same hint from `MissingReason`). Separately, an `Unmapped` cloud model (its provider has no `PolicyFor` mapping, so sync never routes it) is refused ("not in LiteLLM") when its route goes through the proxy, and launches normally direct (LiteLLM off). A discovered model is never refused (#179 Phase B: wt routes it under its discovered id). The rule and its wording are `catalog.Row.RefusedByRoute`/`RouteRefusal`; `renderTable` (TUI), `pickerBlockedReason` (non-TUI) and `wt smoke` apply it.

**Inventory** (`localmodels.Inventory(cfg)`): probes ollama (`/api/tags` + `/api/ps`, cloud `remote_host` entries excluded), omlx/mtplx (model-dir scan + what the server is serving, `localmodels.ServedIDs`; the two scans differ — mtplx's directory is flat `org--name` directories (`scanModelDirs`), while omlx's is scanned two levels deep as omlx itself does (`scanOmlxModels`, after omlx 0.7.0 `discover_models`): a top-level directory holding `config.json` is a model named after it, one without is an organization folder whose child directories holding `config.json` are models named after the **child**, a directory holding `adapter_config.json` is a LoRA adapter and never a model, a name found twice is listed once, and a model dir that is itself a model (`config.json`, no `adapter_config.json`) is the one model, but only when nothing else was found and the scan saw no Hugging Face cache entry at the top level (omlx may have registered a model from it, and then its own fallback does not fire). The shared fixture `docs/contracts/omlx-model-dirs.sample.json` pins this scan and modelman's `omlx_model_dirs` to the same names for the same trees. The folder itself is never listed. Hugging Face hub cache entries (`models--Org--Name/snapshots/…`), which omlx also resolves, are not listed. The names must equal the ids of omlx's `/v1/models/status`, which `Pool.Find`, `matchArtifact` and the load/unload requests match on. A test that builds an omlx model directory uses `localmodels.MakeOmlxModelsForTest`, since a bare directory is not a model) and mlx_lm_server (running only — `/v1/models`, no artifact discovery, so `ArtifactKnown` stays false; with 2+ registered pairings and none name-matching a served id it is `partial` + `Snapshot.Ambiguous`, since `/v1/models` lists HF repo ids, never a `+draft-` pairing name) concurrently. Per-family status `ok` / `partial` (the running-state probe failed, so `Running` is untrustworthy) / `unreachable` (discovery failed); a refused connection also sets `Snapshot.Down`. **Never reads modelman's `running` flag.** Probe origins resolve here (`FamilyOrigin`; `FamilyOriginPort` returns origin *and* port from one resolution, so a command-line port and dialed URL cannot disagree) and are shared with `internal/lifecycle`, so both describe the same server. `Entry.ArtifactKnown` distinguishes "confirmed missing" from "could not determine".

**`wt served <provider>`** (`cmd/wt/model_cmds.go` `runServed`) prints `ServedIDs` for omlx, mtplx or mlx_lm_server and exits 1 on a probe error, never an empty list. modelman's omlx probe calls it when omlx refuses its keyless status request, because only wt resolves a `secret_ref`.

**omlx's `/v1/models` is not what is running (#201).** It lists every model in omlx's engine pool — the whole model directory, minus hidden ones — loaded or not; read as "running" it made every omlx model on disk a launch row, a sync route and a stop candidate for as long as the service was up, and made a start into an idle server ask to "replace" a model that was never loaded. `localmodels.ServedIDs(cfg, client, family)` is the one answer to "what is this server serving", used by both the inventory (`probeFamily`) and the lifecycle occupancy re-probe (`liveServed`) so they cannot disagree. For omlx, `localmodels.OmlxPool(cfg, client)` is the one reading (`Pool`: `Models` with `Loaded`/`Loading`/`Pinned`/`LastAccess`/`Size`, the `Ceiling` and `InUse` memory, and `SizesKnown`), carried on `Snapshot.OmlxPool` so the picker, the occupancy check and the eviction plan read the same data, and `ServedIDs` is its loaded-or-loading models. It asks `/v1/models/status` **first**, with the registry key — that endpoint reports on-disk ids (an aliased model is not mismatched), includes hidden models and says `is_loading`, so none of those cases needs special handling. It is behind omlx's management auth — it wants the server's API key whenever one is set, even on loopback, unlike `/v1/models` under `allow_unauthenticated_inference` — so the key is the registry omlx provider's `auth.secret_ref` (`localmodels.FamilyAPIKey`), sent only then. Only when status refuses or does not answer does the reading fall back to `omlxLoaded`'s `/health` (no key; the pool's `model_count`/`loaded_count` — zero loaded is "nothing" on a healthy (2xx) answer, while on the 503 omlx sends while pinned models preload, zero built still asks status) plus `/v1/models` (the list counts as the loaded set **only when it is as long as the pool** — a hidden model is counted, not listed), and then `SizesKnown` is false: the loaded set is known, the sizes are not. Mixed counts that status will not explain are an **error**, i.e. `StatusPartial` / `*OccupancyUnknownError`, never a guess. An omlx with no `/health` counts falls back to the list. mtplx and mlx_lm_server serve one model per process, so their list is the answer. A listed-but-unloaded omlx model is therefore a **start** row (the start loads it with `POST /v1/models/{id}/load`; omlx itself would load it on first request, but that hides a long load and a possible eviction). Two loaded omlx models are both routed, by sync and by a start alike (see Lifecycle). modelman's `_probe_running` applies the keyless half of the same rule (`_omlx_loaded`).

**A `-M` pin is looked up among ALL rows, discovered ones included** (`catalog.Find`). Its row decides: launch row → launch; start row → start flow; blocked → error with the row's reason; no row → `catalog.MissingReason` (`<id> is not on disk — pull or download it first`, or the `modelman start` hint for a running-only family), else "not in the eligible list". The TUI pin, `wt start` and `wt smoke` use the same fallback. A table with no rows at all — on entry or after a refresh — routes back to the agent picker with `catalog.NoRowsReason`.

**Non-TUI (`cmd/wt/resolve.go`):** with no `-M`, only launch rows are eligible (`launchableModels`) — rotation never hands an agent a server that is not up, a start row is never auto-selected (only a pin may start one), and rotation (`NextFromEligible`, which walks `cfg.Models`) never lands on a discovered row. `startForLaunch`: stderr progress, Ctrl+C cancels (second Ctrl+C exits wt), an occupied provider needs TTY `y/N` or `--replace`. In the TUI, `--replace` covers only the pinned row. Both paths use `lifecycle.StartErrorMessage`. No launchable match → "no cloud or running local model for agent X — start one with `wt -M <id>`".

## Lifecycle (`internal/lifecycle`)

Go port of modelman's start/warmup: `Start(ctx, cfg, Target, Options{AllowReplace, Progress, OnUnloaded})`, `Stop`, `StopModelDeferred` + `SettleRoutes` (one proxy restart per batch, #142), `Evictions`. Backends: ollama (`Shared`; daemon must already answer — wt never kickstarts it), omlx (`Pool`: `omlx start` if down, then `POST /v1/models/{id}/load`; a model stop is `/unload`), mtplx (`Exclusive`; `mtplx serve` in its own session with modelman's pidfile/log paths; torn down on failure/cancel). Writes nothing to modelman state. Used by the TUI start flow, `startForLaunch`, `wt start`, and `wt smoke`.

- **A keyed omlx (#256).** omlx started with an API key answers 401 to keyless `/v1` requests, chat completions included, unless it allows unauthenticated inference. The omlx warmup (`omlxWarm`) therefore sends `localmodels.FamilyAPIKey(cfg, "omlx")` as a Bearer token; the liveness probe stays keyless, since `probe` counts any HTTP answer, a 401 too, as "up". `env.warmup` ends on the first 401/403 with `*KeyRefusedError` (`KeySent` tells a missing key from a refused one) instead of polling out `warmupTimeout` — for every backend, though only omlx passes a key. `lifecycle.Warm` / `wt warm <provider> <model>` (`cmd/wt/model_cmds.go` `runWarm`) is that warmup alone, omlx only, for modelman's fallback. **Keyless-inference mode.** An omlx with an API key and `allow_unauthenticated_inference = true` answers a keyless `GET /v1/models` and `POST /v1/chat/completions`, and `/health`, but refuses its management endpoints without the key: `GET /v1/models/status`, `POST /v1/models/{id}/load` and `POST /v1/models/{id}/unload` all answer 401. A registry with no `auth.secret_ref` on the omlx provider is the common local setup, so wt sends no key there. A start still works: when `/load` answers 401/403 and no key was sent, `omlxLoad` falls back to `omlxWarm`'s keyless chat completion, on which omlx loads the model (a server that refuses inference too answers that with `*KeyRefusedError`, at once). A key that was sent and refused gets no fallback. What wt cannot do in this mode follows from one fact: without the key wt cannot see **which** models are loaded in a partly loaded pool. `/health` gives counts only, so `omlxLoaded` returns an error ("omlx has N of M models loaded and would not say which") and the omlx family is `StatusPartial`. That is the ordinary state as soon as the pool holds more than one model and one is loaded; only an empty or fully loaded pool reads (`OmlxPool`'s fallback, `SizesKnown` false). While it is partly loaded: (1) no omlx model reads as running — in the picker, `wt served` (exit 1), `wt stop`, or `wt start --plan` (`unknown`); (2) a second start normally gets `*OccupancyUnknownError`, the "cannot tell — replace?" prompt. The named-victims prompt is the exception, when every pool model is loaded and `poolVictims` names every other one; (3) wt cannot size the pool, predict evictions or report them, and `reconcilePool` does nothing without a status reading; (4) `wt litellm sync` does not correct the routes: it freezes an untrusted family (`untrustedFamilies` → `UntouchedFamilies`) and warns, so the route of a model omlx evicted stays until the pool is empty or fully loaded; (5) `wt stop <model>` ends at `model "<id>" is not running` (`unknown model "<id>"` for a discovered model with no registry row), because `stopCandidates` drops entries that are not `Running` or whose family probe is untrusted — including a model wt just started through the fallback. Only when every pool model is loaded (a one-model pool included) does the stop reach `omlxUnload`, which returns an error that unwraps to `*KeyRefusedError` and names both ways out; it never falls back to stopping the service, because a model stop must not take siblings down; (6) a model omlx cannot fit or does not know fails the chat warmup with a non-401 error, which is polled for the whole warmup budget as on `main`, instead of the immediate `*NoRoomError` / not-found errors `/load` gives. The two ways out of all of it: set `auth.secret_ref` on the registry's omlx provider, which gives full pool behavior, or run `wt stop omlx`, which stops the service and removes the family's routes. Not covered: the LiteLLM route still carries `api_key: not-needed` (`internal/litellm/policy.go`), so a keyed omlx that refuses unauthenticated inference starts but is not reachable through LiteLLM.
- **Tenancy and the eviction plan** (`tenancy.go`, `evictions.go`). `TenancyOf(providerID)` says how a family holds models: `Exclusive` (mtplx — a start replaces the occupant, a stop stops the process), `Shared` (ollama — loads beside, nothing is displaced), `Pool` (omlx — loads beside and may evict, a stop unloads one model); every caller switches on it. `Evictions(t, snap)` returns the running models a start is expected to displace plus `known`: `Exclusive` the one other occupant, `Shared` none, `Pool` the plan. The plan fits the target when `InUse + size(target) <= Ceiling - Ceiling*poolAdmissionMarginPct/100`; the margin (15%, one constant) exists because omlx begins evicting at `ceiling * soft_threshold`, not at the ceiling. `soft_threshold` defaults to 0.85 and omlx does not report it, so wt assumes the default; a prediction against the ceiling itself, or with a smaller margin, says "fits" on loads that evict. When it does not fit, wt walks the other loaded, unpinned models by `LastAccess`, oldest first, until the projection fits; a walk that never fits names every unpinned model, and omlx gives the final answer at load time. With `SizesKnown` false or no ceiling, every other loaded model is named (the loaded set is still known, so `known` stays true). A target absent from the pool reading has size zero. `known` is false, for any tenancy, only when the family's probe is not trusted — that alone yields `*OccupancyUnknownError`. A family whose probe was refused (`Snapshot.Down`) is the exception: nothing is serving, so the plan is known and empty, and `wt start <id> --plan --json` on a cold server answers `fits`. The engine still re-probes such a server before it acts (`resolveEvictions`), in case it came up since the snapshot. The prediction can miss, so the omlx start (`omlxLoad`, `omlxpool.go`) reads the pool before and after the `/load` and `reconcilePool` handles whatever omlx unloaded: it removes each such model's route (deferred; `e.restartOwed` makes `Start`'s one settling bounce apply it), prints `wt: omlx unloaded <id> to make room` (marked `(not predicted)` when the plan did not name it) and calls `Options.OnUnloaded`. It runs **on failure too**, since omlx can evict before a load fails. It acts only on a status reading (`SizesKnown`): the fallback reading names models by the list's ids, an alias included, so a still-loaded sibling can be missing from it, and a fallback or failed reading therefore changes nothing and leaves the routes to `wt litellm sync`. A refused connection during the load ends it at once (omlx went away, most likely out of memory) instead of being retried for the whole budget. omlx answers 507 with `*NoRoomError` (its `detail` names what holds the memory) and 401/403 to a key the registry named with `*KeyRefusedError`; a keyless load that is refused falls back to the chat warmup (see "A keyed omlx" above). The load carries the registry key and is bounded by `warmupTimeout`.
- **Never replaces without `AllowReplace`** (`*OccupiedError`, whose `Occupants` lists the Exclusive occupant or the Pool victims). If the probe cannot determine occupancy (a single-model server accepted then stalled, or answered unusably) it returns `*OccupancyUnknownError` rather than assuming empty; connection refused is an ordinary cold start. Failure wording: `message.go` (`StartErrorMessage`, `StageLabel`).
- **Route hook** (`routes.go`): after a successful start/stop, `config.yaml` routes are updated via `internal/litellm` — a started model is routed under the catalog row's own id (`StartRouteChange` resolves `Target.ModelID`: the registry model with that exact id, else `litellm.DiscoveredModel`; `litellm.ModelFor`'s name match is the fallback only for a `Target` with an empty `ModelID`); an `Exclusive` start (mtplx) removes every marked route of the family (`Change.RemoveFamilies` — discovered siblings included, plus the family's registry ids; never a hand-written row; minus the started id), while a `Pool` start (omlx) adds the one id and removes only the ids of models it evicted (`poolRouteIDs`: the entry's own id when it is a catalog row id, plus the id of every registry model that names the model under any provider id of the family — `localmodels.FamilyProviderIDs`, so an `omlx` row and an `omlx-6bit` row naming one directory both go; the discovered id is the fallback, used only when none of those gave an id), never the family — clearing it is what once made sync and the start hook undo each other with two models loaded (#213); a stop removes with `routeRemoveModel` (`Exclusive`: the family; `Pool`: that model's ids, its loaded siblings keep theirs; `Shared`: nothing) and `lifecycle.Stop` of a whole provider with `routeRemoveFamily`; ollama adds one on start; stop leaves an ollama route in place (a pulled model stays routed — #179). The hook runs only when wt performs the start/stop. A launch row (already running, perhaps started outside wt) gets the launch-time route check instead, `lifecycle.EnsureModelRoute(cfg, model) bool` (#192): for a local model, or a registry cloud model sync would route (`litellm.CloudModels` — the repair for a config.yaml that lost its cloud rows; sync still owns keeping them current, so the cloud change is `Change.AddMissingOnly`: a cloud row that is there is not rebuilt, which would resolve the provider's `secret_ref` on every launch — a warning in a shell without the key, a rewritten `api_key` and a proxy restart in a shell with another — and a row that is missing is a build the picker's non-blocking form defers, `Options.DeferMissingAdd`, #253), it writes the model's route if it is missing, prints `wt: LiteLLM route for <id> updated` on stderr when it wrote **that model's own row** (`litellm.Outcome.Written`, set by `applyPlanned` from per-row digests taken around the write — only when the plan adds a row, since nothing else can produce a `routed` outcome; a `routed` outcome is reported for every row a change sets, identical or not, and `Result.Changed` is about the whole file), and restarts the proxy only if the file changed. A write that changed the file some other way (#206: another row's `api_base` repair, an enforced `litellm_settings` key) prints that repair's own line or, with nothing more specific already printed, `wt: LiteLLM config.yaml updated` (`reportEnsured`, shared by both forms of the check) — the restart wait that follows must not come unexplained. It is Add-only — it never removes a route (no `RemoveFamilies`; stale routes are left to the next start, stop or `wt litellm sync`), never starts or stops a model, never replaces a hand-written row whose name is not a registry model id (one named like a registry id is adopted as wt's own row by `litellm.ApplyChange`, the rule `wt litellm sync` applies — guide 04, `docs/guides/04-litellm-config.md`, Gotchas) and never fails a launch. Callers: `launchFilteredImpl` (`cmd/wt/launch.go`: `-M` pin, single auto-resolved model, rotation) and the picker's `proceedToLaunch` (`internal/tui/app.go`), both only when the launch's route goes through LiteLLM; `wt start <running id>` (then `wt: <id> is already running`) and `wt smoke` on an already-running target, both unconditionally. LiteLLM failures only warn; a missing `config.yaml` is silent. It comes in two forms, differing only in how long they will wait for the `config.yaml` lock: `EnsureModelRoute` (bounded at `ensureRouteLockTimeout`, 10s; `EnsureModelRouteTo(out, …)` is the same check printing to the caller's writer) and `TryEnsureModelRouteTo`, which attempts the lock exactly once and reports `done == false` rather than waiting — for the TUI picker, whose update goroutine cannot block (see TUI). That form also sets `litellm.Options.DeferMissingAdd`, so a cloud model whose row is missing is named in `litellm.Result.Missing` instead of being built there: building it resolves the provider's `secret_ref`, and an `exec:` ref runs its helper synchronously, bounded only by `execSecretTimeout` (15s), which is the same freeze by another route (#253). A write that defers a row saves nothing at all — not the `litellm_settings` or `api_base` repairs either — so the retry makes the whole change in one write and the proxy restarts once, not once per attempt. Both "not established" outcomes report `done == false` and print nothing; the retry, through the blocking form, does the work and reports. `litellm.ErrRegistryRedirected` is the one failure it reports itself, with `done == true`: no wait changes a refusal. `Start` reports `StageRouting` before the hook.
- **`config.yaml` write is synchronous; restart + readiness wait are async** in a goroutine tracked by `WaitPendingRoutes()`. Every process exit must call it (`cmd/wt/main.go`, plus `runAgentCmd`'s exit-code propagation and `wt smoke`'s failure exit, which bypass main), **and every path about to hand the model to an agent must call it first** (`startForLaunch`, `start_flow.go` before `proceedToLaunch`, `smoke.go` before the first `RunRow`, and right after the launch-time route check: `ensureRouteBeforeLaunch` in `cmd/wt/start.go`, and the picker's `checkLaunchRoute` in `internal/tui/start_flow.go`, which waits in a command behind `phaseRouting` and only when the check changed `config.yaml`) — the agent talks through the proxy, so proceeding mid-restart gets a refused connection or the old route table. On the CLI paths that wait is the only stretch of a launch with nothing else on stderr to show for it, so `ensureRouteBeforeLaunch` announces it and repeats the line with elapsed time every `routeWaitInterval` (`waitForProxyRestart`) — the counterpart to the picker's `phaseRouting` screen. Which paths wait is the check's own return value: the write is the only thing that restarts the proxy (`restartIfChanged`), so an unchanged route — the common launch — prints nothing and its `waitPendingRoutes` returns at once.
- **Route output belongs to the operation:** everything `routes.go` prints (the `updated` line, every warning, the async restart's included) goes through one mutex-guarded helper, `routePrintf(ctx, …)`, to `routesWarn` (stderr) — unless the operation's context carries its own writer (`withRouteOutput`), which is how `EnsureModelRouteTo`/`TryEnsureModelRouteTo(out, …)` send one check's output to the caller. The writer rides on the context so that it follows the check into the restart goroutine (`context.WithoutCancel` keeps values) and nothing else: an unrelated operation's restart still in flight keeps printing to stderr instead of being collected as this check's (the process-wide `SetRouteOutput` redirect this replaced did exactly that — pinned by `TestRouteOutputIsNotSharedWithAnotherOperation`). `out` is safe to read only after `WaitPendingRoutes()`. The TUI picker is the one caller (below) — stderr is not reliably visible under the alt screen.
- **That goroutine runs on `context.WithoutCancel(ctx)` on purpose.** Callers `defer cancel()` the instant the hook returns; inheriting cancellation means the restart never runs. Don't "restore" cancellation propagation — `TestRouteRestartSurvivesCallerCancelAfterReturn` and `TestStartWrapperRestartSurvivesCancelledCaller` pin it. Restart warnings are therefore always printed.
- **Readiness wait:** before writing, `litellm.Listening` probes `/health/liveliness` once (1.5s; false only for refused/unresolvable, so a slow or 503 proxy counts as present). `WaitReady` (up to 30s) runs only if the hook restarted the proxy **and** that probe found a listener — a stopped proxy costs nothing.
- **Replace (`Exclusive`):** the occupant's route is removed as soon as it's stopped (`env.onOccupantStopped`, wired only by `defaultEnv`) so a start that then fails can't strand it; that write uses `litellm.Options.NoRestart`, and `Start` owns one settling bounce (`routeAfterStart`, or `bounceRoutes` on failure) — one restart per replace, not two; a `Pool` eviction's removal is written the same way (`reconcilePool`), so a start that evicts also costs one restart. `bounceRoutes` writes nothing, so it has no lock wait to bound — it only triggers the async, detached restart (`bounceProxyAsync`).

## Rotation (Go)

Global rotation: each successful launch records one model id in `~/.config/agent-wt/rotation.state` (atomic write); the picker cursor lands on the model *after* it (`FirstAfter`, shared by the picker and `wt rotate`). Launch paths call `rotation.RecordFor(agent, id)`, which also appends the agent-tagged usage event to `~/.config/agent-wt/usage.jsonl`. Rotation positions the cursor only when a last-launched registry model exists (else first launchable row) and never advances onto a discovered row.

- **The sort order is also the default selection.** `newPickModel` (the standalone `wt smoke`/`wt start` pickers) never calls `Select`, so its highlighted row is index 0; `enterModelPhase`'s no-rotation fallback picks the first actionable row. Native-first (#172) therefore makes a native model what a bare Enter launches there — deliberate, and pinned by `TestPickStartModelDefaultsToNativeRow` / `TestEnterModelPhaseNoRotationDefaultsToNativeRow`. Changing `sortRows` changes what Enter picks; don't add a display-only rule to it without deciding the default too.
- The last-launched row gets a `> ` prefix — **plain ASCII on purpose**: Unicode geometric shapes are East Asian Ambiguous width and misalign CJK terminals.
- The leftmost column is the live "in use" count from `refcount.Store.Counts` (2-rune prefix, clamped at 9), before the rotation marker.
- Columns: FAMILY, MODEL, LOC, STATUS, RUNNING, COST, 1D, 7D, 30D, SURVEY. `wt smoke`'s picker has no agent context: SURVEY is empty and usage uses model-level `Counts`.
- Sort: native models first (#172); then cloud + running local by cost (output then input price; local/subscription-only = $0; no-data last), then 7-day usage; non-running local alphabetical. Native-first is a *partition*, not an exemption: native rows still fall through to the group rules among themselves.
- TUI callers fetch the agent's full catalog once (`cfg.ModelsForAgent`), narrow it with `cfg.EligibleModelsIn` (single-traversal filter), and pass it to `enterModelPhase`.

```bash
go run ./cmd/wt rotate code    # debug helper: print the model after the last-launched in the "code" tag group
```

## Start/stop (`wt start`, `wt stop`)

`cmd/wt/model_cmds.go`; user-facing behavior in [docs/wt-start-stop.md](../wt-start-stop.md). Code notes:
- `wt start <id>` resolves through `catalog.Find` over `localRows` (locals on disk or running, registered or detected, one snapshot), falling back to `catalog.MissingReason` for an id with no row; no-arg uses `tui.PickStartModel` via the `pickStartModelTUI` seam.
- `wt stop` uses `survey.StopCandidates`, `survey.StopEntries` (shared stop loop), and `survey.PickerWith(..., Options{IncludeInUse: true})`; the no-arg picker probes once and reports whether it had anything to offer (`stopPickerAll`). A bare provider is validated against `stoppableProviders` (what `lifecycle.CanStop` accepts). A target on mtplx (`Exclusive`) widens to every running model of that provider (`withFamilyCollateral`); omlx models are never widened — `wt stop <omlx model>` unloads just that one (`POST /v1/models/{id}/unload`, the service stays up) and `wt stop omlx` calls `lifecycle.Stop`, which runs `omlx stop` and clears the family's routes. In-use targets go through `confirmStop` with `stopImpact` (sessions summed, an `Exclusive` provider counted once); `--yes` skips.
- `wt start <id> --json` (`start_json.go`, `runStartJSON`) never prompts. `--plan` prints the `Evictions` plan (`running`, `fits`, `would_unload` with each victim's live `sessions`, or `unknown`) and changes nothing; without `--replace` a start that would unload exits 1 with the plan on stdout; with it the start runs and prints `started`/`already_running` plus `unloaded` (collected through `Options.OnUnloaded`). A failure is exit 1 with the message on stderr and nothing on stdout. Both shapes are pinned by `docs/contracts/wt-start-cli.sample.json`, read by the Go test in `cmd/wt` (modelman's contract test lands with its omlx delegation).
