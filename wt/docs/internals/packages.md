# Packages and files

What each file of `cmd/wt` and each package under `internal/` holds, in full. [../../CLAUDE.md](../../CLAUDE.md#go-module) has the one-line version; read this before adding a file or a package, or when looking for the function that owns a behavior.

| Path | Purpose |
|---|---|
| `cmd/wt/main.go` | CLI entry point (cobra), exit-code handling |
| `cmd/wt/app.go` | shared dependency struct (loads/validates config and profiles.toml once); also loads and statically validates slot-profiles.toml (`app.slotChecks`, `app.slotLoadErr`; seam `loadSlotStore`) |
| `cmd/wt/commands.go` | `rotate` subcommand (debug helper) |

| `cmd/wt/profile.go` | `wt profile list/show/status/on/off`; `setEnabledLine`'s surgical `enabled = ...` edit |
| `cmd/wt/slot_launch.go` | the non-TUI slot-profile launch: `launchSlotProfile` (the ten steps, fail closed), `applySlotProfile` (the fail-closed applier both paths use), `runSlotAgentCmd` (run and post-exit), `slotWarnings` (the load error, each unknown key through `slotUnknownKeyNote`, each unusable profile, `slotReservedNote` for a taken `profile/` prefix, and `slotContentNotes`, the drivers' `config_content` warnings, worded per profile by `slotContentNotesFor`; `runLaunchPath` prints them before the TUI and again after it), the `slotPin` sentinel `resolveModel` returns, `launchSlotChecks`; seams `ensureSlotRoutes`, `restartProxyNow`, `probeProxyNow`, `settleRoutesNow`, `startSlotModel`, `buildSlotCmd` |

| `cmd/wt/exitcode.go` | `exitCodeError` / `exitCodeOf` — how one command exits with a status other than 1; `reportExit`, main's `wt:` line (none for a quiet error); `agentExitStatus`, a picker launch's agent status (#412) |
| `internal/config/` | config load/validate/save (agents + joined registry catalog), route resolution (`ResolveRoute`), migrations |
| `internal/provider/` | the ONE table of provider and family facts (`table.go`): which provider ids share a server (family), each id's LiteLLM `Policy`, its default registry `Seed` row and PATH command, and per family the default origin and model directory, the port wt hands the server, the running-only / served-only / routes-follow-artifact / served flags and the `Tenancy`; `provider.go` holds the types and accessors (`FamilyOf`, `PolicyFor`, `SeedRow`, `ProcessFor`, `ProcessFamilies`, …; a family's `Process *ProcessSpec`, `Ready` (with `EndpointPath`, the address a machine-scope instance reports) and `Scope` say how wt runs it as a process; mtplx, rec and sushi are the process families), which return copies. | `internal/slotedit/` | the only writer of `slot-profiles.toml`: `Add`/`Set`/`Remove` edit the bytes comment-preservingly, `Apply` validates the result and writes it atomically behind a `.bak-<stamp>` backup (keeps mode, writes through symlinks, refuses multi-line strings and dotted `slots.`/`env.` keys); `LeadingComments` reads the comment above each entry.
