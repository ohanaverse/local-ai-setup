# Packages and files

What each file of `cmd/wt` and each package under `internal/` holds, in full. [../../CLAUDE.md](../../CLAUDE.md#go-module) has the one-line version; read this before adding a file or a package, or when looking for the function that owns a behavior.

| Path | Purpose |
|---|---|
| `cmd/wt/main.go` | CLI entry point (cobra), exit-code handling |
| `cmd/wt/app.go` | shared dependency struct (loads/validates config and profiles.toml once); also loads and statically validates slot-profiles.toml (`app.slotChecks`, `app.slotLoadErr`; seam `loadSlotStore`) |
| `cmd/wt/commands.go` | `rotate` subcommand (debug helper) |
| `cmd/wt/commands_config.go` | `wt config` subcommand family; `runConfigEditor` opens the editor on a tab (bare `wt config`: Agents; bare `wt model`: Models) and runs the one route sync the Models tab owes |
| `cmd/wt/resolve.go` | `resolveModel` — single model for non-TUI launch from live `catalog` rows; a `-M` pin on a start row starts it |
| `cmd/wt/start.go` | `startForLaunch` — non-TUI start driver: stderr progress, Ctrl+C cancel, replace confirmation, `allowReplace`, the others question (`decideOthers`, #412); `startForLaunchOwed` is the same driver for a caller that already owes a proxy restart (a slot-profile launch), and returns `started <id>; launch cancelled` for a Ctrl+C that lost to the start |
| `cmd/wt/start_others.go` | the others question of a non-TUI start (#412): `othersFlag`/`othersMode` (the root `--others=keep\|stop`), `othersQuestion` and `askChoice` (`[s/k/N]`, through the `chooseOthers` seam on `/dev/tty`), `othersWarning` (the one no-TTY line), `stoppableIDs` |
| `cmd/wt/helpers.go` | `mustGetString`, `yolo`, `renderTable`; guard helpers; TTY seams and picker-TTY errors |
| `cmd/wt/launch.go` | `buildFilteredCmd`, `launchFiltered` (`launchFilteredImpl`), `launchPassthroughImpl`, `runAgentCmd`; profile apply (`applyProfileForLaunch`, `applyResolvedProfile`) |
| `cmd/wt/stats.go` | `wt stats` — read-only report: the survey table over `survey.jsonl`, then the usage table |
| `cmd/wt/stats_usage.go` | `wt stats`' usage half: `collectUsage` (launches from `usage.jsonl` joined with LiteLLM spend), `buildUsageRows`, the `querySpend` and `stdoutWidth` seams |
| `cmd/wt/stats_usage_table.go` | `renderUsageTable` — the usage table's cells, laid out by `renderPlainTable` |
| `cmd/wt/plain_table.go` | `renderPlainTable` — the one borderless, width-aware text table (`wt stats`, `wt model list`): the first column is the row's key and is never truncated |
| `cmd/wt/stats_json.go` | `wt stats --json` — `buildStatsJSON`, one document built from the same rows as the tables |
| `cmd/wt/model_cmds.go` | `wt start` / `wt stop` |
| `cmd/wt/smoke.go` | `wt smoke` — one-shot model×agent smoke test |
| `cmd/wt/profile.go` | `wt profile list/show/status/on/off`; `setEnabledLine`'s surgical `enabled = ...` edit |
| `cmd/wt/slot_launch.go` | the non-TUI slot-profile launch: `launchSlotProfile` (the ten steps, fail closed), `applySlotProfile` (the fail-closed applier both paths use), `runSlotAgentCmd` (run and post-exit), `slotWarnings` (the load error, each unknown key through `slotUnknownKeyNote`, each unusable profile, `slotReservedNote` for a taken `profile/` prefix, and `slotContentNotes`, the drivers' `config_content` warnings, worded per profile by `slotContentNotesFor`; `runLaunchPath` prints them before the TUI and again after it), the `slotPin` sentinel `resolveModel` returns, `launchSlotChecks`; seams `ensureSlotRoutes`, `restartProxyNow`, `probeProxyNow`, `settleRoutesNow`, `startSlotModel`, `buildSlotCmd` |
| `cmd/wt/profile_slots.go` | the slot-profile half of `wt profile`: `writeSlotProfileList`, `showSlotProfile` (which prints the shown profile's `slotContentNotesFor` lines under its slots, #419), and `maskKey` (the one rule for showing the proxy key, shared with `wt litellm status`) |
| `cmd/wt/litellm.go` | `wt litellm ...` |
| `cmd/wt/model.go` | `wt model` group — bare, it opens the Models tab of `wt config` (needs a terminal); `wt model init [--json]` — creates the registry and seeds provider rows, then one route sync (`syncRoutesAfterWrite`) |
| `cmd/wt/model_write.go` | `wt model add`, `edit`, `rm` — each one `modeladmin` write, then one route sync (`syncAndWarn`); the `ollamaCaps` seam, and `confirmRemove`, which is `wt stop`'s `promptStop` (it opens the terminal through `openTTY`) |
| `cmd/wt/model_list.go` | `wt model list [--json]` — `modeladmin.Rows` over one probe; `fitModelList` drops PATH, then SIZE, on a narrow terminal |
| `cmd/wt/cloudsync.go` | `wt cloud-sync` — the command, both flows' plans printed, the one confirmation, the one `config.UpdateRegistry` both flows share (`writeCloudSync`: each plan is made again under the lock; a flow whose plan changed is marked stale and not applied, and when no flow is left the `apply` returns `errPlanChanged`, so nothing is written and a missing registry is not created), the route sync, the exit code (`cloudSyncOutcome.err`); the openrouter flow's fetch (`planOpenRouterFlow`); seams `cloudFetch`, `confirmCloudSync`, `cloudSyncNow` (the prompt opens the terminal through `openTTY`) |
| `cmd/wt/cloudsync_catalog.go` | the ollama flow: `planOllamaFlow` (the skip on a registry with no ollama provider row, page or `--html`, `ollama list`, tag resolution, the duplicated-id refusal, the printed plan; exit 2 and 3), `ollamaGate` (mass removal, the removal digest; exit 4 and 5), `runOllamaWork` (the daemon named once, then pulls, then removals, after the registry write), `saveFailedHTML` (always a new 0600 file) |
| `cmd/wt/cloudsync_ollama.go` | the ollama CLI for the ollama flow: `ollamaTags` (`ollama list`, cloud stubs included), `ollamaPull`, `ollamaRemove` (ollama's "model '<tag>' not found" is done; the answer must name the tag), all through the `ollamaCLI` seam, pinned with `OLLAMA_HOST` to the registry's ollama origin; `ollamaFailure` (one line of stderr, escapes stripped), `ollamaTimedOut` (wt's own limit, said as a timeout), `cmd.WaitDelay` so a wrapper script's child cannot hold a stopped command open |
| `cmd/wt/exitcode.go` | `exitCodeError` / `exitCodeOf` — how one command exits with a status other than 1; `reportExit`, main's `wt:` line (none for a quiet error); `agentExitStatus`, a picker launch's agent status (#412) |
| `internal/config/` | config load/validate/save (agents + joined registry catalog), route resolution (`ResolveRoute`), migrations |
| `internal/provider/` | the ONE table of provider and family facts (`table.go`): which provider ids share a server (family), each id's LiteLLM `Policy`, its default registry `Seed` row and PATH command, and per family the default origin and model directory, the port wt hands the server, the running-only / served-only / routes-follow-artifact / served flags and the `Tenancy`; `provider.go` holds the types and accessors (`FamilyOf`, `PolicyFor`, `SeedRow`, `ProcessFor`, `ProcessFamilies`, …; a family's `Process *ProcessSpec`, `Ready` (with `EndpointPath`, the address a machine-scope instance reports) and `Scope` say how wt runs it as a process; mtplx and rec are the process families), which return copies. A leaf (standard library only), so `config`, `localmodels`, `litellm`, `lifecycle` and `cmd/wt` all read it. Facts only — probes, start/stop and name matching stay in the packages that own them. `lifecycle`'s `TestBackendsMatchProviderTable` keeps its backends in step with the table |
| `internal/tomlw/` | ordered TOML document (`Decode`, `Table`) and an emitter (`Encode`) that reproduces tomli-w's layout byte for byte — what lets a wt write leave every line it did not change as it was. Imports nothing from wt; never use the stock `toml.Encoder` on the registry (it sorts keys and shifts local dates) |
| `internal/cloudsync/` | the pure core of `wt cloud-sync`: `ParsePricing` (the only code that knows ollama.com/pricing's HTML; `golang.org/x/net/html` tokenizer, fail-loud `*ParseError`), `ResolveCloudTags`/`VerifiedTags`, `PlanCatalog` (+ `EntriesGone`, the one count `MassRemoval` and the exit-4 line both use, `RemovalDigest`, `Format`), `ParseOpenRouter`/`PlanPrices`, the two `Apply` methods that change a `config.RegistryDoc` (sharing `applyGraduations`), and `format.go`, the blocks of the two `Format`s that read the same in both flows (graduated, kept, removal digest). No I/O, no clock: see [Cloud sync](cloud-sync.md) |
| `internal/tiers/` | read-only reader of modeltiers' `tiers.toml` (`Path` follows modeltiers' rule, `MODELTIERS_OUT` first; `Load` never fails; `Index.Rating` by provider id + model name; `Entry.Context` is models.dev's window for a cloud model and `Entry.ContextBasis` where it came from (`host` or `largest_row`); `agents.claudeWindow` declares a `host` window alone (#405, #470); `Entry.Cell` is the TIER cell, `Entry.Short` a slot's form on the slot line, `Entry.Notes` the mode line's long forms); `contract_test.go` parses `../docs/contracts/tiers.sample.toml` and asserts known entries' codes and aligned scores |
| `internal/rotation/` | global rotation state (`rotation.state`) + next-model selection; `last-picked.state` (the picker's marker: `LastPicked`, `RecordProfile`), which a slot-profile launch writes without moving `rotation.state` |
| `internal/usage/` | append-only JSONL launch history (1d/7d/30d); `RecordFor` tags the agent; `CountsForAgent` per agent×model, legacy agent-less lines count toward `Counts` only; `(*StoreImpl).AllCounts(agent, asOf)` enumerates every model in the file, bucketed against the caller's instant (for `wt stats`; not on the `Store` interface) |
| `internal/refcount/` | live-session "in use" counts: JSONL keyed by pid, swept for dead pids on every launch, recorded at each launch path's commit point; `RecordAll` records one line per distinct slot model of a profile session; `SessionCounts` (`LiveCounts` over the default store: sweep, then count) is what both replace confirmations name per occupant (#412) |
| `internal/survey/` | post-session survey + stats; stop picker and stop loop (`Picker`, `PickerWith`, `ReadStopState`, `StopEntries`) |
| `internal/agents/` | driver abstraction (`BuildLaunchCmd`, capabilities), picker catalog, drivers, `RunAndCleanup` (shared apply-run-cleanup core for both launch paths), `BuildPassthroughCmd` |
| `internal/profiles/` | launch-profile overlays — see [Profiles](launch-flow.md#profiles-internalprofiles); and slot profiles: `slot.go` (`SlotProfile`, `LoadSlots`, `ParseSlots`, which fails the whole file on a wrong TOML type and lists the keys the schema does not name in `SlotStore.Unknown`, `SlotPath`, the `SlotCapable` driver interface, `MergeConfigContent`) and `slot_validate.go` (`ValidateSlots`, `SlotCheck`, and `SlotDrivers`, the callbacks static validation asks the drivers through, `ConfigContent` among them: the agent's own `config_content` rule) — see [Slot-profile launch](launch-flow.md#slot-profile-launch) |
| `internal/smoke/` | `wt smoke`'s core: `Eligibility`/`Candidates` (rows per agent from one inventory snapshot; `Eligibility` returns both the model union and per-model agent lists), `RunRow` (PASS/FAIL/SKIP via the `buildAndRun` seam) |
| `internal/catalog/` | the shared row policy for every model list wt shows or resolves: `Build` (local rows only from the inventory), `Find` (includes discovered rows), `MissingReason` (why a pinned registry id has no row), `Row.Action` (launch/start/block), `Row.BlockReason`, presence status (`ok`/`unknown`; `new` for discovered, including discovered models handed in via `Input.Models`). No rendering, counts or sorting; `profile.go`: slot-profile rows (`ProfileRow`, `ResolveSlotProfile` — resolved validation, whose last per-slot rule is `lifecycle.Routable`, and which gives a row blocked by any rule the `Running` and `Loading` of its one local model (`slotLocalState`) — and `SlotPrefixReserved`/`SlotPrefixHolder`, the one predicate for the reserved `profile/` prefix: a provider with id `profile`, or a model id that begins with `profile/`), emitted only for an `Input` that sets `SlotProfiles` |
| `internal/localmodels/` | local inventory — see [Local-model resolution](local-models.md#local-model-resolution); `Entry.LoadedSize` (the memory a running model holds, as its server says), `OllamaLoaded` (each loaded model's name and `/api/ps` size, `OllamaModel`), `FormatSize` (sizes as `ollama list` prints them, for `wt model list`, the Models tab and the start engine) |
| `internal/modeladmin/` | the core of model management, shared by the `wt model` commands and the Models tab, with no UI import: `Rows` (every registry model and every discovered one, with status, running, path and size — nothing hidden, unlike `catalog.Build`), `WeightsNote`; `Add`, `Edit`, `Remove` (each one `config.UpdateRegistry`, no route sync), `CheckAdd` (what an add refuses without the registry, for a caller with a slow lookup to run first), `Fields` and `FieldError` (the editable fields as typed, and which one is wrong), `DeriveID`, `OllamaCapabilities` |
| `internal/lifecycle/` | local-model start/stop engine — see [Lifecycle](local-models.md#lifecycle-internallifecycle); `Resident`, `OthersAnswer` (`Options.Others`) and `OccupiedError.Others`/`OthersUnknown`: other providers' models loaded beside a start's target, `residentOthers` in `evictions.go` (#412); `profile_routes.go`: `EnsureModelRoutes`, `RestartProxy`, `ProbeProxy` for a slot-profile launch; `Routable` (`routes.go`) is the predicate `EnsureModelRoutes` fails on, exported for the catalog's resolved validation; `server.go` (`processServer`, the one backend of every `provider.ProcessFamilies()` family: spawn, stop, `serverEndpoint`/`serverStartEndpoint`, `PortlessAddressError`, the machine-scope adopt/stop), `server_loading.go` (identity of a server still loading, `loadingServer`/`stopLoadingServer`/`forgetServer`; was `mtplx_loading.go`) and `ready.go` (`readyNow`/`waitReady`: models-list and command-json readiness) — the mtplx-only `mtplx.go` and `mtplx_loading.go` are gone |
| `internal/litellm/` | the sole implementation of LiteLLM `config.yaml` route management: `configfile.go`, `entry.go` (entries), `policy.go` (`Policy` and `PolicyFor`, over `internal/provider`'s table), `service.go` (`ApplyChange` — the targeted route writer the lifecycle hook uses, its unit `Change` with `RemoveFamilies`; `DiscoveredModel`, `RowFamily`; `Sync`/`PlanSync`), `restart.go` (`RestartContext`, `Listening`, `WaitReady`), `dburl.go` (`DatabaseURL` — the spend database's connection string; reads, never writes) |
| `internal/spend/` | per-model request, token and cost totals from the proxy's `"LiteLLM_SpendLogs"` table: one aggregated query through `psql` (`Query`) over the window `(start, end]` (`InWindow` — the launch counts' rule, and what a test's spend stub filters with), typed failures (`ErrNoConnectionString` for a blank string and `ErrConnectionString` for one that cannot be handed over, both refused before `psql` is looked for; `ErrNoPsql`, `ErrUnreachable`, `ErrQuery`), no Postgres driver. `conn.go` turns the connection string into libpq's `PG*` environment variables — it is never a `psql` argument (#282), and `psql` inherits no `PG*` variable from wt |
| `internal/guard/` | `block-main-commit` pre-commit hook |
| `internal/rootclaim/` | what both launch paths share around `sessionclaim`: `Lookup` (the root checkout, its git common directory and branch through `internal/worktree`), `Root.Self` (this process's claim) and `Choose` (the plain-terminal menu and its one key: c, w, q/Esc/Ctrl-C/end of input). Runs no git itself, but links `internal/worktree`, so its `TestMain` isolates git |
| `internal/sessionclaim/` | the root checkout's session claims: `Claim`, `Self` (this process's claim, start time from `ps -o etime=`), `Join` (under an flock on `wt-sessions/.lock`: prune stale claims, list the live others; with none, write this claim atomically under the same lock, else unlock, call `ask` and relock to write; returns `release`; both scans skip claims of this process's ancestors), `Others` (the same read without the lock or any change, for the picker's screen), `Menu`/`Describe`/`CheckFailed`/`NewWorktreeName` (`describe.go`, the text both launch paths share). A claim is live when its pid runs and its start time matches within 2 s. Imports only `internal/config` (no git: `internal/rootclaim` does that); the file format is [docs/contracts/session-claims.md](../../../docs/contracts/session-claims.md). `cmd/wt/sharedroot.go` and `internal/tui/sharedroot.go` are its two callers, through `internal/rootclaim`; see [Shared-root check](launch-flow.md#shared-root-check-internalsessionclaim) |
| `internal/worktree/` | repo detection, enumeration, creation; `prs.go`: `PRs` (each branch's pull request from one `gh pr list` listing, `PRListOpen` or `PRListAll`, through the `listPRs` seam; any failure a loaded, empty set), `MergePRs` (two listings joined per head, open over closed or merged, else the higher number), `PRSet` (one listing or several joined: `ByHead`, each head's PR keyed by `PRKey` — the lower-cased head repository and the head branch, a fork's PR under its own repository (#387), one whose head repository is gone dropped — and `BaseRepo`, a same-repository PR's head, "" when none, which marks the listed repository's PRs as yours for `ForBranch` and is named in the picker's `no remote is …` notice; `ForRemote` is a remote row's lookup by its repository and branch, `ForBranch` a local row's: under the repository its branch pushes to or tracks (`Entry.TrackRepo`) alone, else among the PRs from `BaseRepo` and from the `RepoSet` it is given (the remotes' repositories), never a stranger's fork, by `preferPR`; `HasHeadRepo`, `HasBranch`; `EmptyPRSet`, the loaded set with no PRs; `Loaded` is whether any listing has answered), `PRBranch` (the head branch a worktree or local row is looked up under, and a remote row's display name), `StubPRListForTest`; `remotes.go`: `RemoteRepos` (each remote's owner/repo from its fetch URL in one `git remote -v`, which applies `insteadOf` rewrites, the host ignored, "" for a local path or `file://`), `RepoSet`/`NewRepoSet` (a set of owner/repo names, lower-cased; `EnumerateRepos` returns every remote's, which the picker hands to `ForBranch`), `SplitRemoteBranch` (a remote-tracking name split by the longest known remote), which `Enumerate` uses to fill `Entry.RemoteRepo` and `Entry.RemoteBranch` (and `Entry.TrackRepo` for local rows, from each branch's push/upstream remote); `EnumerateRepos` is `Enumerate` that also returns the remotes' `RepoSet`, so one `git remote -v` serves both; the picker tags a remote row only with the PR whose head is its `RemoteRepo` and `RemoteBranch` (#388, #387) |
| `internal/gitenv/` | the variables that decide which repository git acts on, and `IsolateForTest`, which every test binary that can run git calls from its `TestMain` (see [testing.md](testing.md)); imports nothing from this module |
| `internal/initseed/` | `--init` seeding |
| `internal/ollamacheck/` | pre-launch `ollama list` availability check, pinned to the registry's ollama address; `StubListForTest` is its seam (`fortest.go`) |
| `internal/configeditor/` | the TUI behind `wt config`: the Agents tab (`config.toml`; edits buffered, saved with ctrl+s) and the Models tab (`registry.toml` through `internal/modeladmin`: a table of `modeladmin.Rows`, `d` to remove, and the add / register / edit form of `models_form.go` on `n` and `enter`, hand-built on `bubbles/textinput` like the agent form; each change written at once from a `tea.Cmd`, the probe and the form's ollama lookup in a `tea.Cmd` too). A refused save stays on the form — the cursor on the field a `modeladmin.FieldError` names, any other refusal (`config.ErrModelAmbiguous`, a row the writer will not write back) shown as the save's error with nothing written. `Run` reports `Result.RegistryChanged`, and `cmd/wt`'s `runConfigEditor` then runs the one route sync the tab owes; a quit asked for while a write is in flight waits for it (`leave`, `quitPending`), so the result is never "unchanged" for a registry that changed, and is then an ordinary quit: agent edits made while it waited get the unsaved-changes prompt |
| `internal/themes/` | color themes (4 palettes, `themes.toml`) |
| `internal/tui/` | Bubble Tea shell, pickers, launch, start-on-select flow (`start_flow.go`); `modelrows.go` (rows + sort), `modeltable.go` (`buildTable`, `renderTable`); `PickStartModel` — standalone picker without launch-route gating, used by `wt start` and `wt smoke`; `slot_flow.go`: the slot-profile launch behind `phaseSlot`, and what a quit out of it still owes (`settleQuitSlot`, `settleQuitSlotStart`, which reads the start's outcome from `startState.result`) |
| `internal/tuilayout/` | what both TUIs fit a terminal with: `ListFrame`, `FitTo`, `DrawnFrame`, `Clip` (a list-backed screen is never taller or wider than the terminal), `WrapText`/`Flow` (free text wrapped between words, for a status that must be read whole) and `Columns` (a table that drops whole columns, in an order each table names; a list item joins one through `TableItem`; `StyleTableTitle` is the one title-bar reset its `TitleRoom` counts on, called by every table-backed list) |
