# wt Go tests: seams and isolation

Internals reference for `wt/`, reached from [`wt/CLAUDE.md`](../../CLAUDE.md). Backticked paths are relative to `wt/` unless they start with `../`.

## Go tests

Every `Test*` has a top-level `//` comment stating **what** it tests and **why** it matters (the user-facing consequence of a regression).

**Test seams.** TTY, installed-check, guard, TUI behavior, usage store, local-inventory probing, model starting, profiles, and model-server flows are stubbed via package-level var seams (`tuiRun`, `launchCommand`, `stdinTTY`, `installed`, `maybeInstallGuard`, `newUsageStore`, `flushTTY`, `pickModelTUI`, `pickStartModelTUI`, `loadProfileStore`, `confirmProfile`, `openTTY`, `profileApplier`, `stdoutWidth`, `statsNow`) — production code calls the var, tests swap it. The worktree picker's PR lookups are `internal/cleanup`'s (`cleanup.FillPRs`): the `TestMain` of `internal/tui` makes `cleanup.StubPRListForTest` and `StubPRBaseListForTest` fail, and a picker test passes its own `GatherInputs.PRList`. `internal/tui`'s `findRepoRoot` (the picker's `git rev-parse --show-toplevel`) is left real, since the package's git is isolated; `TestPickerOpenResolvesTheRepoRootOnce` swaps it for a counter to pin one lookup per picker open (#390). Per-call hooks are the rule: `cmd/wt-session`'s model-server seams are fields of the `hooks` struct on `app` (`buildGateway`, `buildSlotGateway`, `newClient`, `beatInterval`, `stopIn`, `jobSleep`, `smokeRun`; zero value = real behavior; a `*modelSession` carries the hooks of the app that built it), `internal/tui`'s launch-build seams are `launchHooks` on the bubbletea model, and `internal/smoke`'s agent run is the `smoke.RowOptions` argument of `RunRowGateway`; a test sets the field on the app (or the `testHooks()` value it passes to `rootCmdWith`/`runRootWith`) it runs. The package-level var seams listed above are the migrating exception: convert one onto those hooks when its package is touched, and add a new seam as a per-call hook, never as a `var x = realX`.

**No test writes the developer's real config directory.** `internal/tui` and `cmd/wt-session` launch stub agents, record usage, take profile locks and load the config, so their `TestMain`s point `XDG_CONFIG_HOME` at a throwaway directory for the whole package (and clear `WT_REGISTRY` and `MODELMAN_REGISTRY`) through `config.IsolateConfigHomeForTest`; a test that sets its own still wins. `internal/config` does the same: most of its tests set only `XDG_CONFIG_HOME`, and a `WT_REGISTRY` or `MODELMAN_REGISTRY` inherited from the developer's shell outranks it. Tests name a scratch registry through `WT_REGISTRY`. In a package with no isolating `TestMain`, a test that sets it also sets `MODELMAN_REGISTRY` to `""` (the alias is read after `WT_REGISTRY`, permanently), so neither name can be inherited. `TestRegistryPathPrecedence` (`internal/config/registry_env_test.go`) is the test that proves the alias is still read, after `WT_REGISTRY`; llmbench's `test_registry_path_precedence` proves the same for its reader. Before this, every run of `internal/tui` rewrote the real `rotation.state` with a test model and appended `wt-stub` launches to the real `usage.jsonl`. `internal/modeladmin` does it too (its `TestMain` also arms the registry write guard, pinned by `TestRegistryWriteGuardIsArmedHere`); it stubs no probe, because `Rows` takes the snapshot as an argument. `TestConfigHomeIsNotTheDevelopersOwn` pins it in both packages. A new package whose tests reach `config.Dir()` needs the same setup — check with a before/after listing of `~/.config/agent-wt` around `go test`.

**No test lets the developer's environment decide which git repository it is in.** Two things otherwise do: an exported `GIT_DIR` (tests run from a git hook) names a repository whatever the working directory is, and a `TMPDIR` or `GOTMPDIR` inside a checkout puts every temp directory inside that checkout (`t.TempDir()` is made under `GOTMPDIR` when that is set, `os.MkdirTemp("", ...)` under `TMPDIR`). Under `GIT_DIR`, `git init <dir>`, `git -C <dir> commit` and `git worktree add` in a test's own fixture act on that repository; either way a test that changes into a bare temp directory to be "outside a git repo" is inside one, and in `cmd/wt-session` the root command then takes the picker branch, where the real `maybeInstallGuard` appends the commit hook to that repository and the real `tuiRun` opens `/dev/tty` (a hang in a terminal).

`gitenv.IsolateForTest()` (`internal/gitenv/gitenv.go`) closes both for a whole test binary, and the rule is: **the `TestMain` of every package whose test binary can run git calls it, as a statement of its own** — whether a test runs git itself or reaches production code that does (`internal/worktree`, `internal/guard`, `internal/smoke`'s `NewRowDir`), however far down its imports. It unsets the repository-locating `GIT_*` variables (`repoVars`: the ones `git rev-parse --local-env-vars` lists, and `GIT_NAMESPACE`; unset, not emptied, since an empty `GIT_DIR` is a fatal error to git) and sets `GIT_CEILING_DIRECTORIES` to the temp roots (`TMPDIR` and `GOTMPDIR`, each also as the path its symlinks resolve to), so a directory below one is in a repository only when a test ran `git init` there or in a parent it made. It also sets `GIT_SSH_COMMAND=false` and `GIT_TERMINAL_PROMPT=0` (`networkGuards`, #426): an ssh remote (`git@host:…`, `ssh://`) fails at once without running ssh, so a fixture that names a real one (the picker's `worktree.FetchRemotes` fetches every remote) never reaches the network with the developer's keys, and git never waits on the terminal for a username or password (`TestIsolateForTestSetsTheNetworkGuards`, `TestIsolateForTestStopsGitStartingSSH`). That is all it blocks: an https remote is still fetched and a credential helper in the developer's git config still runs for it, a `git://` remote still connects, and a `url.insteadOf` in that config can still turn an ssh URL into https, so a fixture remote that must not be reached gets a URL that cannot be fetched by any transport (a missing path, a host under `.invalid`). The packages today (20): `cmd/wt-session`, `cmd/wt-model`, `internal/agents`, `internal/cleanup`, `internal/dirtsnap`, `internal/gitenv`, `internal/gittest`, `internal/guard`, `internal/initseed`, `internal/launchwarn`, `internal/modeleditor` (it links the lifecycle), `internal/modelserver`, `internal/removal`, `internal/rescue`, `internal/rootclaim`, `internal/rootmove`, `internal/sessioneditor` (it links `internal/agents`), `internal/smoke`, `internal/tui` and `internal/worktree`. That list is not what enforces the rule: `TestEveryPackageThatRunsGitIsolatesIt` (`internal/gitenv/packages_test.go`) parses the module's source and fails for a package that holds the string literal `"git"` (or a command line starting with it) in any file, or links a package whose non-test files do, and has no such `TestMain`. It cannot see git started under a name that is not written out (a variable, a shell script, a child process that runs git itself); a package that does that calls `gitenv.IsolateForTest()` all the same. `internal/gitenv` imports nothing from this module, which is why any package's tests can import it without a cycle; the list of variables lives there and nowhere else in the tests (`internal/smoke`'s production `gitRepoEnv`, which strips an agent's environment, is a separate, shorter list).

The scrub is process-wide and never restored, so it holds in a parallel test and in one that forgets it exists, and a test needs no helper to build a repository in `t.TempDir()`. A test that sets one of the variables on purpose with `t.Setenv` (`TestNewRowDirIgnoresInheritedGitDir`) has it for its own duration, and `t.Setenv`'s cleanup puts back what it found, which is the variable unset (`TestSetenvOnPurposeSurvivesAndIsUndone`). A test that moves `TMPDIR` or `GOTMPDIR` has moved the temp roots: it calls `t.Setenv("GIT_CEILING_DIRECTORIES", os.Getenv("GIT_CEILING_DIRECTORIES"))` to register the restore and then `gitenv.IsolateForTest()` again (`TestIsolateForTestStopsAtEveryTempRoot`). Git's global and system config (`~/.gitconfig`) is still read: `IsolateForTest` is about which repository git acts on and which transports can leave the machine, so a fixture that commits sets its own identity. The network guards live only in test binaries, so `internal/smoke`'s `gitRepoEnv` (what a smoke row's agent does not inherit) does not list them.

In `cmd/wt-session`, `expectDirectLaunch(t)` (`cmd/wt-session/helpers_test.go`) is what is left per test: `tuiRun` and `maybeInstallGuard` stubs that fail the test. A test that runs the command tree (`rootCmdWith(testHooks())`, through `runRootWith`/`runWTWith`) up to a launch it has stubbed (`launchCommand`, a `hooks.buildGateway`, or a fake model server) calls it first, and one that launches inside a repository it built (where the guard is expected) calls `expectDirectLaunchInRepo(t)` instead, whose `maybeInstallGuard` is a no-op. A test that means to reach the TUI stubs `tuiRun` itself.

Five `TestMain`s guarantee no Go test probes a real server, starts a real model, queries a real database, or drains the developer's terminal input queue:
- `internal/tui`: a session's picker reads every model from a model client, so its `TestMain` stubs no inventory, start or route seam (they were deleted with Task 19); a test hands the picker a fake client (`fakeModels`, `models_client_test.go`; `flowEnter`, `catalogFor` and `withServer` in `testhelpers_test.go`). The standalone picker (`PickStartModel`) takes its rows as an argument. The `TestMain` isolates the config home, git, the tiers file and the worktree picker's PR lookups.
- `cmd/wt-session` (`testmain_test.go`): `hooks.client` builds, whenever no `newClient` hook is set and the binary is a test (`testing.Testing()`), a client that refuses any model server but a loopback one (tests run a fake server, `httptest`), so the guard covers every test app, a bare `&app{}` and `newApp()` included (`testHooks()` is the same guard, named for tests that set more fields; `TestModelClientSeamRefusesNonLoopback` pins the zero value); the host stop moved to `cmd/wt-model` with its seams. `cmd/wt-model`'s registry, route and stop commands (`wt-model model init|add|edit|rm|list`, `wt-model cloud-sync`, `wt-model litellm sync`, `wt-model stop`) carry their seams as fields of `host` (`seams.go`): `testHost()` sets `probeInventory` (the inventory `wt-model litellm sync`, `wt-model model list` and the Models tab read) to `localmodels.OnDiskSnapshotForTest` (`stubProbeInventory` swaps in a fixed snapshot), makes `seedEnv` describe a machine with nothing installed, fails `ollamaCaps`, `openTTY`, `confirmRemove` and cloud-sync's `cloudFetch`, `ollamaCLI` and `confirmCloudSync`, and makes `syncRoutesAfterWrite` return a "not stubbed" warning (a command that writes the registry would otherwise go on to the real route sync), and `wt-model stop`'s `stopState` read nothing, its `stopEntries`, `stopProvider` and `stopLoading` fail and its `confirmStop` decline, so no test stops a real model; tests stub them on their own host (`stubSeedEnv`, `stubRouteSync`, `realRouteSync`, `stubOllamaCaps` in `cmd/wt-model/helpers_test.go`, `stubConfirmRemove` in `fixtures_test.go`). A session path reaches none of these: `TestSessionPathsNeverTouchTheRegistryOrLifecycle` (`boundary_test.go`) scans every non-test file of `cmd/wt-session` (no host command is left in it since phase 4 stage 2) and of the session packages (`tui` without its `models_tab*` files, `agents`, `smoke`, `profiles`, `modelclient`, `modelmode`, `modelping`, `urlrule`, `editorkit`, `modeview`, `sessioneditor`, `cli`) for the host calls, and allows exactly four reads of the host config: `app.go`'s `loadHost` (`config.Load`, the one loader behind `hostConfig`), `cleanup.go`'s `noRegistry` and `protectedPaths` (`.hostConfig`, R10's best-effort protected-path read) and `stats.go`'s `spendFromServer` (`.hostConfig`, stats' family fallback when no server answers).
- `internal/survey`: `flushTTY` is a no-op. `internal/hoststop`: `lifecycle.IsolateProcessesForTest()` closes the process servers' pidfiles and the process seams (below).
- `internal/litellm` (`testmain_test.go`): `runShell` fails with "runShell not stubbed in this test", and `proxyProc` — the default restart's pid lookup, SIGTERM, SIGKILL and liveness check, one struct of four functions — finds no pid, refuses to signal and reports nothing alive. So an unstubbed restart looks up and signals nothing and its command is refused. Tests of the default restart call `stubDefaultRestart(t, &fakeProxy{…}, timing, fail)` (`restart_graceful_test.go`), which installs a fake process, a recording shell and a `drainTiming` in milliseconds, and clears both override variables. Beyond that package the real functions guard themselves: inside any test binary (`testing.Testing()`) `realProxyProcess` reports no pid and signals nothing, and `realRunShell` runs no command that starts with `launchctl`. A test in another package that reaches `litellm.RestartContext` with no override command and no stubbed seam therefore gets a "failed to restart" warning, and the developer's proxy is neither signalled nor kickstarted. No test may look up, signal or restart a real process. The readiness half of the default restart a changed write makes (`bounce`: the probe before the restart and the wait after it, #382) is stubbed too: its `Listening` reports nothing listening, so no write waits, and its `WaitReady` fails; tests of the wait swap `bounce` with `stubBounce` (`restart_wait_test.go`). `cmd/wt-model`'s `TestMain` does the same through `litellm.StubProxyReadinessForTest`, since a `wt-model litellm sync` there runs with the test's `WT_LITELLM_RESTART_CMD` and would otherwise probe whatever answers at the test config's `[litellm]` url; a test of the wait installs its own (`TestLitellmSyncWaitsForTheProxy`, `cmd/wt-model/litellm_sync_test.go`). `cmd/wt-session`'s `TestMain` keeps the same stub, though the session binary runs no route sync.
- `internal/spend`: `lookPath` and `runPsql` both fail, so no test finds or runs the real `psql`. Tests use `stubPsql` (canned output and exit status; it records the arguments and the whole environment `psql` would get, and `libpqVars` picks the `PG*` entries out) or `fakePsqlBinary` (a shell script run as a real child process, for the exec plumbing and the deadline). The connection string must never be among the arguments (#282): a test that adds a `psql` option asserts the full argument list. `wt stats` reads spend from the model server since Task 18 and has no database code of its own; its table tests supply spend rows through `stubSpend(t, report, err)` (`stats_usage_test.go`: a fake model server answering `GET spend` with a `modelapi.SpendReport` or the error code), read by the production collector (`collectUsageRemote`). `litellm.DatabaseURL` adds a guard of its own: under the throwaway config home the registry is redirected, so it will not read the default `config.yaml` or the proxy's LaunchAgent plist. `internal/litellm`'s own `DatabaseURL` tests replace `loadProxyEnv` (`stubProxyEnv`) or name a temp plist (`writePlist`); none reads the real one.

**A slot-profile launch is closed the same way.** It runs against the model server: `cmd/wt-session`'s tests drive `launchSlotProfileRemote` against a fake server (`slot_launch_remote_test.go`, with `hooks.buildSlotGateway` wrapped to see the build) and `internal/tui`'s drive `beginRemoteSlotLaunch` with `fakeModels`; `TestSlotFlowParity` (both packages, `internal/profiles/testdata/slot_launch_remote_parity.txt`) holds them to the same server calls. `internal/lifecycle`'s `TestMain` does **not** stub `restartProxy` or `waitProxy`: a test of `EnsureModelRoutes`, `RestartProxy` or `ProbeProxy` (host-side, no session calls them) installs `stubRoutes` or `realRoutes` first. The slot-profile fixtures are `slotPicker` (`internal/tui/slot_row_test.go`), `slotRow` and `slotWireRows` (`cmd/wt-session/slot_launch_test.go`); `docs/contracts/slot-profiles.sample.toml` pins the file format.

`internal/smoke`'s `smokeProbe` is the same idea for `Eligibility`, with the exported `SetSmokeProbeForTest` for other packages. `internal/modeladmin`'s `statLocalPath` answers whether a row's `fetch.local_path` is there (an `os.Stat`); a test of `Rows` or `WeightsNote` that has such a row swaps it, so the answer does not depend on the machine. `internal/lifecycle` uses a different convention: every seam (HTTP clients, exec, inventory, timeouts, pidfile paths) lives in one `env` struct that `defaultEnv()` fills and tests rebuild with `testEnv()`; its `TestMain` doubles as a fake `mtplx` helper process when `LIFECYCLE_HELPER=mtplx`.

**No test reads a real process server's pidfile (mtplx's, rec's, sushi's) or signals a process it did not start.** The stop of a loading mtplx (`internal/lifecycle/server_loading.go`) reaches the machine through three things: the pidfile path (`env.serverProc["mtplx"]`, from `serverProcess(spec)`, which `WT_MTPLX_PIDFILE` redirects together with the log and the start record), the process-table read (`env.describe`, from the package var `describeProc` = `realDescribeProc`) and the signal (`env.signal`, from `signalProc` = `realSignalProc`). `lifecycle.IsolateProcessesForTest()` closes four seams (the process-table read, the signal, the readiness command `readyStdout` and the wired-limit read `readWiredLimit`) with a "not stubbed" error and, for every process family (mtplx, rec and sushi), points the pidfile variable its spec names (`WT_MTPLX_PIDFILE`, `WT_REC_PIDFILE`, `WT_SUSHI_PIDFILE`) at a directory that does not exist, for the rest of the process; the `TestMain`s of `internal/lifecycle`, `internal/hoststop`, `cmd/wt-model` and `cmd/wt-session` call it, so `defaultEnv()` is closed in all four (`TestProcessSeamsFailClosedHere`, `TestProcessSeamsAreClosedInThisPackage` in `internal/hoststop`, `TestStopLoadingSeamFailsClosed` in `cmd/wt-model`). The last two prove the engine's seams are closed and not merely unused: each checks that `WT_MTPLX_PIDFILE` is a scratch path, writes its parent's pid into that pidfile and expects `lifecycle.LoadingServer` to return the "not stubbed" error — with the isolation removed from `TestMain` they fail, where a check for "no pidfile found" would pass. `cmd/wt-model`'s `testHost()` also fails its `stopLoading` seam (`lifecycle.StopLoading` in `newHost`); tests use `stubStopLoading` (`cmd/wt-model/stop_loading_test.go`), and name what the pidfile said through `hoststop.FamilyState.Loading` in a stubbed stop state. `internal/hoststop`'s tests pass `stopDeps.loading` through `stopHarness`, and `stopDeps.begin` as a `harnessBatch` whose notices reach the loop through `lifecycle.DeliverStopNoticeForTest`. In `internal/lifecycle`, a test builds an env over a fake process table with `procTable.env(t)` (pidfile under `t.TempDir()`, every signal recorded, none sent; `onSignal` and `onDescribe` change the table as the stop proceeds, `signalErr` is what the signal returns). The exported `LoadingServer` and `StopLoading` build their env from `defaultEnv()`, so a test of them swaps the package vars themselves and names a pidfile with `t.Setenv`: `stubProcessSeams(t)`. The real seams are run only in `loading_darwin_test.go`, against children the test starts itself (`startChild`: `/bin/sleep`, or a `#!/bin/sh` script named `mtplx` under `t.TempDir()`, each in its own session), through `childEnv`, whose signal seam fails the test for any target but that child or the group it leads. `internal/modelsetup` (the model server's setup) reaches the machine only through `Env`'s seams: `config.IsolateConfigHomeForTest` in its `TestMain`, a recording `fakeEnv` in its tests, and the real launchctl, lsof and ps seams refuse with a "test binary" error (`TestDefaultEnvRefusesLaunchdAndListenerLookupsUnderTest`). A new package whose tests can reach `lifecycle.LoadingServer`, `lifecycle.StopLoading` or `hoststop.ReadStopState` calls `lifecycle.IsolateProcessesForTest()` from its `TestMain`.

**`wt stats` has one clock.** `statsNow` is read once per run and every window in the report is measured back from that value: `buildStatsRows` takes it (and leaves out a survey answer dated after it, itself; `survey`'s `inWindow`, shared with the picker, has no upper bound), `collectUsage` hands it to both the spend request (`collectUsageRemote`, the model server's `GET spend`) and `(*usage.StoreImpl).AllCounts(agent, asOf)`, and `--json` prints it as `as_of`. `AllCounts` never reads `internal/usage`'s own unexported `now` (that clock stamps `RecordFor` and feeds the picker's `Counts`/`CountsForAgent`), so `pinStatsNow(t, at)` pins the whole report from `cmd/wt-session`. Pin first, then seed: `seedLaunches` measures its ages back from `statsNow()`, and `seedLaunchesAt` takes absolute timestamps for a test about the window's edges (`TestStatsLaunchesAndSpendShareOneInstant`). The window is `(asOf - window, asOf]` in all three halves — launches (`AllCounts`), spend (`spend.Query`'s SQL) and survey rows (`inWindow` plus `buildStatsRows`' upper bound) — and a spend stub that filters by time must use `spend.InWindow(t, start, end)`, never comparisons of its own: `internal/spend`'s `TestQuerySQLWindowIsInWindow` reads the operators back out of the built SQL and holds them to that function, which is what keeps a stub from applying a rule the database does not. `AllCounts` is not on the `usage.Store` interface — `wt stats` holds the concrete store — so a `usage.Store` double does not implement it.

**`wt stats` decides its rows once, and renders twice.** `buildStatsRows` (survey) and `buildUsageRows` (usage) decide which rows exist; `surveyTableRows`, `renderUsageTable` and `buildStatsJSON` render every row they are handed. A rule about which rows exist belongs in a builder, never in a renderer — `TestStatsNoDataRuleHasOneHome` pins that for the survey's "no data" rule, and `TestStatsJSONAgreesWithTheTable` runs the command both ways and compares both halves, row for row and cell for cell (it reads the bordered survey table back with ANSI sequences stripped, the one place that is worth the coupling).

**Registry writes.** `internal/modeladmin` and `internal/modeleditor` (whose Models tab, `wt-model model`, writes the registry) write it in their tests, so each has an isolating `TestMain` (modeleditor's also names the home directory the tab abbreviates paths against, `testUserHome`, which its tests set on the model); modeladmin's also fails the package's `runOllamaShow` seam: no test runs the developer's `ollama`. The Models tab's form reaches that lookup only through `ModelsDeps.Capabilities`, which the tab's test machine (`tabMachine.deps`) fails unless a test stubs it; a form test delivers keys with `sendKey`, which does not run the cursor-blink commands a text input returns (each sleeps half a second). `cmd/wt-model`'s `testHost()` fails `ollamaCaps` and `confirmRemove` for the same reason; tests use `stubOllamaCaps` and `stubConfirmRemove` (`cmd/wt-model/helpers_test.go`, `fixtures_test.go`). For `wt-model cloud-sync` it makes `cloudFetch` and `confirmCloudSync` fail with "not stubbed", so an unstubbed test fetches no public page and opens no terminal (`TestCloudSyncSeamsFailClosed`), and `ollamaCLI` fail the same way, so none runs the developer's ollama — a pull or an rm there changes their machine (`TestOllamaSeamFailsClosed`; `stubOllama`, in `cmd/wt-model/cloudsync_ollama_test.go`, records each command with the origin it was pinned to, and `TestRealOllamaCLIPinsTheDaemon` runs the real exec path against a script in a temp `PATH`); tests use `stubCloudFetch` (pages by URL, anything else a 404), `stubConfirm` (the answer, and a hook that plays another program writing the registry while the user reads the plan), `noTerminal` (the real `promptCloudSync` with `openTTY` failing, as under an agent's shell) and `cloudSyncHome` (a home with the test's registry, and the clock pinned through `cloudSyncNow`), all in `cmd/wt-model/cloudsync_test.go`. modeladmin's `statLocalPath` seam (is a row's `fetch.local_path` there?) is left real, since a stat changes nothing; a test whose answer depends on it swaps it for a function that describes the disk it wants. A test of what a y/N prompt does with no terminal stubs `openTTY` to fail: `wt-model stop`'s `confirmStop` and `wt-model model rm`'s `confirmRemove` are both `realConfirmRemove`, which opens `/dev/tty` only through the host's `openTTY`, so the refusal is tested where the test run has a terminal too. `internal/config` has two seams of its own: `registryWriteGuard` (set by `IsolateConfigHomeForTest`; `UpdateRegistry` asks it before taking the lock, so a guarded write creates nothing) and `registryBeforeRename` (a test swaps it to play another program writing the file between wt's read and its rename). A new package whose tests reach `config.UpdateRegistry` must call `config.IsolateConfigHomeForTest` from its `TestMain`, and assert `config.RegistryWriteGuardArmed()` in one test: the guard is off unless a `TestMain` arms it, so a binary that forgot fails open. `internal/cloudsync` has its own `TestMain`: its `Apply` tests go through `config.UpdateRegistry`, so it calls `config.IsolateConfigHomeForTest` and asserts the write guard is armed. `internal/litellm`'s `TestMain` does the same beside its restart and proxy stubs: the alias half re-reads the registry (`Options.loadRegistry`'s default, `config.Load`), so no test may reach the real one.

**Prefer asserting on unexported functions directly** — same-package tests can call them (e.g. `buildStatsRows`); parsing rendered lipgloss output couples tests to border glyphs/padding and flakes under forced-color ANSI.

```bash
go test ./...                        # all Go tests
go test ./internal/worktree -v       # verbose, one package
go test ./internal/agents -run TestOpenCodeOllamaPrefix -v   # one test
go vet ./...                         # static analysis
make check                           # shellcheck + shfmt check + go-format-check (gofmt -l gate wt-ci runs); `make format` writes both
```

From the monorepo root, `make test-all` runs the CI-equivalent sweep (root lint + llmbench + wt build/vet/test).


## The import-graph ratchet

`internal/depcheck/depcheck_test.go` shells out to `go list -deps -f '{{.ImportPath}}'` (non-test dependencies, exact import paths) for each session library package and `cmd/wt-model`, and skips with a message when `go` is not on PATH. It needs no network and touches no config home. It fails when a session library package links the admin set outside its allow-list entry, and also when an allow-listed edge is no longer linked ("remove it from the allow-list"), so the boundary only tightens. `TestEveryInternalPackageIsClassified` keeps its lists complete (every `internal/` package is a session library, banned or in `otherPackages`, and a renamed or deleted package fails), `closure` fails when `go list` does not return the target itself, and `TestRatchetReportsBothFailureBranches` feeds the pure `ratchetProblems` a synthetic closure. `TestAdminScreensStayOffTheSessionScreens` is the third rule: the closures of the editors and their shared leaf (`internal/sessioneditor`, `internal/modeleditor`, `internal/editorkit`) must not contain `internal/tui` (no allow-list; share styling through `themes`/`tuilayout`). The rules are in [packages.md](packages.md#package-graph-rules); `cmd/wt-session/boundary_test.go` is the complementary AST scan of host calls.

## Detail moved from wt/CLAUDE.md

The full text of rules that [CLAUDE.md](../../CLAUDE.md) now keeps as one-line summaries.

- **Tests stay off the developer's machine.** The `TestMain` of each package that builds a model table or a claude launch (`cmd/wt-session`, `internal/tui`, `internal/agents`) calls `tiers.IsolateForTest` (`MODELTIERS_OUT` at a file that does not exist), so no test reads the real `tiers.toml`. The `TestMain` of each package that reaches `config.Dir()` calls `config.IsolateConfigHomeForTest` (throwaway `XDG_CONFIG_HOME`; `WT_REGISTRY` and `MODELMAN_REGISTRY` cleared); `cmd/wt-session` also stubs the host inventory probe, and no test runs `psql`; a session path runs against a fake model server. Tests name a scratch registry through `WT_REGISTRY`, and where no `TestMain` isolates also set `MODELMAN_REGISTRY` to `""`. A new package that reaches `config.Dir()` needs the same.

- **Git finds only repositories a test made**: the `TestMain` of every package whose tests can run git (itself, or via `internal/worktree`, `guard` or `smoke`) calls `gitenv.IsolateForTest()` (`TestEveryPackageThatRunsGitIsolatesIt`). It also blocks ssh (`GIT_SSH_COMMAND=false`) and git's terminal prompts (`GIT_TERMINAL_PROMPT=0`), not https or `git://`, so a fixture remote that must not be reached gets a URL no transport can fetch.

- **Losses read sites are pinned**: `TestEveryLossesReadSiteIsLabelled` (`internal/cleanup/losses_guard_test.go`, with `TestLossesGuardBites`) is a name-keyed `go/ast` scan (no `go/types`) of every non-test file in `cmd/wt-session` and `internal/`. It lists each function that touches a row's `.Losses` with exact counts: a deliberate raw read carries the marker `// losses: raw, <why>`, a removal-side read must use `Row.EffectiveLosses` (or the sealed `SawLosses`), and a new read site fails until its author labels it. Why: a rescued original's raw losses still count the commits its record keeps, so a consumer on the wrong view would refuse a removable original or offer and force what it must not.
- **The root is reset in one place**: `TestRootMutationFunctionsAreExactlyTheAllowList` (`internal/removal/rootguard_test.go`, with `TestRootMutationScanSeesEachShape`) is a `go/ast` scan of `internal/removal`'s non-test files: the functions holding the argv words `"reset"`, `"--hard"`, `"switch"`, `"checkout"`, `"restore"` or `"stash"`, or a file-deleting call (`os.Remove*`, `os.Rename`, `syscall`/`unix` unlink), are exactly `rootMutationAllowed` (`ReleaseRoot` and its `removeCarried`), and a stale entry fails too. `TestHardResetExistsNowhereOutsideRemoval` (with `TestHardResetScanSeesEachShape`) reads every non-test file of the module outside `internal/removal` and fails on a `"--hard"`, `"reset"`, `"clean"`, `"checkout"`, `"restore"` or `"stash"` argv word or a `git reset`/`git clean` command-line literal; its file-name exemption list (`hardResetExempt`) is empty. The guards cover only the listed argv words. `internal/rootmove` and `cmd/wt-session/restore_root*.go` are inside the deletion scan too: `TestRootmoveContainsNoDeletion` bans `rootmoveBanned` (the rescue list plus `"--hard"`, `"reset"`, `"clean"` and any `"update-ref"`), `TestRiskyRootmoveSourceBites` shows the scan finds each shape, and `TestRootmoveIsInsideTheDeletionScanAndNeverAllowed` pins that no allow-list entry exempts them. Why: `ReleaseRoot`'s reset destroys the root's uncommitted work and is safe only behind its three proofs (verified copy, record, unchanged fingerprint), which `TestReleaseRootRefusesWithoutAnyOfTheThreeProofs` checks one by one; a reset, switch or removal anywhere else would have none.
- **`wt restore-root` is held by real repositories**: `internal/rootmove` tests (its `TestMain` isolates git and the global git config, as `TestEveryPackageThatRunsGitIsolatesIt` requires) drive `Preflight` and `Execute` in scratch repositories with a bare `origin`, with the step functions (`executeInto`, `beforeRelease`, `releaseRoot`, `stepGit`, `afterRelease`) as seams for failure injection at each row of the recovery table; `TestCodesCoverEveryCodeRootmoveEmits` holds `Codes` to the sources, and `cmd/wt-session/restore_root_contract_test.go` holds the envelope to `docs/contracts/restore-root-result.*`. Why: the command's safety is the order of its steps and the state each failure leaves, which only a real checkout shows.
- **The rescued original, end to end**: `cmd/wt-session/rescue_removable_test.go` drives the real `wt rescue`, `wt cleanup` and `wt remove` together in scratch repositories: `TestRescuedOriginalReadsRemovableAndGoesWithItsBranch` (the clean original lists proven with evidence `rescued` and removes with `--yes` and its branch, the copy and the record stay), `TestRescuedOriginalStopsReadingRemovableAndRefuses` (a new commit, a deleted record, an edit after a clean rescue, an ignored file and gh unavailable each leave it reading as today), `TestRescueTwiceThenRemove` and `TestCleanupReadsWhatRescueWrites`. Unit coverage is in `internal/cleanup/preserved*_test.go` and `internal/removal/preserved_test.go`.
- **The cleanup list's test seams and fixtures** (`internal/tui`). `RemoveFuncs.Program` is the per-call seam under `RunCleanupList` (nil: the real alt-screen program): a test sets it on the funcs it hands in to return a final model, with `rescueRow` or `restoreRoot` set, and the stop function, so the after-the-screen steps and the re-entry loop run without a terminal (`TestRunCleanupListStopsForwardingThenRescues`). The removal flow's screens live in `confirmScreens` (`cleanup_confirm_test.go`: confirm proven, typed, held, selected, progress, results); `removalScreen(name)` resizes one for the layout table. **A new confirm screen joins both tables**: `confirmScreens` feeds `TestConfirmFitsTheTerminal80x24` (80x24, 40x12, 40x8, 30x12) and `TestEveryListPhaseFitsTheTerminal` (`layout_test.go`, through `removalScreen`), so a screen added to only one is measured only there. `holderClaim(t, repo, path, branch, agent)` makes a held worktree: a real `sleep` child process plus a claim under the repository's `wt-sessions` with the child's real pid and start time (an unverifiable claim raises no held label), reaped with `Kill` and `Wait` in `t.Cleanup`; use it, not a hand-written claim, for any `held by session` pin. **The confirm's typed buffer is shared**: the model's `conf` is a `*cleanupConfirm`, so copies of a `cleanupListModel` share it, and a screen reached by typing and then reused by a later step keeps those characters; type each step (`typeWord`) on a freshly opened confirm screen. `TestCleanupLockedOnlyForHardStops` pins which rows lock (primary, current, locked, operation, nested, missing directory) and which never do (default branch, held, root drift, no default branch).
- **A real-screen check is part of a TUI change.** A unit test of a view passed while an 80-column screen cut a line short (and again in Part 5, where a held tag was cut mid-word at 80x24 and `flowUnits` now wraps an oversized tag at its spaces, `TestFlowUnitsWrapsOversizedUnitsAtSpaces`). Capture the real screen at 80x24 from a Python `pty.fork()` driver: set the size with `TIOCSWINSZ` before exec, answer the OSC 10/11/12 colour queries and the cursor-position query (without the answers the program draws nothing), rebuild the screen from the bytes, send ctrl+c to quit, and run it against a scratch repository with a throwaway `XDG_CONFIG_HOME`. No driver is checked in. Children the driver starts (held-claim `sleep`s) are killed and waited.
- **Run `go test ./...` for any production-code change, not only the package you edited.** Some guards scan production code across packages: `TestEveryLossesReadSiteIsLabelled` (`internal/cleanup/losses_guard_test.go`) reads every non-test file in `cmd/wt-session` and `internal/`, `internal/tui` included (`cleanupLocked` carries a `// losses: raw` label), so a new read of `.Losses` in the TUI fails in `internal/cleanup`, and `TestDeletionStringsOnlyInRemovalPackage` scans the whole module for deletion code.

## Verification commands

Run the Go test block in [CLAUDE.md](../../CLAUDE.md#go-tests) before any commit, then exercise the installed binary (build the branch first: `D=$(mktemp -d)`, `go build -o "$D/wt" ./cmd/wt-session` and `go build -o "$D/wt-model" ./cmd/wt-model`; with `~/.local/bin/wt` and `~/.local/bin/wt-model` possibly predating it). Also: `--version` prints the version and exits; `--debug-worktrees` lists worktrees and branches (test helper); `--check-guard` / `--no-guard` check / remove the `block-main-commit` guard.

```bash
wt                                   # interactive TUI (needs TTY)
wt -W my-feature -A claude           # named worktree + launch (a new name is created and said so)
wt --cwd -A codex                    # current directory
claude-wt --cwd                      # shim forwards to wt
wt --init                            # seed agent instruction files
wt start [<id>] / wt stop [<id>]    # one local model through the model server (routes follow automatically)
wt-model stop <provider>|--all      # host provider stop on the server's machine; asks about client sessions
wt-model served <provider> [--json]  # ids an omlx/mtplx/mlx_lm_server/rec/sushi server is serving now
wt-model warm omlx <model>           # load a model into a running omlx (keyed warmup; llmbench's omlx backend calls it)
wt-model litellm list / sync / status      # routed ids, reconcile cloud + running local routes, routing state
wt-model model init [--json]               # create registry.toml if missing; add default provider rows (safe to re-run)
wt-model model                       # the Models tab (needs TTY): n add, enter edit/register, d remove
wt-model model list [--json]               # every registry model and every local model found, with live status
wt-model model add <provider> <name> --family F   # register a model (one route sync)
wt-model model add mlx_lm_server <target> --draft <draft> --family F   # a target+draft pairing; wt cannot start one
wt-model model edit <id> --tags code       # change family, tags, location or prices; nothing else in the row moves
wt-model model rm <id> [--yes]             # registry only; prints where the weights are
wt-model cloud-sync --dry-run        # plan a price and ollama-catalog refresh; changes nothing (fetches public pages, runs `ollama list`)
wt profile show -A <agent> -M <id>   # dry-run profile resolution
wt profile list                      # automatic profiles, then slot profiles with each one's static verdict
wt profile show -A claude -M profile/<name>   # a slot profile: the picker's verdict, the slots, the --settings payload (key masked)
wt stats [--window 7d] [--family F] [--json]  # survey table, then launches and LiteLLM spend per model
wt smoke <model-id> [--only claude,codex] [--prompt P] [--timeout 5m] [--json]
wt cleanup --plain --no-fetch        # which worktrees and branches can go, with the proof (reads only)
wt remove <path-or-branch> --dry-run --json   # what a removal would do; changes nothing (run real removals only in a scratch repo)
wt rescue <path-or-branch> --dry-run --json   # what a rescue would copy; changes nothing (run real rescues only in a scratch repo)
make test-agents                     # live agent × model matrix, gateway mode only (needs WT_MODEL_URL and WT_MODEL_TOKEN_FILE; changes no wt config)
```
